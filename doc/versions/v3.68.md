## 1. Problem / Opportunity
*   **Context:** Alur scan QR penjualan saat ini (`QRScannerSheet.handleRawScan → resolve() → api.getProductSizeById(id)`, `Screens/QR/QRScannerSheet.swift:558-584`) melakukan 1× `GET /product-sizes/{id}` (→ query Supabase) per scan. Selama `.resolving`, `isActive=false` (`QRScannerSheet.swift:76-78`) sehingga kamera berhenti. Di pasar (20 item), throughput = 20× RTT serial (~400-800ms/scan). Mode `addToExistingSale` (`TambahPenjualanSheet.swift:312-313`) berpola sama.
*   **Objective:** Scan terasa instan (<50ms) dengan lookup lokal, kamera tetap aktif di cart mode, kebenaran stok/harga final tetap dijamin backend saat `POST /sales-orders`. Zero backend changes. Kompatibel mundur dengan label `oura:UUID` yang sudah tercetak.

## 2. User Flow & UX Specifications
*   **Entry Point:** Tidak berubah — Beranda "Scan & Jual", Penjualan toolbar QR (`mode: .sellOnly`), `TambahPenjualanSheet` tombol QR (`mode: .addToExistingSale`), Produk toolbar (`mode: .stockInOnly` / `.any`).
*   **Flow baru (sellOnly + addToExistingSale):**
    1. Sheet dibuka → langsung `preload` katalog (`GET /product-sizes?page=1&limit=500`, reuse `api.getAllProductSizes()`, ~240 varian) jika cache kosong/expired. Tampilkan chip tipis "Memuat katalog…" tanpa blokir kamera.
    2. Scan `oura:UUID` → lookup dictionary lokal sinkron → **langsung** `addToCart` + `ScanFeedback.success()` + toast, kamera tetap jalan. Tidak ada state `.resolving` yang menghentikan kamera di cart mode.
    3. Cache-miss (UUID tidak ada di cache) → fallback `GET /product-sizes/{id}` sekali, lalu insert ke cache. Jika 404 → error card seperti sekarang.
    4. Background revalidation (debounced, paralel): untuk id di keranjang, refresh `getProductSizeById` max 1× per id per 60 detik. Jika harga/stok berubah → update row + banner kuning "Harga/stok diperbarui dari server".
    5. Checkout: `POST /sales-orders` tetap validator final. Jika backend tolak karena stok kurang → toast merah + auto-clamp qty ke stok server + jangan dismiss sheet.
*   **Flow mode `.any` / `.stockInOnly` (single-resolve):** Tetap tampilkan `resolvedCard` seperti sekarang, tapi resolve dari cache dulu (instan), lalu silent refresh untuk stok terkini.
*   **QR parser (kombinasi, backward-compatible):**
    *   `oura:<uuid>` (label lama) → lookup cache.
    *   `oura2:<uuid>:<priceCents>` (label baru, opsional) → lookup cache + jika `sellingPrice` cache nil, pakai harga embedded sebagai prefill sementara (tetap revalidasi). Parser harus tolak QR non-oura (abaikan, kamera jalan terus).
*   **UI Components:** Reuse `resolvingCard`, `errorCard`, `cartBar`, `QRCartCheckoutSheet`, `ScanFeedback`. Tambah 1 chip status cache kecil di `cartModeOverlay` ("Katalog 5 mnt lalu • tap untuk refresh").
*   **Validation Rules (`canSave`):**
    *   Scan-to-cart: `qty_baru <= cachedStockQty`; jika melebihi → error toast, tidak tambah (sama seperti sekarang tapi lawan cache, bukan hasil fetch).
    *   Checkout (`canCheckout` existing): tambah guard `!isRefreshingPrices` (tunggu revalidasi selesai max 2 detik, lalu lanjut dengan data terbaik).
*   **State & Progressive Disclosure:** Kamera tidak diblokir preload. `scanState` di cart mode hanya `scanning | error` (hapus jeda `.resolving` yang stop kamera); `.resolving` hanya dipakai untuk cache-miss single. Tambah `@State cacheAgeText` untuk chip.

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada endpoint baru/diubah.
    *   Reuse `GET /product-sizes?page=1&limit=500` (`APIService.getAllProductSizes()`) untuk preload — 1 call per buka scanner (atau 0 jika cache fresh TTL 5 menit).
    *   Reuse `GET /product-sizes/{id}` hanya untuk cache-miss + background revalidation (paralel via `withTaskGroup`, bukan serial).
    *   `POST /sales-orders` tetap satu-satunya penulis stok; konflik stok ditangani sebagai error yang sudah ada (`409` → pesan server).
*   **Validation & Errors:** Tidak ada error baru. Oversell dari cache basi akan muncul sebagai error `POST /sales-orders` yang sudah ada — UI wajib menampilkannya tanpa crash (lihat §5).

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak berubah. Jangan ubah `ProductSizeDetail` atau `APIService`.
*   **Views & Controllers:**
    *   **BARU `Screens/QR/QRProductCache.swift`** — sumber kebenaran lokal, misal:
        ```swift
        @MainActor final class QRProductCache: ObservableObject {
            static let shared = QRProductCache()
            @Published private(set) var byId: [UUID: ProductSizeDetail] = [:]
            @Published private(set) var lastSyncAt: Date? = nil
            var ttl: TimeInterval = 300
            var isFresh: Bool { lastSyncAt.map { Date().timeIntervalSince($0) < ttl } ?? false }
            func preload(api: APIService) async  // getAllProductSizes(), isi byId
            func lookup(_ id: UUID) -> ProductSizeDetail?
            func upsert(_ d: ProductSizeDetail)
            func parseQR(_ raw: String) -> (id: UUID, embeddedPrice: Double?)? // oura: + oura2:
        }
        ```
        Catatan: pakai `shared` agar `TambahPenjualanSheet`, `QRGeneratorView`, `ProdukListView` reuse cache yang sama. Jangan duplikasi dictionary per-sheet.
    *   **EDIT `Screens/QR/QRScannerSheet.swift`:**
        *   Tambah `@StateObject cache = QRProductCache.shared`, `.task { await cache.preload(api:) }` saat sheet muncul + tap chip untuk force-refresh.
        *   `isScanning`: di mode `.sellOnly` / `.addToExistingSale`, kembalikan `true` juga saat cache-hit resolve (jangan stop kamera). Opsi minimal: `isScanning = (scanState == .scanning || scanState == .resolving && isCacheHit) && !showCheckoutSheet`, atau sederhanakan: jangan set `.resolving` sama sekali untuk cache-hit — langsung `addToCart` sinkron.
        *   `handleRawScan`: parse via `cache.parseQR`, lookup sinkron dulu; hanya `Task { await resolveMiss(id) }` jika miss.
        *   `resolve(_:)` existing dipertahankan untuk miss + single mode; tambah `revalidateCartIds()` dengan `withTaskGroup` + debounce 500ms.
        *   `QRCartCheckoutSheet`: tampilkan badge "stok terverifikasi × detik lalu" + jalankan `revalidate` sebelum `checkout()` (timeout 2 detik, best-effort).
    *   **TIDAK menyentuh:** `ScanToSellSheet`, `ScanToStockSheet`, `MockAPIService` (mock tetap jalan; cache melapisinya), backend.
*   **TTL & invalidasi:** Default 5 menit. Invalidasi proaktif: setelah `checkout()` sukses / `adjustStock` sukses / `confirmBatch` sukses → `cache.lastSyncAt = nil` agar preload berikutnya fresh.

## 6. Verification & Test Plan
*   **Smoke Test:** Build lolos; buka Scan & Jual (airplane-mode dengan cache terisi → scan label lama tetap masuk keranjang instan); buka-tutup scanner 3× hanya 1 network preload (cek log); mode `.any` tetap tampilkan resolvedCard.
*   **Sanity Test Scenarios:**
    1. Scan 5 label berbeda berurutan cepat (<2 detik) → 5 toast sukses, `cartItemCount=5`, kamera tidak freeze (rekam waktu `handleRawScan→toast` <100ms per item saat cache hit).
    2. Scan label sama 2× saat stok cache=1 → toast kedua "Stok penuh", qty tetap 1.
    3. Cache-miss: hapus 1 id dari cache (atau scan UUID asing valid) → fallback fetch jalan, 404 tampilkan "Produk tidak ditemukan".
    4. Harga berubah di server setelah preload → background revalidation update row + banner muncul.
    5. Checkout saat stok server sudah 0 (simulasi jual dari device lain) → error backend tampil, sheet tidak dismiss, qty auto-clamp.
    6. Format `oura2:<uuid>:<price>` → prefill harga embedded saat cache tidak punya harga, tetap revalidasi.
*   **Non-goal (masuk v3.69):** Endpoint slim/batch, persistensi SQLite permanen, antrian offline POST, QR payload penuh (nama/gambar).
