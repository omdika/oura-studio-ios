# v3.38 — Perbaikan Error Decoding Analisis Waste Kain

**Status:** IMPLEMENTED
**Date:** 2026-08-26
**Changed by:** Frontend
**Backend changes required:** None.

---

## Latar Belakang

Saat pengguna membuka halaman **Analisis Waste Kain** (tab Lainnya -> Laporan -> Waste Kain) ketika tersambung ke live API backend, halaman tersebut menampilkan pesan kesalahan (*error card*) bertuliskan:
`Gagal memuat laporan. Decode error: keyNotFound 'total_waste_area_cm2' at [Index 0]`

---

## Analisis Masalah & Penyebab (Root Cause)

Masalah ini disebabkan oleh ketidakselarasan antara model data di sisi klien Swift dan respons JSON dari database/API backend:
1.  Model data klien `WasteByMaterial` di `ReportsModels.swift` mendefinisikan variabel `totalWasteAreaCm2: Double` sebagai tipe **non-opsional** (wajib ada).
2.  Di tingkat backend live, untuk beberapa bahan kain yang belum memiliki data pemotongan riil atau tidak memiliki sisa potongan (*waste*), properti `total_waste_area_cm2` bisa bernilai kosong (`null`) atau tidak dikirimkan sama sekali (*omitted*) di dalam elemen JSON-nya.
3.  Ketika `JSONDecoder` mencoba mem-parsing array respons, ketiadaan field ini menyebabkan error kritis `keyNotFound` yang membatalkan seluruh proses pembacaan laporan sehingga UI menampilkan kegagalan pemuatan.

---

## Solusi & Langkah Perbaikan

Untuk menyelesaikan ketidakselarasan ini secara defensif dan kokoh, kami mengubah properti tersebut menjadi **tipe data opsional**:

### 1. Mengubah Skema Model (`ReportsModels.swift`)
Mengubah properti `totalWasteAreaCm2` dari `Double` menjadi `Double?` (opsional):
```swift
struct WasteByMaterial: Codable, Identifiable {
    let materialId: UUID
    let materialName: String
    let avgWastePct: Double
    let totalWasteAreaCm2: Double? // Menggunakan opsional untuk penanganan aman null

    var id: UUID { materialId }

    enum CodingKeys: String, CodingKey {
        case materialId = "material_id"
        case materialName = "material_name"
        case avgWastePct = "avg_waste_pct"
        case totalWasteAreaCm2 = "total_waste_area_cm2"
    }
}
```

### 2. Memberikan Fallback Visual di UI (`ReportsView.swift`)
Pada tampilan daftar baris waste, kami menyematkan operator fallback `?? 0` agar jika properti tersebut bernilai `null` dari API, UI akan tetap menampilkan `0 cm²` secara aman tanpa memicu crash:
```swift
Text("\(item.totalWasteAreaCm2 ?? 0, specifier: "%.0f") cm²")
```

## Verifikasi Hasil

*   **Pemuatan Sukses:** Laporan Waste Kain sekarang dapat terbuka dan di-load secara sukses 100% tanpa adanya error decoding.
*   **Keamanan Eksekusi:** Aplikasi berjalan kokoh (*defensive programming*) sekalipun database mengembalikan data parsial atau kosong untuk beberapa bahan kain historis.
