## A. QR Cart Mode (Keranjang) — Scan Multiple → Single Checkout

### Latar Belakang

v3.17 mengimplementasikan scan QR one-shot: scan satu produk → ScanToSellSheet (qty + harga) → POST. Untuk kasir di market atau packaging session, flow ini masih terlalu lambat — setiap item butuh konfirmasi terpisah.

Implementasi baru menambahkan **cart mode** di `QRScannerSheet` mode `.sellOnly`: scanner tetap aktif selama scanning, setiap scan menambah item ke keranjang virtual, checkout dilakukan sekali untuk semua item dalam satu SalesOrder.

### Behavior

| Aksi | Hasil |
|---|---|
| Scan QR produk (pertama kali) | Produk masuk keranjang, toast "ditambahkan" muncul, scanner langsung aktif kembali |
| Scan QR produk yang sama lagi | Qty bertambah +1, toast "N×" muncul |
| Scan produk melebihi stok | Toast error "Stok penuh", scan diabaikan |
| Tap "Checkout →" di cart bar | Scanner pause, `QRCartCheckoutSheet` terbuka |
| Kembali dari checkout | Cart tetap, scanner aktif kembali |
| Konfirmasi pembayaran | Satu `POST /sales-orders` dengan semua items, `markSalesOrderPaid`, keranjang kosong, scanner sheet dismiss |

### Komponen

**`cartBar` (bottom bar saat keranjang tidak kosong):**
- Tampil: cart icon + jumlah item + total Rupiah + "Checkout →" button
- Background: `.ultraThinMaterial`
- Menyembunyikan `scanHint` saat ada item

**`cartToast` (top floating notification):**
- Background hitam semi-transparan, checkmark hijau
- Auto-dismiss setelah 1.8 detik
- Animation: `.spring(response: 0.3, dampingFraction: 0.7)` (iOS 16 compat)

**`QRCartCheckoutSheet` (private struct dalam QRScannerSheet.swift):**
- List produk dengan stepper per item (trash icon saat qty=1 → hapus)
- Swipe-to-delete untuk hapus item
- Payment method chips (Cash/Transfer/QRIS/Marketplace) + `@AppStorage` untuk persist last-used
- Optional customer name
- Total + confirm button
- Warning banner jika ada produk tanpa HPP batch (Opsi A — lihat bagian B)

### State

```swift
@State private var cartItems: [CartItem] = []
@State private var showCheckoutSheet = false
@State private var cartToast: String? = nil

private var isScanning: Bool {
    scanState == .scanning && !showCheckoutSheet
}
```

`CartItem` struct (private, dalam QRScannerSheet.swift):
```swift
private struct CartItem: Identifiable {
    let id = UUID()       // untuk ForEach identity
    let size: ProductSizeDetail
    var qty: Int
    var unitPrice: Double
}
```

### QRGeneratorView PDF Layout (juga di v3.18)

Perubahan layout PDF setelah tuning empiris:

| Parameter | Nilai sebelumnya (v3.17) | Nilai sekarang |
|---|---|---|
| QR size | 3×3 cm (estimasi awal) | 1.8 cm × 1.8 cm |
| Margin kertas | tidak ditentukan | 2 mm |
| Gap antar QR | tidak ditentukan | 0.5 mm |
| Kolom per halaman A4 | 6 | **11** |
| Font caption | tidak ditentukan | 5.5pt, forced 6pt line height |

Caption format: 3 baris — `productName` / `fabricVariantName` (skip jika nil) / `sizeLabel`. Dirender dengan `NSMutableParagraphStyle` dengan `minimumLineHeight = maximumLineHeight = 6.0` untuk kontrol presisi tanpa clipping.

## B. HPP Fallback untuk Stok Manual (Opsi A)

### Root Cause

`POST /sales-orders` saat ini mengambil HPP snapshot dari `production_batch_item` terakhir yang dikonfirmasi untuk `product_size_id` tersebut. Jika tidak ada (stok diinput manual via `adjustStock`), backend mengembalikan error:

```
No HPP recorded yet for product_size_id {id} — cannot compute profit
```

Ini memblokir penjualan sepenuhnya — padahal produk sudah ada, harga sudah ada, yang tidak ada hanya data cost historis.

### Keputusan: Opsi A (Backend Fallback)

Backend diubah agar:
1. Coba ambil HPP dari batch produksi terkonfirmasi (existing behavior)
2. Jika tidak ada → fallback ke **PatternSpec aktif terbaru** untuk product_size tersebut: hitung estimated HPP dari material costs + labor
3. Jika tidak ada PatternSpec → lanjutkan dengan `hpp_total = 0`, tandai `hpp_source = "manual"`

Ini tidak memblokir penjualan dan tetap mencatat estimasi profit yang useful.

### Frontend Changes (sudah diimplementasikan)

**Warning banner** di `ScanToSellSheet` dan `QRCartCheckoutSheet` ketika `size.latestHppBreakdown == nil`:

```
ℹ️ Profit dihitung dari estimasi resep pola — batch produksi belum pernah dikonfirmasi.
```

Banner ini bersifat informatif, bukan blocking. Penjualan tetap bisa dilanjutkan.

Lokasi:
- `ScanToSellSheet.swift` — Section setelah info produk (sebelum form qty/harga)
- `QRScannerSheet.swift` → `QRCartCheckoutSheet` — Section sebelum error message
