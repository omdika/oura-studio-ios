# Version 3.59 - Fitur Cetak Resi Penjualan (Thermal Bluetooth & PDF)

## 1. Problem / Opportunity
*   **Context:** Currently, there's no native functionality to print sales receipts directly from the application. Users need to manually record sales and lack immediate physical proof for customers or digital archives. The existing sales flow lacks immediate post-checkout actions.
*   **Objective:** To provide a seamless and efficient way for users to print sales receipts immediately after recording a sale or later from the sales detail page, supporting both physical thermal printing via Bluetooth (TSPL) and digital PDF export, tailored for 57mm thermal paper.

## 2. User Flow & UX Specifications

**A. Catat Penjualan (Record Sales) Page:**
*   **Toggle Switch:** Add a `UISwitch` (SwiftUI equivalent) labeled "Cetak Struk Otomatis" (Auto Print Receipt).
    *   **Placement:** Directly below the "Sudah Lunas" (Paid) switch.
    *   **Behavior:**
        *   If `on`, after clicking "Simpan" (Save) and successful transaction:
            *   The application will attempt to connect to the last-used Bluetooth thermal printer.
            *   Send TSPL commands to print the receipt.
            *   The "Catat Penjualan" view will dismiss/pop, returning to the previous view (e.g., `ProdukListView`).
            *   **Crucially:** The UI should not block waiting for the print to complete. A subtle toast notification ("Struk sedang dicetak..." / "Receipt printing...") can appear briefly.
        *   If `off`, normal save flow (dismiss view without printing).
    *   **Persistence:** The state of this toggle should be persisted (e.g., using `UserDefaults`) so it remembers the user's preference for subsequent sales.

**B. Daftar Penjualan (Sales List) -> Detail Penjualan (Sales Detail) Page:**
*   **Buttons:**
    *   Add a "Cetak Struk" (Print Receipt) button.
    *   Add a "Simpan sebagai PDF" (Save as PDF) button.
    *   **Placement:** At the top right or bottom action bar of the `DetailPenjualanView`.
*   **Behavior for "Cetak Struk":**
    *   On tap, attempts to connect to the last-used Bluetooth thermal printer and prints the receipt.
    *   Provides feedback on printer status (e.g., "Mencari printer...", "Terhubung...", "Gagal mencetak: Printer tidak ditemukan/offline").
*   **Behavior for "Simpan sebagai PDF":**
    *   On tap, generates a PDF of the receipt and presents a standard share sheet (`UIActivityViewController`) for the user to save, share, or open the PDF.

**C. Printer Configuration / Pairing (Implicit UX - Needs further thought but noted here):**
*   **Initial Setup:** The application needs a way for users to pair with a Bluetooth thermal printer. This could be a dedicated settings page (e.g., "Pengaturan Printer") where users can:
    *   Scan for Bluetooth devices.
    *   Select their thermal printer.
    *   Store the printer's identifier for future auto-connection.
*   **Error Handling:** Clear messages for disconnected printers, paper out, etc.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   No direct database schema changes are immediately required for this feature, as it primarily concerns output and client-side preferences.
*   However, if we want to log print attempts or printer settings globally, a `user_preferences` table or similar could be considered in the future. For now, client-side persistence is sufficient for the toggle state.

## 4. API Contract (FastAPI)
*   No new API endpoints are required. The receipt content will be generated purely from existing sales data fetched via the `GET /api/v1/penjualan/{sale_id}` or similar endpoints that populate the sales detail page.

## 5. Frontend Changes (SwiftUI)

**A. Core Logic:**
*   **Bluetooth Manager:** A new `BluetoothPrinterManager` class/struct to handle:
    *   Bluetooth scanning and connection.
    *   Storing/retrieving last-used printer identifier (`UserDefaults`).
    *   Sending raw TSPL commands.
*   **Receipt Generator:** A `ReceiptGenerator` class/struct responsible for:
    *   Constructing the receipt content based on `Penjualan` (Sales) model data.
    *   Formatting for 57mm paper width (approx 32 characters per line for standard fonts).
    *   Generating QR codes for Instagram and TikTok links.
    *   Converting receipt content into TSPL commands for thermal printing.
    *   Rendering receipt content into a `PDFDocument` or `UIImage` for PDF export.
*   **UserDefaults Integration:** To save the state of the "Cetak Struk Otomatis" toggle.

**B. Views & Modifiers:**
*   **`CatatPenjualanView.swift`:**
    *   Add `Binding<Bool>` for `isAutoPrintEnabled`.
    *   Add `Toggle(isOn: $isAutoPrintEnabled) { Text("Cetak Struk Otomatis") }` below the "Sudah Lunas" toggle.
    *   Modify `simpanPenjualan()` action to check `isAutoPrintEnabled` and trigger `BluetoothPrinterManager.printReceipt()` if true.
    *   Integrate `UserDefaults` for `isAutoPrintEnabled`.
*   **`DetailPenjualanView.swift`:**
    *   Add "Cetak Struk" button: Triggers `BluetoothPrinterManager.printReceipt()`.
    *   Add "Simpan sebagai PDF" button: Triggers `ReceiptGenerator.generatePDF()` and presents `UIActivityViewController`.
*   **`APIService.swift` (or relevant data fetcher):**
    *   Ensure all necessary sales item details, customer info, etc., are available for receipt generation.

## 6. Verification & Test Plan
*   **Smoke Test:**
    *   Verify "Cetak Struk Otomatis" toggle appears and persists state in `CatatPenjualanView`.
    *   Verify "Cetak Struk" and "Simpan sebagai PDF" buttons appear in `DetailPenjualanView`.
*   **Sanity Test Scenarios:**
    *   **Automatic Print:** Record a new sale with "Cetak Struk Otomatis" enabled. Verify the view dismisses immediately and a print job is initiated (e.g., by observing printer activity or a toast message).
    *   **Manual Print (Detail):** Navigate to an existing sale's detail page. Tap "Cetak Struk". Verify print job initiation.
    *   **Save as PDF:** Navigate to an existing sale's detail page. Tap "Simpan sebagai PDF". Verify the share sheet appears with a valid PDF document.
    *   **No Printer Connected:** Test both automatic and manual print when no Bluetooth printer is connected or found. Verify appropriate error messages/UX.
    *   **Content Accuracy:** Verify receipt content (items, quantities, prices, totals, QR codes) is accurate for various sales scenarios (e.g., multiple items, discounts).
    *   **Paper Size/Formatting:** Physically print a receipt on 57mm paper and confirm layout, readability, and fit within the paper width.
