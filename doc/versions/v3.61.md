# Version 3.61 - Sertakan Harga di Label QR (Toggle Radio + Posisi di Atas Size)

## 1. Problem / Opportunity
*   **Context:** Generator QR di halaman Produk saat ini mencetak label thermal 33×15mm (TSPL) dan PDF A4 tanpa informasi harga. Owner ingin opsi menampilkan harga jual tepat di atas caption size pada label agar label bisa langsung ditempel di produk untuk display toko/event. Opsi ini harus bisa diaktifkan/nonaktifkan dengan cepat dan preferensinya persisten.
*   **Objective:** Tambahkan toggle "Sertakan Harga" berbentuk radio button di (a) sheet Generator QR dan (b) Pengaturan Printer Thermal di Lainnya → Pengaturan. Kedua toggle membaca/menulis config yang sama di local storage (`@AppStorage`), default OFF. Saat ON, semua jalur cetak label (thermal TSPL & PDF A4 preview) menyisipkan satu baris harga di atas baris size dengan layout terstruktur yang ada.

## 2. User Flow & UX Specifications

### 2.1 Entry Points
*   **P1 — Generator QR:** Sheet `QRGeneratorView` (dibuka dari ProdukListView / ProdukDetailView). Daftar varian dengan checkbox, qty stepper, "Pilih Semua", filter tanggal masuk stok, dan bottom bar `Preview & Print`.
*   **P2 — Pengaturan Printer Thermal:** `SettingsView` → Section "Pengaturan Printer Thermal" (sudah ada: Lebar/Tinggi/Gap + Pilih Printer Bluetooth).

### 2.2 Pengaturan Printer Thermal — Setting Baru
*   **Lokasi:** Di dalam Section "Pengaturan Printer Thermal" di `SettingsView.swift`, sisipkan row baru **di bawah `Jarak Antar Label` dan di atas tombol `Pilih Printer Bluetooth`** (urutan logis: dimensi → opsi konten label → koneksi printer).
*   **Komponen:** Radio Group 2 opsi horizontal (bukan Toggle/Switch), agar konsisten dengan permintaan "pakai radio button":
    *   Label baris: `Sertakan Harga di Label`
    *   Hint: `Jika aktif, harga jual akan dicetak di atas ukuran pada label thermal & PDF.`
    *   Opsi: `○ Ya` | `○ Tidak` (radio circle, selected = fill + accent color `OuraTheme.Colors.accent`, unselected = border gray)
    *   Visual: Gunakan komponen radio generik (HStack 2 pilihan, tap = select). Selected state menampilkan `circle.fill` accent, unselected `circle`.
*   **Penyimpanan:** `@AppStorage("labelIncludePrice") private var labelIncludePrice: Bool = false` — Bool tunggal, default `false` (tidak sertakan harga, menjaga kompatibilitas label lama).
*   **Reaktivitas:** Perubahan di SettingsView langsung tercermin di QRGeneratorView (dan sebaliknya) karena keduanya mengikat key AppStorage yang sama — tanpa sinkronisasi manual.
*   **Validasi `canSave`:** Tidak ada — radio langsung persist on tap (tanpa tombol Simpan).

### 2.3 Generator QR — Radio Toggle di Sheet
*   **Lokasi:** Di `QRGeneratorView.swift`, tambahkan Section radio **di atas Section "Pilih Semua"** (atau sebagai row standalone di antara Section filter tanggal dan Section "Pilih Semua"), agar terlihat sebelum daftar produk dan dekat dengan aksi cetak, namun tetap di dalam `List` (insetGrouped) sehingga scroll bersama konten.
*   **Komponen:** Radio Group identik dengan di SettingsView (reuse view yang sama):
    *   Label: `Sertakan Harga di Label`
    *   Opsi: `Ya` / `Tidak`
    *   Binding: `@AppStorage("labelIncludePrice") private var labelIncludePrice: Bool` — **key sama persis** dengan SettingsView.
*   **Perilaku:**
    *   Tap `Ya` → `labelIncludePrice = true` → preview label (baik di `ThermalLabelPreviewCard` maupun di `QRPrintPreviewSheet`) langsung menampilkan baris harga; PDF generator akan menyertakan harga saat `preparePDF()` dipanggil.
    *   Tap `Tidak` → `labelIncludePrice = false` → baris harga hilang di semua preview/cetak.
*   **State & Progressive Disclosure:** Radio selalu enabled (tidak tergantung seleksi varian). Tidak memblokir `Preview & Print`.
*   **Alternatif yang ditolak:** Menaruh toggle di `QRPrintPreviewSheet` saja — ditolak karena user harus melihat opsi sebelum memilih varian, dan preview sheet adalah langkah terakhir. Toggle di list utama memberi feedback lebih awal.

### 2.4 Posisi Harga di Label
*   **Aturan penempatan:** Harga ditempatkan **tepat di atas caption size**, di dalam blok teks terstruktur di sebelah kanan QR (area caption). Urutan vertikal dari atas ke bawah (y = rata atas sejajar QR, x = textX):
    1. SKU (font "3"→"2"→"1" auto-shrink)
    2. Nama produk (font "1", maks 2 baris)
    3. Varian kain (font "1", 1 baris, jika ada)
    4. **Harga** ← BARU, hanya jika `labelIncludePrice == true` dan `sellingPrice != nil`
    5. Size (font "2", dipin di bawah dengan margin 16 dots)
*   **Jika toggle OFF atau `sellingPrice == nil`:** Langkah 4 dilewati sepenuhnya; layout kembali ke urutan lama (SKU → nama → varian → size) tanpa celah kosong.
*   **Jika varian tidak punya `selling_price`:** Saat toggle ON, baris harga tetap dirender sebagai placeholder `Rp -` atau dilewati? Keputusan: **lewati baris harga untuk varian tersebut saja** (jangan cetak "Rp -") agar label tidak menampilkan informasi menyesatkan. Varian lain yang punya harga tetap menampilkan harganya. PDF dan thermal konsisten.
*   **Format harga:** Rupiah Indonesia tanpa desimal: `Rp 75.000` (gunakan `NumberFormatter` locale `id_ID`, grouping separator `.`, tanpa `,00`). Contoh: `22000` → `Rp 22.000`.
*   **Visual hierarchy harga:** Font "1" bold? Mengikuti konsistensi existing: SKU bold besar, size semibold accent. Harga sebaiknya **font "2" regular atau semibold, warna `textPrimary`**, agar tidak bersaing dengan size yang dipin di bawah (size tetap accent). Di preview SwiftUI, harga menggunakan `.font(.system(size: 9, weight: .medium))` dengan `foregroundStyle(OuraTheme.Colors.textPrimary)`.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Tidak ada perubahan DB.** `selling_price` sudah ada di `product_size` (`NUMERIC`, nullable, `api_contract.md` baris 405) dan sudah dikembalikan di `GET /products/{sku}/sizes` serta `GET /products` enrichment via `ProductSizeDetail.sellingPrice: Double?` (`ProductModels.swift:172`). Toggle disimpan murni di client local storage.

## 4. API Contract (FastAPI)
*   **Tidak ada endpoint baru atau perubahan kontrak.** Data harga diambil dari endpoint existing yang sudah dipakai `QRGeneratorView.loadData()`:
    *   `GET /products` + `GET /products/{sku}/sizes` (via `api.getAllProductSizes()`) — sudah mengembalikan `selling_price`.
*   **Validasi & Errors:** Tidak ada — jika `selling_price` null, baris harga di-skip per-varian (bukan error).

## 5. Frontend Changes (SwiftUI)

### 5.1 Shared Config & Helper
*   **AppStorage key (baru):**
    ```swift

    ```
    *   Key harus identik di `SettingsView.swift`, `QRGeneratorView.swift`, `PrintPreviewSheet.swift` (dan `QRPrintPreviewSheet` di dalam QRGeneratorView).
*   **Helper format Rupiah (reuse atau baru):**
    ```swift
    extension Double {
        var rupiahLabel: String {
            let f = NumberFormatter()
            f.numberStyle = .decimal
            f.locale = Locale(identifier: "id_ID")
            f.groupingSeparator = "."
            f.maximumFractionDigits = 0
            return "Rp \(f.string(from: NSNumber(value: self)) ?? "\(Int(self))")"
        }
    }
    // atau gunakan existing .rupiahFormatted jika sudah ada
    ```
*   **Komponen Radio generik (baru, reusable):**

## 6. Verification & Test Plan

### 6.1 Smoke Test
1. Build & run — navigasi: Produk → Generator QR (sheet) → terlihat radio "Sertakan Harga" dengan opsi Ya/Tidak (default Tidak).
2. Buka Lainnya → Pengaturan → scroll ke "Pengaturan Printer Thermal" → terlihat radio yang sama di bawah Jarak Antar Label.
3. Ubah di Generator QR ke Ya → tutup sheet, buka Pengaturan → radio di Pengaturan ikut berubah ke Ya (dan sebaliknya) — bukti AppStorage sinkron.
4. Restart app → pilihan Ya/Tidak tetap persist (UserDefaults).
5. Pilih 1 varian dengan harga (mis. M·Satin Rp 22.000) → Preview & Print → di daftar thermal label dan di preview card thermal, lihat baris harga di atas size. Cetak thermal (jika printer tersedia) → verifikasi fisik posisi harga di atas size.
6. Matikan toggle → baris harga hilang di preview & cetak.

### 6.2 Sanity Test Scenarios
*   **Harga null/missing:** Buat varian tanpa selling_price (baru, belum di-set) → toggle Ya → label varian tersebut TIDAK menampilkan baris harga (tidak ada "Rp -"), varian lain dengan harga tetap menampilkan.
*   **Format Rupiah:** sellingPrice `75000` → label menampilkan `Rp 75.000` (bukan `75000` atau `Rp75.000` atau `75,000`).
*   **Posisi di atas size:** Screenshot label thermal / PDF → konfirmasi urutan vertikal: SKU > nama > varian > HARGA > SIZE (size selalu terbawah, dipin). Jika labelIncludePrice OFF, urutan kembali SKU > nama > varian > SIZE tanpa gap ekstra.
*   **Ruang tidak cukup (label pendek):** Set Tinggi Label ke 12mm (lebih pendek dari default 15mm) → toggle Ya → pastikan harga tidak menimpa size yang dipin; jika tidak ada ruang, harga di-skip dengan graceful (size tetap terbawah).
*   **Multi-qty & multi-varian:** Pilih 3 varian, masing-masing qty 2 (total 6 label) → toggle Ya → semua 6 label menampilkan harga masing-masing di atas size-nya (harga per-varian, bukan harga global tunggal).
*   **PDF A4 sinkron:** Toggle Ya → Preview & Print → tab "Kertas A4" → PDF menampilkan harga di atas size untuk setiap cell QR. Toggle Tidak → PDF tanpa harga.
*   **Persistensi cross-sheet:** Set Ya di Generator QR → buka PrintPreviewSheet (single varian dari ProdukDetailView) → preview-nya juga menampilkan harga (karena AppStorage sama).
*   **Backward compat:** AppStorage belum pernah di-set (fresh install) → default Tidak → label lama tanpa harga, tidak ada crash atau migrasi.

### 6.3 Regression Guard
*   Thermal label tanpa harga (default) harus identik pixel-perfect dengan sebelum v3.61 (tidak ada pergeseran layout saat toggle OFF).
*   Bluetooth printing flow (scan/connect/printLabel) tidak berubah kecuali tambahan baris TEXT opsional.
*   Existing reports / HPP / selling_price flows tidak tersentuh.

## 7. Open Questions / Non-Goals
*   **Non-goal:** Tidak ada perubahan backend, tidak ada kolom baru, tidak ada endpoint baru.
*   **Non-goal:** Tidak menambahkan harga ke QR payload (`oura:<UUID>`) — payload tetap UUID saja.
*   **Future (out of scope):** Opsi format harga (dengan/tanpa "Rp"), opsi menampilkan harga diskon/event (v3.58 Intercept Harga) di label — bisa ditambahkan nanti dengan membaca effective price, namun v3.61 memakai `sellingPrice` mentah.
