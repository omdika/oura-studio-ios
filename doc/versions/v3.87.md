# Version 3.87 - Filter Kategori + Jumlah Size per Varian di Produk List

## 1. Problem / Opportunity
*   **Context:** Halaman Produk (`ProdukListView`) sudah menampilkan chip kategori tiap baris, namun belum ada cara untuk **saring daftar produk per kategori** (pouch / scrunchie / semua). User harus scrolling seluruh list untuk mencari produk satu kategori. Selain itu, belum ada ringkasan jumlah varian per ukuran (XS–XXL + Free Size) yang tampil di atas list.
*   **Objective:** Tambah filter kategori (chip single-select: all/pouch/scrunchie, default all) yang berefek ke **komponen total** (Total Produk, Total Varian, Total Stok, Stok Kosong) dan **list produk**, serta tampilkan distribusi jumlah size per varian (XS, S, M, L, XL, XXL, Free Size) di atas list. Backend sudah punya kolom `product.category` (nullable, nilai pouch/scrunchie), jadi filter dilakukan **server-side** via `GET /products?category=` agar tetap pakai pagination, tidak perlu load-all client-side.

## 2. User Flow & UX Specifications
*   **Entry Point:** Halaman Produk (tab Produk). Filter kategori ditempatkan di area header/atas list produk (di bawah search header, di atas kartu total).
*   **UI Components:** `ChipSingleSelect` (existing component di `Components/ChipSingleSelect.swift`) dengan opsi `all` / `pouch` / `scrunchie`. Opsi "all" = default (tidak ada chip terpilih / semua kategori).
*   **Distribusi size:** Baris chip/count di atas list produk, satu chip per label ukuran (XS, S, M, L, XL, XXL, Free Size) masing-masing menunjukkan jumlah varian non-archived yang terlihat setelah filter. Urutan tampil: XS → S → M → L → XL → XXL → Free Size.
*   **Efek ke total:** Saat filter kategori aktif (bukan all), semua card total (`totalProductsCount`, `totalVarianCount`, `totalStockQty`, `outOfStockCount`) dihitung dari data yang sudah difilter server-side (bukan `productStats` global yang mencakup semua kategori).
*   **Efek ke list:** `filteredProductsToDisplay` hanya menampilkan produk non-archived yang kategori-nya cocok. Produk di luar kategori tersembunyi dari list. Pagination tetap berjalan normal karena filter di sisi server.
*   **State:** `@State private var selectedCategory: ProductCategory = .all` dengan enum `ProductCategory` (all / pouch / scrunchie), match case-insensitive pada `Product.category`.
*   **Reset:** Mengganti kategori memicu `requestReload(force: true)` (sama seperti toggle filter tanggal via `onChange(of: isFilterActive)`).
*   **Kombinasi filter:** Kategori + search + filter tanggal tetap saling menghormati (interseksi). Saat filter tanggal aktif, kategori tetap dikirim ke backend.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Tidak ada migration baru.** Kolom `product.category` sudah ada (migration `b5d06862784d_add_category_to_product`, nullable=True, nilai contoh pouch/scrunchie).

## 4. API Contract (FastAPI)
*   **`GET /products`** — tambah query parameter `category` (str, optional):
    *   Jika diisi: filter `Product.category.ilike(category)` (case-insensitive).
    *   Jika tidak diisi / `"all"`: tidak ada filter kategori (perilaku existing).
    *   Response tetap `PaginatedResponse[ProductOut]`, pagination normal.
*   **`GET /products/stats`** — tambah query parameter `category` (str, optional):
    *   Jika diisi: agregasi statistik hanya untuk produk dalam kategori tersebut.
    *   Jika tidak diisi: perilaku existing (semua produk non-archived).
    *   Digunakan agar card total tampil instan dan akurat per kategori.
*   Endpoint lain: tidak ada perubahan.

## 5. Frontend Changes (SwiftUI)
*   **`Networking/APIService.swift`**:
    *   `getProducts(page:limit:search:category:)` — tambah parameter `category: String? = nil`, tambahkan `&category=<value>` ke URL jika diisi.
*   **`Screens/Produk/ProdukListView.swift`**:
    *   Tambah enum `ProductCategory: String, CaseIterable` (all / pouch / scrunchie) dengan `title`.
    *   `@State private var selectedCategory: ProductCategory = .all`.
    *   Panggil `getProducts(page:limit:search:category:)` dengan `category = selectedCategory.rawValue` saat bukan `.all`.
    *   `totalProductsCount`, `totalVarianCount`, `totalStockQty`, `outOfStockCount`: jika kategori aktif → pakai `productStats` (yang sudah difilter per kategori via `getProductStats(category:)`); jika all → pakai `productStats` global (existing).
    *   Tambah computed `sizeCountByLabel: [(label: String, count: Int)]` — kelompokkan `ProductSizeDetail` non-archived milik produk yang lolos filter, grouped by `sizeLabel.uppercased()`, urutkan menurut daftar ["XS","S","M","L","XL","XXL","Free Size"] (pakai `sizeLabelSortKey` existing; label di luar daftar seperti "Free Size" diletakkan terakhir).
    *   Tambah view `sizeDistributionSection` di atas `summaryHeaderView` di dalam `productList` VStack.
    *   Tampilkan `ChipSingleSelect` untuk kategori di area atas (di bawah search header, di atas kartu total).
    *   `onChange(of: selectedCategory)` → `requestReload(force: true)`.
*   **Tidak perlu ubah:** `ProductModels.swift` (category sudah ada), `MockAPIService.swift` (opsional: tambah data pouch untuk uji manual).

## 6. Verification & Test Plan
*   **Smoke Test:** `xcodebuild` sukses + backend build/migration sukses. Buka tab Produk → chip kategori "all" default aktif, list produk muncul, total card tampil.
*   **Sanity Test Scenarios:**
    1.  Pilih chip "pouch" → hanya produk kategori pouch yang muncul di list; Total Produk/Varian/Stok/Stok Kosong menurun sesuai data pouch; distribusi size di atas list berubah hanya mencakup size produk pouch.
    2.  Pilih chip "scrunchie" → hanya produk kategori scrunchie; total dan list menyesuaikan.
    3.  Kembali ke "all" → semua produk non-archived muncul lagi; total kembali ke nilai global (`productStats`).
    4.  Kombinasi kategori + search + filter tanggal → semua filter tetap saling menghormati (interseksi).
    5.  Distribusi size: urutan chip selalu XS, S, M, L, XL, XXL, Free Size; count nol jika tidak ada varian ukuran tersebut.
*   **Test case terkait:** `doc/test/TC-009-filter-kategori-produk.md`.
