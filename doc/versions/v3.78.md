# Version 3.78 - Fix Server Error Saat Edit Metode Pembayaran (SalesOrder)

## 1. Problem / Opportunity
*   **Context:** Saat pengguna membuka detail invoice (mis. INV-000249) lalu mengubah metode pembayaran (Pembayaran → QRIS / Cash / Transfer / Marketplace) dan menekan "Simpan", layar menampilkan banner merah **"Server error"** di bagian bawah. Hal ini terjadi hanya saat mencoba edit metode pembayaran (dan nama pelanggan), bukan saat edit data lain.
*   **Objective:** Mengatasi server error saat edit pembayaran SalesOrder dengan memilih **Opsi A** (frontend-only): nonaktifkan edit `payment_method` dan `customer_name` setelah order dibuat, sesuai desain API existing yang menentukan SalesOrder edit "by design, not supported".

## 2. Decision (Final)
*   **Pilihan: Opsi A** — Frontend-only, tidak perlu perubahan backend.
*   **Alasan:**
    1. Konsisten dengan `api_contract.md` baris 499: SalesOrder edit "🚫 by design, not supported — line items aren't edited after creation (money/stock have already moved); correct via cancel below, then re-enter".
    2. Tidak perlu deploy backend, cepat selesai, risiko regresi rendah.
    3. Best practice POS: transaksi yang sudah dibayar (paid) adalah catatan keuangan immutable; perubahan metode pembayaran harus melalui Void/Refund lalu buat transaksi baru, bukan mengubah data existing.
*   **Opsi B (tidak dipilih):** Menambahkan dukungan backend `PATCH /sales-orders/{id}` untuk `customer_name` / `payment_method`. Ditangguhkan karena membutuhkan perubahan backend + deploy dan bertentangan dengan desain API existing.

## 3. Root Cause (Ditemukan saat penelitian)
*   **Frontend** (`PenjualanListView.swift` baris 670–681): fungsi `save()` memanggil `api.updateSalesOrder(id:customerName:paymentMethod:)` yang mengirim `PATCH /sales-orders/{id}` dengan body `{customer_name, payment_method}`.
*   **Backend** (`app/routers/sales.py` baris 331–344): endpoint `PATCH /{order_id)` hanya menerima body `SalesOrderStatusUpdate` = `{status}` untuk mark paid/unpaid. **Tidak ada field `customer_name` atau `payment_method`** di schema request.
*   **Akibat:** Saat body berisi `customer_name` / `payment_method`, FastAPI/Pydantic menolak request (422 Unprocessable Entity atau 500). Error ditangkap frontend dan ditampilkan sebagai `errorMsg` berwarna merah ("Server error").
*   **API Contract** (`api_contract.md` baris 453): `PATCH /sales-orders/{id} body: { status } -- mark paid` — tidak ada definisi update `customer_name` / `payment_method`.

## 4. Database Schema Changes
*   Tanpa perubahan database. Kolom `payment_method` dan `customer_name` sudah ada di tabel `sales_order` (baris 171–179 `api_contract.md`).

## 5. API Contract (FastAPI)
*   Tidak ada endpoint baru. Endpoint existing `PATCH /sales-orders/{id}` tetap hanya untuk `status`.

## 6. User Flow & UX Specifications
*   **Entry Point:** Dari `PenjualanListView` (detail invoice), section "Info Penjualan" → Picker "Pembayaran" + TextField "Nama pelanggan".
*   **Aturan edit berdasarkan status order:**
    *   **Order belum dibayar (`status == "unpaid"`):** Picker "Pembayaran" dan TextField "Nama pelanggan" tetap bisa diedit (masih dalam fase draft/checkout).
    *   **Order sudah dibayar (`status == "paid"`):** Keduanya **dinonaktifkan (disabled)** / ditampilkan sebagai read-only. Tidak ada tombol Simpan yang memicu `PATCH` dengan field pembayaran/nama pelanggan.
    *   **Order dibatalkan (`status == "cancelled"`):** Tidak bisa diedit (sudah ada logika `isEditable = !order.isCancelled`).
*   **Alur alternatif jika pelanggan ingin mengganti metode pembayaran:** Batalkan order (via `POST /sales-orders/{id}/cancel`) → buat penjualan baru dengan metode pembayaran yang benar.
*   **Indikasi UI:** Saat order sudah paid, tampilkan catatan kecil di bawah field bahwa pembayaran/nama pelanggan tidak dapat diubah setelah transaksi lunas.

## 7. Frontend Changes (SwiftUI)
*   **File:** `Screens/Penjualan/PenjualanListView.swift`
*   **Modifikasi:**
    1. Section "Info Penjualan" (baris 532–544): tambahkan kondisi `isEditable && !order.isPaid` agar Picker "Pembayaran" dan TextField "Nama pelanggan" hanya muncul saat order belum dibayar. Saat sudah paid, sembunyikan section edit atau tampilkan sebagai read-only.
    2. Toolbar "Simpan" (baris 659–665): tetap aktif, tetapi hanya akan mengirim `customerName` (jika berubah) tanpa `paymentMethod` yang dikunci, atau sebaiknya `updateSalesOrder` hanya dipanggil ketika ada perubahan yang diizinkan.
    3. Tambahkan indikasi teks read-only / catatan "Tidak dapat diubah setelah transaksi dibuat" saat `order.isPaid == true`.
*   **Tanpa perubahan backend.**

## 8. Verification & Test Plan
*   **Smoke Test:** App build sukses (`xcodebuild`), layar detail invoice dapat dibuka tanpa crash.
*   **Sanity Test Scenarios:**
    1. Buka detail invoice yang **belum dibayar** → ubah Pembayaran → tekan Simpan → sukses tersimpan, tidak ada "Server error".
    2. Buka detail invoice yang **sudah dibayar (paid)** → Picker Pembayaran dan TextField Nama pelanggan **tidak bisa diubah (disabled/read-only)** → tekan Simpan → tidak ada "Server error".
    3. Buka detail invoice yang sudah paid → coba Batalkan → Buat penjualan baru dengan metode pembayaran berbeda → berhasil.
    4. Buka detail invoice yang sudah dibatalkan → semua field non-editable (sudah ada guard `isEditable`).
