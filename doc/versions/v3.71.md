# Version 3.71 - Tap Stok Habis → Detail Varian Ukuran

## 1. Problem / Opportunity
*   **Context:** Di Beranda, seksi "STOK HABIS" (kartu horizontal, max 5) dan sheet "Stok Habis (243)" via "Lihat semua" saat ini read-only — tap item tidak ke mana-mana. User harus cari manual produk yang habis di tab Produk untuk restock/produksi.
*   **Objective:** Tap item stok habis langsung membuka halaman detail varian ukuran yang habis, dari kartu dashboard maupun dari daftar penuh di sheet.

## 2. User Flow & UX Specifications
*   **Entry Point:** (a) Kartu `stockAlertCard` di `stockOutSection` BerandaView; (b) Row di `StockOutAllSheet` (daftar penuh + searchable).
*   **Flow yang disepakati:**
    1. Tap kartu/row → resolve `ProductSizeDetail` via `api.getProductSizeById(alert.productSizeId)` (`GET /product-sizes/{id}`, kontrak v3.17 — tanpa endpoint/DB baru).
    2. Dari sheet: `dismiss()` dulu, lalu parent resolve + push (tidak ada sheet menumpuk, tidak ada push di dalam sheet).
    3. Push `ProdukSizeDetailView(productSize:)` di `NavigationStack` Beranda (hierarchical push, sesuai aturan struktural #1).
*   **UI Components:**
    *   Bungkus `stockAlertCard` dan row sheet jadi `Button` / `NavigationLink`-style (`.buttonStyle(.plain)` agar kartu tidak berubah visual).
    *   Tambah `chevron.right` kecil di trailing kartu + row sebagai affordance tap.
    *   State loading per-item: `resolvingAlertId: UUID?` — tampilkan `ProgressView` kecil gantikan badge "Habis" saat resolve berjalan; cegah double-tap (guard `resolvingAlertId != nil`).
    *   Error resolve (deleted/archived/network): tampilkan inline banner merah di Beranda (`stockResolveError: String?`, auto-clear saat reload sukses) — tanpa alert blocking.
*   **Validation Rules (`canSave`):** N/A (navigasi read-only, bukan form).
*   **State & Progressive Disclosure:** Tanpa aksi cepat tambahan (disepakati) — user pakai tombol produksi/tambah-stok yang sudah ada di `ProdukSizeDetailView`.
*   **A11y:** `accessibilityIdentifier("stok-habis-item-\(productSizeId)")` di kartu + row; `accessibilityLabel` "Buka detail [productName] ukuran [sizeLabel]".

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Nihil.
*   **New / Modified Columns:** Nihil — `LowStockAlert.productSizeId` sudah ada dan cukup sebagai kunci resolve.

## 4. API Contract (FastAPI)
*   **Endpoints (reuse, tanpa perubahan backend):**
    *   `GET /api/v1/product-sizes/{size_id}`
        *   **Response Body:** `ProductSizeDetail` (id, productSku, productName, sizeLabel, fabricVariantName, stock, HPP, sellingPrice, images).
        *   **Validation & Errors:** 404 jika size dihapus → tampilkan banner "Produk tidak ditemukan / sudah diarsip"; 401 → flow auth existing.
*   **Catatan:** `LowStockAlert` tidak membawa `productSku`/`fabricVariantName`, jadi resolve-by-id adalah satu-satunya cara presisi (nama produk saja ambigu — contoh "scrunchie muslin salur hijau tosca" muncul untuk XL + XXL).

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Nihil — `APIService.getProductSizeById(id:)` + `MockAPIService.getProductSizeById` sudah ada.
*   **Views & Controllers (tepat apa yang diubah):**
    *   `Screens/Beranda/BerandaView.swift`
        *   Tambah `@State private var selectedStockDetail: ProductSizeDetail?`, `@State private var resolvingAlertId: UUID?`, `@State private var stockResolveError: String?`.
        *   `NavigationStack` → `NavigationStack(path:)` atau tambah `.navigationDestination(item: $selectedStockDetail) { ProdukSizeDetailView(productSize: $0) }` (pilih yang minim diff dengan stack existing — stack Beranda saat ini tanpa path, jadi `navigationDestination(item:)` paling aman).
        *   `stockAlertCard(_:)` → bungkus `Button { Task { await resolveAndPush(alert) } }`; tambah chevron + spinner saat `resolvingAlertId == alert.id`.
        *   Tambah `private func resolveAndPush(_ alert: LowStockAlert) async` — guard double-tap, set resolving, `try await api.getProductSizeById`, set `selectedStockDetail`, catch → `stockResolveError`, finally clear resolving.
        *   `.sheet(isPresented: $showAllOut)` → teruskan `onSelect: { alert in showAllOut = false; Task { /* delay ~300ms agar dismiss selesai */ await resolveAndPush(alert) } }`.
        *   Tampilkan `stockResolveError` sebagai banner merah kecil di bawah `stockOutSection` (seperti pola `errorMsg` di detail view).
    *   `Screens/Beranda/StockOutAllSheet.swift`
        *   Tambah `var onSelect: ((LowStockAlert) -> Void)? = nil` (default nil agar preview/call-site lama tidak rusak).
        *   Row `List` → bungkus `Button { onSelect?(alert) }` (atau `Button` panggil `dismiss()` lalu `onSelect` — pilih satu, konsisten: sheet panggil `dismiss()` sendiri lalu `onSelect`, parent tidak perlu dismiss ulang).
        *   Tambah chevron + `accessibilityIdentifier` per row.
*   **Alternatif yang ditolak:** Pindah tab ke Produk (tab 2) + deep-link via `AppState` — kopling antar-tab, race `ProdukListView` reload vs push, dan back-stack membingungkan. Push di stack Beranda lebih sederhana dan sesuai aturan "hierarchical = push".

## 6. Verification & Test Plan
*   **Smoke Test:** Build sukses; Beranda tampil; tap kartu stok habis → push detail tanpa crash; back → kembali ke Beranda; "Lihat semua" → sheet → tap row → sheet tertutup → detail terbuka.
*   **Sanity Test Scenarios:**
    1. Tap kartu XL "scrunchie muslin salur hijau tosca" → detail yang terbuka `sizeLabel == XL` dan `productSizeId` sama dengan alert (bukan XXL).
    2. Dari sheet (243 item), search "orange" → tap "Ukuran XXL" → sheet dismiss → detail XXL orange terbuka.
    3. Double-tap cepat satu kartu → hanya 1 request `GET /product-sizes/{id}` (guard resolving).
    4. Resolve 404 (size dihapus manual) → banner error tampil, tidak crash, tidak push kosong.
    5. Offline/airplane → banner error network, kartu tetap bisa di-tap ulang setelah online.
