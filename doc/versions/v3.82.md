# Version 3.82 - Fix Tidak Bisa Edit Metode Pembayaran di "Catat Penjualan"

## 1. Problem / Opportunity
*   **Context:** Pada layar "Catat Penjualan" (`TambahPenjualanSheet`), field "Pembayaran" menampilkan "Cash" dengan chevron dropdown. Saat pengguna mengetuk baris tersebut, seharusnya layar pilihan pembayaran (Cash / QRIS / Transfer / Marketplace) muncul, tetapi **tidak terjadi apa-apa** — terlihat seperti pembayaran tidak bisa diedit.
*   **Objective:** Membuat field Pembayaran dapat dipilih lagi (membuka layar/daftar pilihan metode pembayaran) saat membuat penjualan baru, tanpa mengubah logika backend.

## 2. Decision (Final)
*   **Pilihan: Opsi A** — Frontend-only, tidak perlu perubahan backend.
*   **Alasan:**
    1. Binding Picker (`@State private var selectedMethod: PaymentMethod = .cash` → `Picker("Pembayaran", selection: $selectedMethod)`) sudah benar struktural dan enum `PaymentMethod` lengkap (`cash`, `transfer`, `qris`, `marketplace`).
    2. Penyebab nyata adalah `.onTapGesture` pada `content` Form (baris 197–199) yang menangkap/swallow setiap tap di area Form, termasuk tap pada baris Picker, sehingga Picker tidak terbuka.
    3. Modifier `.scrollDismissesKeyboard(.interactively)` (baris 255) sudah ada dan cukup untuk menutup keyboard saat scroll, sehingga `.onTapGesture` Form dapat dihapus dengan aman.
    4. Cepat selesai, risiko regresi rendah, tanpa deploy backend.

## 3. Root Cause (Ditemukan saat penelitian)
*   **File:** `Screens/Penjualan/TambahPenjualanSheet.swift`
*   **Baris 197–199:** `.onTapGesture { UIApplication.shared.sendAction(#selector(UIResponder.resignFirstResponder), ...) }` dipasang pada seluruh `content` Form untuk menutup keyboard numerik (karena `numberPad` tidak memiliki tombol "Done" bawaan).
*   **Masalah:** Gesture Form menangkap tap pada baris Picker sebelum Picker mendapat kesempatan mendorong layar pilihan. Akibatnya tap "Pembayaran" diabaikan dan layar pilihan pembayaran tidak terbuka.
*   **Binding yang benar (tidak perlu diubah):** `@State private var selectedMethod: PaymentMethod = .cash` (baris 21), Picker baris 92–96, dan `save()` sudah mengirim `paymentMethod: selectedMethod.rawValue` (baris 606).

## 4. Database Schema Changes
*   Tanpa perubahan database.

## 5. API Contract (FastAPI)
*   Tidak ada endpoint baru / perubahan backend. `POST /sales-orders` tetap menerima `payment_method` dari `selectedMethod.rawValue`.

## 6. User Flow & UX Specifications
*   **Entry Point:** Dari `BerandaView` → "Catat Penjualan (Manual)" → buka `TambahPenjualanSheet` (navigationTitle "Catat Penjualan").
*   **Flow setelah perbaikan:**
    1. Pengguna mengetuk baris "Pembayaran · Cash".
    2. Picker mendorong layar pilihan metode pembayaran (Cash / QRIS / Transfer / Marketplace).
    3. Pengguna memilih metode → `selectedMethod` terupdate → tampilan field berubah sesuai pilihan.
    4. Tekan "Simpan" → `save()` mengirim `paymentMethod` sesuai pilihan.

## 7. Frontend Changes (SwiftUI)
*   **File:** `Screens/Penjualan/TambahPenjualanSheet.swift`
*   **Modifikasi:**
    1. **Hapus** `.onTapGesture` pada `content` Form (baris 197–199 beserta komentar penjelasannya di atasnya, baris 195–196).
    2. Pertahankan `.scrollDismissesKeyboard(.interactively)` pada `NavigationStack` content (baris 255) sebagai pengganti penutup keyboard saat scroll.
    3. Tidak ada perubahan pada Picker baris 92–96, binding `selectedMethod`, atau fungsi `save()`.
*   **Tanpa perubahan backend.**

## 8. Verification & Test Plan
*   **Smoke Test:** App build sukses (`xcodebuild`), layar "Catat Penjualan" dapat dibuka tanpa crash, keyboard numerik tetap bisa ditutup via scroll.
*   **Sanity Test Scenarios:**
    1. Buka "Catat Penjualan" → ketuk baris "Pembayaran · Cash" → layar pilihan metode pembayaran muncul → pilih "QRIS" → field menampilkan "QRIS".
    2. Ulangi pilih "Transfer" dan "Marketplace" → field berubah sesuai pilihan, `marketplaceFeePct` muncul saat pilih Marketplace.
    3. Isi produk + jumlah + tekan "Simpan" → transaksi tersimpan dengan `payment_method` sesuai pilihan yang dipilih.
    4. Tekan di area kosong form / scroll → keyboard numerik tertutup (via `.scrollDismissesKeyboard(.interactively)`).

## 9. Handoff Notes
*   Frontend-only, tidak perlu deploy backend.
