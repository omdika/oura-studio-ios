# Version 3.76 - Fix Pull-to-Refresh Tidak Jalan di ProdukDetailView

## 1. Problem / Opportunity

*   **Context:** Di halaman detail produk (mis. produk "scrunchie satin shimmer hitam", `ProdukDetailView`), gesture tarik-ke-bawah (pull-to-refresh) **tidak memunculkan spinner dan tidak memuat ulang data**. Data baru dimuat sekali saja saat view muncul via `.task` (baris 158–163), lalu statis sampai aplikasi ditutup/dibuka ulang. User tidak bisa memuat ulang stok/harga/galeri varian tanpa keluar lalu kembali ke layar.
*   **Evidence kode:**
    *   `Screens/Produk/ProdukDetailView.swift:112–130` — `body` pakai `ScrollView { VStack { ... } }` tapi **tidak ada modifier `.refreshable` apapun** di seluruh view.
    *   `Screens/Produk/ProdukDetailView.swift:158–163` — `.task { ... loadSizes(); loadGallery() }` hanya jalankan sekali pada appear.
    *   Fungsi pemuatan **sudah ada** dan siap dipakai: `loadSizes()` (baris 723) dan `loadGallery()` (baris 517), hanya belum di-wire ke aksi pull.
*   **Bandingkan pola yang berjalan:**
    *   `ProdukListView.swift:186` — `.refreshable { await loadFirstPage(force: true) }` → pull-to-refresh di daftar produk berjalan normal.
    *   `PenjualanListView.swift:120`, `BahanListView.swift:340`, `ResepListView.swift:196`, `ProduksiBatchView.swift:52`, `OptimasiView.swift:157` → semuanya pakai `.refreshable` di scroll-container.
*   **Objective:** Tambahkan `.refreshable` ke `ProdukDetailView` yang memanggil ulang `loadSizes()` + `loadGallery()`, tanpa menghapus data saat error, pola konsisten dengan `v3.72` (Penjualan) dan `ProdukListView`.

## 2. User Flow & UX Specifications

*   **Entry Point:** Daftar produk (`ProdukListView`) → ketik baris varian/ukuran → push `ProdukDetailView` (scrollable detail produk dengan card ringkasan + galeri + daftar varian).
*   **Perilaku pull-to-refresh:**
    1.  User menarik layar ke bawah di bagian mana pun konten scroll → spinner native iOS muncul.
    2.  Jalankan `loadSizes()` + `loadGallery()` bersamaan (`async let`), sama seperti `.task` awal.
    3.  Saat sukses: `sizes` + `gallery` di-update ulang, UI merefresh otomatis (Spesifik `sizeGroups` derived dari `sizes`).
    4.  Saat gagal jaringan: **data lama tetap tampil** (`sizes`/`gallery` tidak dikosongkan), tampilkan `errorMsg` existing (baris 118–126 sudah ada UI-nya), spinner hilang. Tidak ada false-empty.
    5.  Kosong beneran (200 OK, array kosong): tampilkan "Belum ada ukuran" / "Belum ada galeri" existing, bukan error.
*   **UI Components:** reuse existing — `ScrollView`, `OuraSectionHeader`, `SizeGroupRow`, `ProdukVariantRow`, `ProgressView` (isLoading), error text card (baris 118–126). Tidak ada komponen baru.
*   **Validation Rules (`canSave`):** N/A (layar read-only + refresh).
*   **State & Progressive Disclosure:** `isLoading` sudah ada (baris 72, 691). Tidak perlu state baru; `loadSizes(quiet: true)` bisa dipakai jika ingin menyembunyikan spinner first-load selama pull, tapi minimal pakai `loadSizes()` biasa agar pull tetap memberi indikasi visual via `isLoading`.

    *   `GET /api/v1/products/{sku}/images` via `api.getProductImages(sku:)` (sudah ada, dipakai `loadGallery()`).

## 5. Frontend Changes (SwiftUI)

*   **Codable Models & APIService:** Nihil (reuse `ProductSizeDetail`, `ProductImage`, `api.getProductSizes`, `api.getProductImages`).
*   **Views & Controllers (tepat apa yang diubah):**
    *   `Screens/Produk/ProdukDetailView.swift`
        *   Tambahkan modifier `.refreshable` di akhir chain body (setelah `.task`, sebelum/bersamaan `.toolbar` tambahan), minimal diff:
            ```swift
            .refreshable {
                await loadSizes()
                await loadGallery()
            }
            ```
        *   Posisi: Tempelkan pada `ScrollView` root (baris 113) atau pada `View` utama body setelah modifier `.background/.navigationTitle/.toolbar`, sehingga gesture pull selalu tersedia termasuk saat `isLoading` / empty. Jangan letakkan di dalam `VStack` kondisional.
        *   `loadSizes()` (baris 723) dan `loadGallery()` (baris 517) tidak perlu diubah — langsung dipakai.
        *   `errorMsg` UI sudah ada (baris 118–126), otomatis muncul saat `loadSizes`/`loadGallery` melempar error yang ditangkap caller.
        *   Jaga `sizes`/`gallery` **tidak ditimpa `[]`** saat error (mengikuti pola v3.72, hindari `try? ?? []`).
*   **Alternatif yang ditolak:** `.refreshable` di dalam `VStack` non-scroll (gesture hilang); `try? ?? []` (menelan error → false-empty).

## 6. Verification & Test Plan

*   **Smoke Test:** `xcodebuild` BUILD SUCCEEDED; tab Produk → pilih produk → `ProdukDetailView` terbuka tanpa crash; data varian + galeri tampil.
*   **Sanity Test Scenarios (device/simulator):**
    1.  Buka detail produk → tarik layar ke bawah → spinner native iOS muncul → hilang setelah data selesai dimuat ulang; data tetap/terbaru.
    2.  Airplane-mode lalu pull → spinner muncul → data lama **tetap tampil** (variants dan galeri tidak hilang) + error card (jika ada) muncul, TIDAK jadi layar kosong "Belum ada ukuran/galeri".
    3.  Kembali online lalu pull lagi → data muat ulang tanpa perlu keluar masuk layar.
    4.  Produk yang memang tidak punya varian/galeri → tampilkan empty-state existing, pull tidak muncul error palsu.
    5.  Scroll naik-turun kemudian pull → gesture tetap responsif di posisi scroll mana pun (karena `.refreshable` pada root `ScrollView`).
*   **Regression:** `ProdukListView`, `ProdukSizeGroupView`, `ProdukSizeDetailView`, `TambahProdukBaruSheet` — tidak ada perubahan perilaku (hanya menambah modifier di `ProdukDetailView`).
