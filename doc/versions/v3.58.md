# Version 3.58 - Intercept Harga Event (Temporary Price Adjustment) - Frontend Only

## 1. Problem / Opportunity
*   **Context:** Saat ini, harga jual produk bersifat statis dan langsung diambil dari data produk. Untuk event atau promosi tertentu, seringkali diperlukan penyesuaian harga jual (misalnya, menaikkan harga sebesar X rupiah untuk semua produk) secara sementara tanpa mengubah harga dasar produk secara permanen.
*   **Objective:** Mengimplementasikan fungsionalitas yang memungkinkan penyesuaian harga jual produk secara global dan sementara untuk event tertentu melalui pengaturan lokal di frontend (tanpa mengubah backend). Penyesuaian ini akan otomatis mempengaruhi harga yang ditampilkan di daftar produk, detail produk, serta harga yang tersimpan saat pencatatan penjualan (scan QR maupun input manual).

## 2. User Flow & UX Specifications
*   **Entry Point:** Pengguna mengakses fitur ini melalui menu "Pengaturan" (Settings), di mana akan ada pilihan baru bernama "Intercept / Ubah Harga Event".
*   **UI Components:**
    *   **EventPriceAdjustmentView (New View):**
        *   Sebuah `Toggle` dengan label "Aktifkan Penyesuaian Harga Event" untuk mengaktifkan/menonaktifkan fitur ini.
        *   Sebuah `CurrencyInputField` yang hanya aktif jika toggle di atas ON, untuk menginput "Jumlah Penyesuaian Harga (Rp)". Nilai default 0.
        *   Penyimpanan bersifat instan ke penyimpanan lokal perangkat (`@AppStorage`).
    *   Ketika fitur aktif:
        *   Di `ProdukListView` dan `ProdukDetailView`, harga yang ditampilkan adalah harga dasar `product.price` + `adjustment_amount`.
        *   Ketika mencatat penjualan di `TambahPenjualanSheet.swift` (baik lewat Scan QR maupun Product Picker), harga default `SaleItem.unitPrice` yang masuk ke keranjang otomatis di-intercept menjadi harga dasar + `adjustment_amount`.
*   **Validation Rules (`canSave`):**
    *   Jumlah penyesuaian harga harus berupa angka positif atau nol (>= 0).
*   **State & Progressive Disclosure:** `CurrencyInputField` untuk jumlah penyesuaian harga akan `disabled` jika toggle "Aktifkan Penyesuaian Harga Event" dalam posisi OFF.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada (Zero DB changes).
*   **New / Modified Columns:** Tidak ada. Semua status konfigurasi disimpan secara lokal di frontend menggunakan `@AppStorage`.

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada perubahan pada endpoint backend.
*   **Pencatatan Penjualan:** Saat mengirim data penjualan via `POST /api/v1/sales`, frontend akan mengirimkan harga jual final yang sudah ditambahkan dengan `adjustment_amount` ke dalam properti `unit_price` di `CreateSalesOrderRequest.ItemInput`. Backend akan menyimpan harga ini secara langsung ke database tanpa mengetahui bahwa harga tersebut telah disesuaikan oleh event di frontend.

## 5. Frontend Changes (SwiftUI)
*   **Storage & AppState:**
    *   Gunakan `@AppStorage("eventPriceAdjustmentActive") var isEventActive: Bool = false`
    *   Gunakan `@AppStorage("eventPriceAdjustmentAmount") var eventAdjustmentAmount: Double = 0.0`
    *   Konfigurasi ini bisa diletakkan atau diakses dengan mudah di seluruh View yang relevan.
*   **Views & Controllers:**
    *   `SettingsView`: Menambahkan `NavigationLink` ke `EventPriceAdjustmentView`.
    *   `EventPriceAdjustmentView.swift` (New File): Implementasi tampilan dan logika pengaturan lokal menggunakan `@AppStorage` di atas.
    *   `ProdukListView.swift` & `ProdukDetailView.swift`:
        *   Lakukan intercept visual pada penampilan harga produk: `displayPrice = product.price + (isEventActive ? eventAdjustmentAmount : 0)`.
    *   `TambahPenjualanSheet.swift`:
        *   **QR Scanner (`handleScannedProduct`):** Saat menambahkan produk hasil scan, isi `unitPrice` dengan `size.sellingPrice + (isEventActive ? eventAdjustmentAmount : 0)`.
        *   **Product Picker:** Saat menambahkan produk secara manual lewat picker, isi `unitPrice` dengan `size.sellingPrice + (isEventActive ? eventAdjustmentAmount : 0)`.

## 6. Verification & Test Plan
*   **Smoke Test:**
    *   Verifikasi halaman `EventPriceAdjustmentView` dapat diakses dari `SettingsView`.
    *   Verifikasi toggle dan input nominal berfungsi dengan baik serta tersimpan di `@AppStorage` (nilai tetap bertahan meskipun aplikasi di-restart).
*   **Sanity Test Scenarios:**
    1.  **Aktifkan Penyesuaian:** Atur `eventAdjustmentAmount` ke 10.000, aktifkan toggle. Verifikasi harga dasar di `ProdukListView` dan `ProdukDetailView` bertambah 10.000.
    2.  **Scan Jual dengan Intercept:** Lakukan scan produk / tambah manual di `TambahPenjualanSheet.swift`. Verifikasi harga item di keranjang otomatis terisi harga dasar + 10.000.
    3.  **Simpan Penjualan:** Simpan transaksi tersebut. Verifikasi transaksi berhasil terkirim dan tersimpan di backend dengan harga yang sudah ditambahkan 10.000.
    4.  **Nonaktifkan Penyesuaian:** Matikan toggle. Verifikasi harga di daftar produk kembali ke harga dasar asli, dan item baru di keranjang penjualan menggunakan harga asli tanpa penyesuaian.
