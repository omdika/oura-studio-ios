# v2.9 — DashboardSummary: optional month-level fields (2026-08-09)

**Changed by:** Frontend + Backend  
**Sections affected:** Section 4 (Reports — GET /reports/dashboard)

---

## Summary

Backend `/reports/dashboard` saat ini hanya mengembalikan 5 field (today + low_stock). Lima field month-level belum diimplementasikan dan menyebabkan `keyNotFound 'month_revenue'` decode error — dashboard dan laporan tidak tampil sama sekali.

**Frontend workaround (sudah diimplementasikan):** field month-level dijadikan optional sehingga decode tidak gagal ketika backend belum mengembalikannya.

**Backend task:** tambahkan semua field month-level ke response schema.

---

## Root Cause

Raw backend response saat ini:
```json
{
  "today_revenue": 43333.33,
  "today_order_count": 3,
  "today_profit": 17333.33,
  "today_units_sold": 5,
  "low_stock_alerts": []
}
```

`DashboardSummary` iOS model mengharapkan tambahan 5 field yang tidak ada:
- `month_revenue`
- `month_orders`
- `month_units_sold`
- `month_batches_confirmed`
- `avg_margin_pct`

Karena semua field ini non-optional dalam struct, decoder gagal pada field pertama yang tidak ditemukan dan melempar error — seluruh dashboard menjadi nil.

---

## Frontend Fix (sudah diimplementasikan)

Lima field dijadikan `Optional` di `DashboardSummary`:

```swift
// Sebelum
let monthRevenue: Double
let monthOrders: Int
let monthUnitsSold: Int
let monthBatchesConfirmed: Int
let avgMarginPct: Double

// Sesudah
let monthRevenue: Double?
let monthOrders: Int?
let monthUnitsSold: Int?
let monthBatchesConfirmed: Int?
let avgMarginPct: Double?
```

`BerandaView` sudah menggunakan `dashboard?.avgMarginPct ?? 0` — tidak ada perubahan view. Mock tidak terpengaruh (masih menge-set semua field dengan nilai konkret).

## Backend Task — GET /reports/dashboard: tambah field month-level

### Spec respons yang diharapkan (lengkap)

```json
{
  "today_revenue": 43333.33,
  "today_order_count": 3,
  "today_profit": 17333.33,
  "today_units_sold": 5,
  "month_revenue": 150000.0,
  "month_orders": 12,
  "month_units_sold": 28,
  "month_batches_confirmed": 2,
  "avg_margin_pct": 0.45,
  "low_stock_alerts": [...]
}
```

### Definisi field yang perlu ditambahkan

| Field | Tipe | Definisi |
|---|---|---|
| `month_revenue` | Float | Total revenue dari semua `sales_order` di bulan berjalan (sold_at ≥ awal bulan) |
| `month_orders` | Int | Jumlah `sales_order` di bulan berjalan |
| `month_units_sold` | Int | Total `qty` dari semua `sales_order_item` di bulan berjalan |
| `month_batches_confirmed` | Int | Jumlah `production_batch` dengan `status = 'confirmed'` di bulan berjalan |
| `avg_margin_pct` | Float | Rata-rata `margin_pct` dari semua `product_size` yang memiliki nilai `margin_pct` (tidak null); 0.0 jika tidak ada |

### Catatan implementasi
- "Bulan berjalan" = `sold_at >= date_trunc('month', NOW())` untuk orders; `confirmed_at >= date_trunc('month', NOW())` untuk batches
- `avg_margin_pct` sebaiknya dihitung dari `product_size.margin_pct` jika sudah tersimpan, atau computed on-the-fly dari `(selling_price - hpp) / selling_price`
- Semua field ini **boleh null/missing** sementara backend belum mengimplementasikan — iOS akan menampilkan 0 sebagai fallback
