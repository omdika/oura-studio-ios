# Version 3.66 - Bunuh Burst Paralel Tab Produk (40 Request → 2)

## 1. Problem / Opportunity
*   **Context:** Buka Tab Produk menembak ~40 request konkuren: 20× `GET /products/{sku}/sizes` paralel (`fetchSizes(for:)` TaskGroup, `ProdukListView.swift:661`) + 20× `GET /products/{sku}/images` per kartu (`.task` cover, `:953`). Kebutuhan 40 koneksi vs pool 15 + RTT us-east-1→Seoul ±180ms = jenuh permanen (`QueuePool TimeoutError`) di deployment FastAPI Cloud; semua layar sesudahnya ikut gagal.
*   **Objective:** Buka Tab Produk dengan maksimal 2–3 request sequential-friendly tanpa mengubah tampilan, search, filter tanggal, statistik header, maupun valuasi stok.

## 2. User Flow & UX Specifications
*   Tidak ada perubahan visual. Loading/empty/refresh/search/filter/tab bar tetap. Korelasi produk↔varian yang dulu dijamin per-SKU request kini dijamin filter client-side by `productId` (data identik, dari endpoint bulk yang sama).
*   Cover kartu: dari `product.coverImageURL` (backend v3.65); produk tanpa foto tampil placeholder seperti sebelumnya (cabang `else` yang sudah ada).

## 3. Database Schema Changes
*   NONE (frontend-only untuk burst; field cover dari backend v3.65).

## 4. API Contract
*   Tidak ada endpoint baru. Hilang dari pola panggil: N× `GET /products/{sku}/sizes` paralel dan N× `GET /products/{sku}/images` per kartu. Bertambah: reuse `GET /product-sizes?page=&limit=500` sequential (sudah dipakai picker penjualan). `GET /products/{sku}/images` tetap dipakai layar Galeri Utama (1 call per buka detil — wajar).

## 5. Frontend Changes
*   `Networking/Models/ProductModels.swift` — `Product`: tambah `coverImageURL: String? = nil` + CodingKey `cover_image_url` (default nil → payload lama/cache lama tetap decode).
*   `Screens/Produk/ProdukListView.swift`:
    *   `fetchSizes(for:)` (burst paralel) DIHAPUS. Ganti helper `fetchAllSizesBulk()` — loop `getAllProductSizes(page:limit:500)` sequential (1 koneksi dalam satu waktu), guard maks 10 page, hormati `Task.isCancelled`.
    *   `loadFirstPage` (non-filter): `getProducts(page:1)` + `fetchAllSizesBulk()` lalu `allSizes = bulk.filter { pageProductIds.contains($0.productId) }` (semantik statistik/search per halaman tetap seperti sebelumnya).
    *   `loadMoreProducts`: tanpa fetch sizes tambahan — append produk baru lalu re-filter dari satu bulk refresh (sequential). Tidak ada dedupe manual lagi (assignment wholesale seperti sebelumnya).
    *   `fetchAllProductSizes()` (jalur filter tanggal): delegasikan ke `fetchAllSizesBulk()` (hasil sama, lebih sedikit request).
    *   `ProductGroupRow`: hapus `.task` fetch galeri per kartu + `@State coverURL`; pakai `product.coverImageURL` langsung. `api` env tetap (dipakai upload).
    *   **Fallback tampilan (referensi 2184526):** `coverURL` di-seed dari list; bila nil (backend lama / produk tanpa cover), satu fetch galeri per kartu dengan `CoverFetchLimiter` (maks 3 konkuren, actor privat di file yang sama) — perilaku tampil identik 2184526, mustahil jadi burst paralel lagi.
*   Layar lain tidak disentuh (detil produk/galeri/size-group tetap 1–2 call per buka — aman untuk pool).

## 6. Verification & Test Plan
*   **Smoke:** `swiftc -parse` + full `xcodebuild` bila toolchain mendukung.
*   **Sanity:** buka Tab Produk → hitung request keluar (harus: 1 products + 1–2 bulk sizes, 0 per-SKU, 0 per-card gallery); bandingkan isi kartu (nama, harga min, stok, badge, cover) sebelum/sesudah; search + filter tanggal + loadMore + pull-to-refresh tetap benar; produk tanpa foto tampil placeholder.
