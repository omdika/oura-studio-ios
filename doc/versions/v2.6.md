# v2.6 — API Contract Fixes (2026-08-08)

**Changed by:** Frontend + Backend  
**Sections affected:** Section 4 (Reports, Production)

---

## Summary

Three API contract clarifications discovered during live backend integration testing. No schema changes. Frontend already deployed workarounds; backend needs to align.

---

## Change 1 — `GET /reports/dashboard`: tambah field `today_units_sold`

**Before:**
```json
{ "today_revenue": 0.0, "today_order_count": 0, "today_profit": 0.0, "low_stock_alerts": [] }
```

**After:**
```json
{
  "today_revenue": 0.0,
  "today_order_count": 0,
  "today_units_sold": 0,
  "today_profit": 0.0,
  "low_stock_alerts": [
    { "product_size_id": "...", "product_name": "...", "size_label": "...", "current_stock_qty": 0, "reorder_min_qty": 5 }
  ]
}
```

`today_units_sold` = `SUM(qty)` dari semua `sales_order_item` di mana `sales_order.sold_at` hari ini (server timezone). Digunakan di Beranda screen — label "N item terjual".

---

## Change 2 — `PATCH /production-batches/{id}/items/{item_id}`: response harus item, bukan batch

**Sebelumnya:** backend mengembalikan seluruh objek `production_batch` (root `id` = batch ID).

**Seharusnya:** kembalikan hanya item yang diupdate:

```json
{
  "id": "<item_id>",
  "production_batch_id": "<batch_id>",
  "product_size_id": "<uuid>",
  "pattern_spec_id": "<uuid>",
  "qty_actual": 5,
  "qty_suggested": 10,
  "fabric_cost_per_piece": 2380.0,
  "hpp_fabric": 0.0,
  "hpp_pooled_material": 0.0,
  "hpp_hardware": 0.0,
  "hpp_labor": 0.0,
  "hpp_overhead": 0.0,
  "hpp_total": 0.0
}
```

`hpp_*` boleh `0.0` untuk draft batch — HPP baru dihitung saat `POST /confirm`.

---

## Change 3 — `GET /production-batches`: `product_size_id` harus selalu ada

Tidak ada perubahan spec — ini klarifikasi bahwa implementasi backend salah.

`production_batch_item.product_size_id` adalah `UUID NOT NULL` di schema DB. Backend menghilangkan field ini untuk confirmed batch items, menyebabkan decode error di iOS client.

**Fix backend:** pastikan `product_size_id` selalu di-include dalam response item, baik status `draft` maupun `confirmed`.

**Workaround sementara di frontend:** `productSizeId: UUID?` di `BackendProductionBatchItem` (tolerant decode). Akan dikembalikan ke non-optional setelah backend fix.
