# Version 3.86 - Fix "Tidak Ada Apa-Apa" Saat Simpan Struk PDF di Detil Penjualan

## 1. Problem / Opportunity

*   **Context:** Saat user menekan tombol "Simpan sebagai PDF" di halaman detil penjualan (`EditPenjualanSheet`, section "Struk Penjualan"), tidak ada apa-apa yang terjadi (silent failure). Tidak ada share sheet, tidak ada error message, dan tidak ada file PDF yang tersimpan. Laporan user: 1.a (tidak ada respons saat ditekan).
*   **Root cause (tiga lapis):**
    1. Di `shareReceiptPDF()` (`PenjualanListView.swift`), `UIActivityViewController` di-present via `connectedScenes.first?.windows.first?.rootViewController` yang bisa nil (app baru launch, background, multitasking) → share sheet tidak pernah ditampilkan (silent failure).
    2. `UIActivityViewController` menerima `fileURL` ke temp directory (`file:///private/.../tmp/Struk_...pdf`). iOS Launch Services menolak file URL temp ini dengan error `NSOSStatusErrorDomain Code=-10814` ("Only support loading options for CKShare and SWY types") → share sheet gagal memuat item.
    3. `rootViewController` (`UIHostingController`) sudah mempresentasikan sheet lain (`PresentationHostingController` dari `EditPenjualanSheet`) → `Attempt to present ... which is already presenting ...` crash saat mencoba present `UIActivityViewController` di atasnya.
*   **Objective:** Memastikan tombol "Simpan sebagai PDF" selalu menunjukkan respons (share sheet muncul, atau error message jelas jika benar-benar gagal), tanpa mengubah alur generate PDF yang sudah benar.
*   **Scope:** Frontend iOS SwiftUI only. Tidak ada perubahan backend/database.

## 2. User Flow & UX Specifications

*   **Entry Point:** Penjualan → tap order di daftar → `EditPenjualanSheet` → section "Struk Penjualan" → tombol "Simpan sebagai PDF".
*   **UI Components:** `UIActivityViewController` (share sheet) tetap digunakan. Jika tidak dapat dipresent, tampilkan `Alert` dengan error message.
*   **Validation Rules:** Tidak ada perubahan pada validasi order/item.
*   **State & Progressive Disclosure:**
    *   `shareReceiptPDF()` dijalankan di `@MainActor` (pastikan UIKit drawing + present di main thread).
    *   Jika `UIActivityViewController` gagal dipresent → tampilkan `Alert` "Gagal membuka share sheet: <reason>".
    *   Jika generate PDF atau write file gagal → `errorMsg` ditampilkan di form (perilaku existing, dipertahankan).
    *   Tombol "Simpan sebagai PDF" tetap enabled selama printer tidak sedang cetak (tidak berhubungan dengan printer).

## 3. Database Schema Changes (FastAPI / SQLAlchemy)

*   **Tidak ada.** Frontend-only.

## 4. API Contract (FastAPI)

*   **Tidak ada.** Tidak ada endpoint yang terlibat (PDF di-generate lokal di-device).

## 5. Frontend Changes (SwiftUI)

*   **File yang diubah:** `Screens/Penjualan/PenjualanListView.swift` (struktur `EditPenjualanSheet.shareReceiptPDF()`).
*   **Perubahan utama (tersimpel):**
    1.  Tandai `shareReceiptPDF()` sebagai `@MainActor` (atau panggil via `DispatchQueue.main.async`) agar `UIGraphicsPDFRenderer` dan `UIActivityViewController` selalu berjalan di main thread.
    2.  Ganti resolusi presenting view controller dengan pendekatan yang lebih robust: cari semua window dari `connectedScenes`, ambil yang memiliki `rootViewController`, lalu **turunkan rantai `presentedViewController`** untuk menemukan view controller terpaling atas (menghindari crash "already presenting" ketika sheet lain sedang ditampilkan). Fallback ke `keyWindow?.rootViewController`.
    3.  Jika `presentingViewController` nil setelah semua fallback → set `errorMsg = "Gagal membuka share sheet: tidak ada window yang aktif"` dan **jangan** present `UIActivityViewController` (hindari crash silent).
    4.  **Kirim `Data` langsung (bukan `fileURL`) ke `UIActivityViewController`**: passing `fileURL` ke temp directory menyebabkan `NSOSStatusErrorDomain Code=-10814` dari Launch Services. Dengan `Data`, iOS mengelola temporary file secara internal, share sheet (termasuk "Simpan ke Files") berfungsi normal.
    5.  Sanitasi `invoiceNo` untuk nama file: hilangkan karakter yang tidak aman untuk path (`/`, `:`, `<`, `>`, `\`, `|`, `?`, `*`) sebelum digunakan sebagai nama file.
    6.  Bungkus seluruh alur (generate PDF + present share sheet) dalam satu `do/catch` dengan `errorMsg` yang informatif.
*   **Backward compatibility:** PDF generation (`ReceiptPDFGenerator.generatePDF`) tidak diubah. Alur cetak thermal (`TSPLPrinterService`) tidak diubah.

## 6. Verification & Test Plan

*   **Smoke Test:** Xcode build berhasil. Buka detil penjualan apa pun, tap "Simpan sebagai PDF" → setidaknya ada respons visual (share sheet muncul, atau alert error jika environment tidakSupport).
*   **Sanity Test Scenarios:**
    1.  Buka detil penjualan yang memiliki item, tap "Simpan sebagai PDF" → `UIActivityViewController` muncul, user bisa pilih "Simpan ke Files".
    2.  File PDF berhasil tersimpan di Files dengan nama `Struk_<invoiceNo>.pdf` dan bisa dibuka.
    3.  Jika dijalankan di environment tanpa window aktif (mis. uji automated), tampilkan alert error bukan crash/silent.
    4.  `invoiceNo` dengan karakter aneh (jika ada di masa depan) tidak menyebabkan crash saat menulis file.
*   **Regression:** Cetak struk thermal (`Cetak Struk`) tetap normal. Edit order, tandai lunas, hapus order tidak terpengaruh.
*   **Test case terkait:** `test/docs/TC-006-download-struk-pdf-penjualan.md`.
