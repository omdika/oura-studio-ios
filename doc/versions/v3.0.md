# v3.0 — Sisa Kain: Tampilan Remaining per Purchase + Total Sisa di Header (2026-08-09)

**Changed by:** Frontend  
**Sections affected:** Section 2 (Tab Produksi → Bahan)

---

## Summary

User tidak bisa tahu berapa panjang kain yang masih tersisa. Tag "Sudah dipakai" yang lama muncul begitu ada 1 cm terpakai — misleading karena kain 120 cm yang baru dipakai 22 cm terlihat sama seperti kain yang sudah habis.

Perubahan ini menampilkan sisa kain secara eksplisit di dua tempat: header material dan setiap kartu pembelian.

---

## Change 1 — Header: "Sisa X cm" di samping tag kategori

Di baris yang sama dengan tag `[Kain]`, sekarang muncul capsule badge di sebelah kanan:

- Hijau: `"Sisa 98 cm"` — ada sisa yang cukup
- Merah: `"Sisa 0 cm"` — semua habis
- Tidak muncul: jika `remaining_length_cm` belum tersedia dari backend

Badge menghitung `SUM(remaining_length_cm)` dari semua purchases material tersebut.

---

## Change 2 — Kartu RIWAYAT PEMBELIAN: tag status granular

Tag "Sudah dipakai" (abu-abu, tidak informatif) diganti dengan:

| Kondisi | Tag |
|---|---|
| `remaining == 0` | `[Habis]` merah |
| `0 < remaining < length` | `[Sisa X cm]` kuning warning |
| `remaining == length` | tidak ada tag (belum dipakai) |
| `remaining_length_cm` null | tidak ada tag |

---

## Model Changes

`MaterialPurchase` ditambah dua computed properties:
- `isFullyConsumed: Bool` — `remaining <= 0`
- `isPartiallyConsumed: Bool` — `isConsumed && !isFullyConsumed`

`isConsumed` lama tidak berubah (masih dipakai untuk logika edit-lock di `EditPembelianSheet`).

---

## API Assessment

Tidak ada perubahan API — `remaining_length_cm` sudah dikembalikan backend per purchase sejak v2.5. Frontend hanya belum menampilkannya.

**Catatan untuk backend:** pastikan `remaining_length_cm` diinisialisasi `= length_cm` saat purchase pertama kali dibuat (belum ada konsumsi). Jika diset `0` by default, seluruh stok akan tampak "Habis" padahal belum dipakai.
