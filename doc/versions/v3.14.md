# v3.14 — Multi-Size Recipe Tabs + Tipe Produk Selector

**Date:** 2026-08-18
**Changed by:** Frontend
**Files:** `TambahResepSheet.swift`, `TambahProdukLengkapSheet.swift`, `NumericInputField.swift`

---

## Latar Belakang

Empat gap yang diperbaiki sekaligus:

1. **Multi-size recipe input terlalu linear:** user harus buat resep satu size lalu keluar dan buka lagi untuk size lain. Tidak bisa isi XS → S → M → XL dalam satu sesi.
2. **NumericInputField stale saat ganti tab:** `@State private var text` hanya diinit lewat `onAppear` — ganti tab yang reuse view yang sama tidak memperbarui nilai tampil.
3. **Toggle "Gabungkan dalam satu resep" membingungkan:** muncul di step 2 (saat input resep), terminology tidak jelas, dan konteksnya hilang karena user sudah melupakan step 1.
4. **Preset range size tidak mencakup XXL:** preset "XS – XL" tidak menyertakan XXL padahal produk nyata membutuhkannya.

## Perubahan Frontend

### 1. Multi-size tabs di TambahResepSheet + TambahProdukLengkapSheet

State sebelumnya (single-size):
```swift
@State private var selectedSizeName: String = ""
@State private var fabricLengths: [UUID: Double] = [:]
@State private var fabricWidths: [UUID: Double] = [:]
```

State baru (multi-size, keyed by sizeLabel):
```swift
@State private var activeSizeLabel: String = ""
@State private var fabricLengths: [String: [UUID: Double]] = [:]
@State private var fabricWidths: [String: [UUID: Double]] = [:]
@State private var fabricRotations: [String: [UUID: Bool]] = [:]
```

Tab picker dengan checkmark indicator: tab menampilkan `Image(systemName: "checkmark")` bila semua kain untuk ukuran itu sudah punya panjang + lebar > 0. Background tab: accent (aktif), accentLight+border accent (selesai), surfaceSheet+border (belum).

`sizeIsComplete(_ label: String)` — checks `selectedFabricIds.allSatisfy { (fabricLengths[label]?[id] ?? 0) > 0 && (fabricWidths[label]?[id] ?? 0) > 0 }`.

`canSave` / `recipeCanSave` — tidak lagi mensyaratkan SEMUA ukuran selesai; cukup `uniqueSizeLabels.contains { sizeIsComplete($0) }` — minimal satu ukuran lengkap.

Save logic: loop `completedLabels = uniqueSizeLabels.filter { sizeIsComplete($0) }`, buat satu `CreatePatternSpecRequest` per completed size dengan sequential `await api.createOrUpdatePatternSpec(req)`.

### 2. Fix NumericInputField stale text saat ganti tab

Dua lapis fix:

**(a)** `.onChange(of: value)` dengan guard `!isFocused`:
```swift
.onChange(of: value) { _, newValue in
    guard !isFocused else { return }
    let formatted = newValue.map { formatNum($0) } ?? ""
    if formatted != text { text = formatted }
}
```
Guard `isFocused` mencegah input decimal "0." terhapus saat user masih mengetik (karena `Double("0.") = nil`).

**(b)** `.id(activeSizeLabel + fabId.uuidString)` di fabric VStack — memaksa SwiftUI destroy+recreate view saat tab berganti, sehingga `onAppear` fresh kembali.

### 3. Tipe Produk selector di step 1 (menggantikan toggle gabungkanResep)

Sebelumnya: toggle "Gabungkan dalam satu resep" muncul di step 2 hanya jika `selectedFabricIds.count >= 2`. Terminology tidak intuitif dan muncul di titik yang salah.

Sesudahnya: section **"Tipe Produk"** di step 1, dua card yang bisa ditap:
- **Varian Kain** (default): tiap kain jadi `ProductSize` tersendiri → scrunchie model
- **Kombo Kain**: semua kain masuk dalam satu PatternSpec → pouch model

State: `@State private var isFabricVariant = true`. Save logic: `if !isFabricVariant { ... gabungkan ... } else { ... satu spec per kain ... }`.

Toggle `gabungkanResep` dihapus sepenuhnya dari state + UI + save logic.

### 4. Perubahan preset + tombol + Ukuran di step 2

- Preset "XS – XL" → **"XS – XXL"** (`["XS", "S", "M", "L", "XL", "XXL"]`) di `TambahProdukLengkapSheet` dan `TambahResepSheet` (dalam `TambahProdukCepatSheet`).
- Tombol **"+ Ukuran"** ditambahkan di tab row step 2 (setelah `ForEach(selectedSizes)`), trigger `showCustomSizeAlert = true`.
- Alert "Tambah" action diupdate: setelah `selectedSizes.append(label)`, langsung `activeSizeLabel = label` agar tab baru aktif otomatis.
