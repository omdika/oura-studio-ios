# Version 3.64 - Opsi Diskon × Qty Global di Pengaturan (Default Flat)

> **Menggantikan/supersede `doc/versions/v3.63.md`.** v3.63 mengusulkan toggle `× Qty` per-item in-memory; atas keputusan owner diganti dengan **setting global di halaman Pengaturan, disimpan di local device**, default OFF (flat / tidak dikali qty).

## 1. Problem / Opportunity
*   **Context:** Saat ini field `Diskon` di `TambahPenjualanSheet` selalu dihitung per-pcs: `lineTotal = (unitPrice - discount) * qty`. Contoh screenshot: Qty 2 × Rp25.000 − Diskon Rp2.000 menghasilkan Rp46.000. Owner menghendaki opsi: diskon kadang flat per baris (tidak dikali qty) → hasil yang diharapkan Rp48.000 (`25.000*2 - 2.000`).
*   **Objective:** Tambahkan opsi global "Diskon dikali Qty" di halaman Pengaturan (Lainnya → Pengaturan), disimpan lokal per-device (default **Tidak / flat**). Saat mode × qty aktif, field Diskon di Catat Penjualan menampilkan caption `× qty` di sebelah label. Berlaku di **kedua** alur jual: `TambahPenjualanSheet` (multi-produk) dan `ScanToSellSheet` (jual cepat QR). Frontend-only, tanpa perubahan backend/API.

## 2. User Flow & UX Specifications
*   **Entry Point 1 — Pengaturan:** `LainnyaView` → segmen `Pengaturan` → `SettingsView` → section baru **`Pengaturan Penjualan`** (di atas `Pengaturan Harga`, di bawah `Pengaturan Umum`).
    *   Kontrol: reuse `RadioOptionButton` Ya/Tidak (konsisten dengan `LabelPriceRadioGroup` v3.61) ATAU `Toggle` — pelaksana pilih satu, rekomendasi **Radio Ya/Tidak** agar konsisten.
    *   Label: `Diskon dikali Qty`; hint: `"Jika Ya, diskon per pcs dikali jumlah (Rp2.000 × 2 = Rp4.000). Jika Tidak (default), diskon flat per baris."`
    *   Key: `@AppStorage("discountMultiplyByQty") private var discountMultiplyByQty: Bool = false` (default `false` = flat).
    *   Persist lokal via `UserDefaults`/`AppStorage` — tidak ke backend, tidak perlu login ulang, survive kill/relaunch.
*   **Entry Point 2 — Catat Penjualan (`TambahPenjualanSheet` → kartu tiap item, Section "Produk Dijual"):**
    *   Baca `@AppStorage("discountMultiplyByQty")` yang sama (live update, tidak perlu restart sheet).
    *   Field tetap `CurrencyInputField(label: "Diskon")` (input = nominal Rupiah seperti diketik).
    *   Jika setting ON (`true`): tampilkan caption **`× qty`** di sebelah label Diskon (font 11, `textTertiary`, mis. `HStack` label + caption). Jika OFF: label polos `Diskon` tanpa caption.
    *   Rumus live `totalRevenue` & subtotal per baris:
        *   OFF (flat, default): `lineTotal = unitPrice * qty - discount`
        *   ON (× qty): `lineTotal = (unitPrice - discount) * qty`
    *   Contoh: Qty 2 × 25.000, Diskon 2.000 → OFF = Rp48.000; ON = Rp46.000.
*   **Entry Point 3 — ScanToSell (`ScanToSellSheet` → Section "Detail Penjualan"):**
    *   Sama: baca AppStorage yang sama, caption `× qty` + rumus yang sama untuk `totalAmount`. Saat `qty == 1` kedua rumus identik — caption tetap tampil apa adanya (tidak perlu disable).
*   **UI Components (reuse standard):**
    *   `CurrencyInputField`: tambah param opsional `caption: String? = nil` → header jadi `HStack(spacing: 4) { Text(label); if let caption { Text(caption).font(.system(size: 11)).foregroundStyle(tertiary) } }`. Default `nil` agar semua pemakaian lama tidak berubah.
    *   `RadioOptionButton` (existing di `SettingsView.swift`) untuk Ya/Tidak.
*   **Validation Rules (`canSave`):**
    *   Flat (OFF): `0 <= discount <= unitPrice * qty` (lineTotal >= 0).
    *   Per-pcs (ON): `0 <= discount <= unitPrice`.
    *   `discount == nil/0` = tanpa diskon (selalu valid, abaikan mode).
    *   Jika melanggar → tombol Simpan disabled (`canSave = false`); disarankan border merah / pesan inline `"Diskon melebihi subtotal"` bila murah (opsional, minimal disable + pesan error existing).
*   **State & Progressive Disclosure:**
    *   Tidak ada state per-item; satu sumber kebenaran = AppStorage global.
    *   Mengubah setting saat sheet Catat Penjualan terbuka langsung me-recompute total (SwiftUI binding).
    *   Item baru (`ProductPickerSheet` / `handleScannedProduct`) selalu `discount = nil` seperti sekarang.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada. Zero migration.
*   **Invariants:** Tidak ada kolom/settings backend baru (setting ini murni preferensi tampilan/hitungan lokal per-device).

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada endpoint baru/berubah. `POST /api/v1/sales` / `CreateSalesOrderRequest.ItemInput(product_size_id, qty, unit_price, discount)` tetap sama — backend tetap mengartikan `discount = per-pcs`.
*   **Frontend Conversion Rule (di `save()` kedua sheet):**
    ```swift
    let disc = item.discount ?? 0
    let q = Double(max(1, Int(item.qty ?? 1)))
    let discountToSend: Double? = disc > 0
        ? (discountMultiplyByQty ? disc : disc / q)
        : nil
    ```
    *   Flat Rp2.000 qty 2 → kirim `1000.0`; backend hitung `(25.000−1.000)*2 = 48.000` ✓.
    *   Per-pcs Rp2.000 qty 2 → kirim `2000.0`; backend hitung `46.000` ✓ (perilaku lama).
    *   Rounding: `Double` division; backend NUMERIC(14,4) menampung desimal. Selisih rounding max Rp1 per baris — diterima.
*   **Validation & Errors:** Tidak ada error backend baru. Validasi over-discount sepenuhnya client-side sebelum kirim.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak berubah (`SalesModels.swift`, `MockAPIService`, `ReceiptGenerator`, `ReportsView` tetap pakai `(unitPrice - discount) * qty` — tetap benar karena nilai yang dikirim sudah dikonversi ke per-pcs).
*   **Views & Controllers:**
    *   `Components/CurrencyInputField.swift`:
        *   Tambah `let caption: String? = nil` + render `HStack` label-caption.
    *   `Screens/Lainnya/SettingsView.swift`:
        *   Tambah `@AppStorage("discountMultiplyByQty") private var discountMultiplyByQty = false`.
        *   Tambah Section `Pengaturan Penjualan` berisi radio Ya/Tidak (atau Toggle) + hint; posisikan di antara Pengaturan Umum dan Pengaturan Harga.
    *   `Screens/Penjualan/TambahPenjualanSheet.swift`:
        *   Tambah `@AppStorage("discountMultiplyByQty") private var discountMultiplyByQty = false`.
        *   `totalRevenue`: branch flat vs × qty per rumus di atas.
        *   `itemCard`: `CurrencyInputField(label: "Diskon", caption: discountMultiplyByQty ? "× qty" : nil, value: item.discount)`.
        *   `canSave`: tambah cek batas diskon per mode.
        *   `save()`: terapkan Conversion Rule sebelum bangun `ItemInput`.
    *   `Screens/QR/ScanToSellSheet.swift`:
        *   Tambah `@AppStorage("discountMultiplyByQty")`; `totalAmount` branch rumus yang sama; `CurrencyInputField` Diskon diberi caption yang sama; `save()` konversi flat → `discount/qty`.
*   **Known Limitation (documented, accepted):** Di riwayat/detail/struk, diskon flat akan tampil terpecah per-pcs (mis. input flat 2.000/qty2 tampil sebagai Rp1.000 di detail). Subtotal & total tetap benar. Tidak ada perbaikan display riwayat di scope ini.
*   **Supersede note:** `doc/versions/v3.63.md` dinyatakan **SUPERSEDED** oleh spec ini — jangan implementasikan toggle per-item `isPerQty` dari v3.63.

## 6. Verification & Test Plan
*   **Smoke Test:** Build lolos; buka Lainnya → Pengaturan → section Pengaturan Penjualan muncul, default Tidak; buka Catat Penjualan label Diskon polos; ubah ke Ya → caption `× qty` muncul (tanpa restart); ScanToSellSheet sama.
*   **Sanity Test Scenarios:**
    1.  Default (Tidak/flat): Qty 2 × 25.000, Diskon 2.000 → Total `Rp48.000`; simpan → revenue backend 48.000 (payload kirim discount 1.000).
    2.  Setting Ya: item sama → total `Rp46.000`; simpan → revenue 46.000 (payload 2.000).
    3.  Persistensi: set Ya → kill app → relaunch → setting tetap Ya; set kembali Tidak → tetap.
    4.  Flat over-limit: diskon 60.000 atas subtotal 50.000 (2×25.000) → Simpan disabled (+ pesan bila ada).
    5.  Per-pcs over-limit: setting Ya, diskon 30.000 > harga 25.000 → Simpan disabled.
    6.  Qty 1: diskon 5.000, Ya vs Tidak → hasil identik (20.000 jika harga 25.000).
    7.  Multi-item flat: A (2×25.000−2.000) + B (1×10.000−0) → total 58.000.
    8.  ScanToSell: qty 3 × 10.000, diskon flat 3.000 → total 27.000; payload kirim discount 1.000.
