# Version 3.89 - Fitur Stok Opname (Physical Inventory Count)

## 1. Problem / Opportunity
*   **Context:** Stok barang jadi (`product_size`) saat ini hanya berubah melalui produksi batch yang dikonfirmasi, penjualan, dan penyesuaian manual one-off (`POST /stock/adjustments`). Tidak ada proses terstruktur untuk melakukan stok opname fisik: mencocokkan stok sistem dengan jumlah barang yang sebenarnya ada di rak, lalu menyesuaikan selisih secara teraudit.
*   **Objective:** Tambah fitur Stok Opname yang memungkinkan pengguna scan QR barang secara acak, hitung jumlah fisik per varian, identifikasi variansi (selisih) terhadap stok sistem, dan menyetujui penyesuaian stok yang ditulis sebagai baris `stock_ledger` (`reason='adjustment`) yang append-only.

## 2. Asumsi & Best Practice (diadaptasi ke kondisi lokasi)
*   Produk sebagian besar sudah punya QR code siap scan → **scan adalah input utama**, tidak ada pencarian daftar panjang satu per satu.
*   Produk **tidak tertata urut** (acak/tersebar) → workflow scan-first, cepat, dukung "scan banyak, simpan nanti" (batch), toleran jeda pindah rak.
*   Ada produk **belum masuk stok (terlewat)** atau **produk baru (belum terdaftar)** → jalur cepat inline buat `Product` + `ProductSize` di tengah sesi tanpa keluar dari alur scan.
*   **Session-based:** sesi opname (draft → in_progress → completed/cancelled) agar hitungan bisa jeda/dilanjutkan dan tidak ada yang tersimpan sembarangan.
*   **Snapshot vs hitungan:** tangkap stok sistem saat sesi dimulai; hitungan fisik dipisah; variansi = fisik − sistem.
*   **Reconciliation sebelum kompak:** pengguna menilai counted vs sistem vs variansi, boleh edit jumlah hitungan sebelum menyetujui.
*   **Append-only compliance:** setiap variansi disetujui → tulis `stock_ledger` baris baru `reason='adjustment'` (mereferensi sesi opname), **tidak** mengedit baris ledger lama.
*   **Audit trail:** siapa, kapan, total nilai variansi, catatan per item.
*   **Reuse komponen existing:** `QRScannerSheet`, `canSave` sheet, status layar (empty/loading/filled/error), pull-to-refresh, searchable dropdown, input numerik/mata uang.
*   Navigasi: push untuk hierarki (list→detail), sheet/modal untuk aksi; jangan tambah bottom-nav tab (masukkan ke tab `Lainnya` atau entri dari `Produk`).
*   **Visibilitas hasil opname per produk:** tiap produk/varian menampilkan badge "Terakhir diperiksa: [tanggal]" di ProdukListView dan ProdukSizeDetailView, diambil dari `stock_opname_session.completed_at` terbaru yang menyentuh produk itu. Produk yang belum pernah dicek tampil dengan indikator "Belum pernah dicek".
*   **Filter dan urutan opname di Produk List:** dukung filter "Belum pernah dicek" / "Dicek dalam 30 hari terakhir" dan urutkan berdasarkan "Terakhir diperiksa" sehingga pengguna mudah menemukan produk yang perlu dicek ulang.
*   **Peringatan variansi sebelum commit:** di layar Reconcile, tampilkan peringatan visual (warna) jika variansi per item melebihi ambang (mis. > 10% atau > 5 pcs) dan tampilkan total dampak finansial (Rp) sebelum tombol "Simpan & Selesai" aktif (`canSave`).
*   **Audit trail lewat Stock Ledger:** setiap variansi yang disetujui ditulis sebagai baris `stock_ledger` baru `reason='adjustment'` dengan `ref_id` merujuk ke `stock_opname_session.id` dan `note` menyebut sesi opname. Dari Stock Card per produk (`GET /reports/stock-card/{product_size_id}`), pengguna bisa trace entri adjustment dan mengetahui bahwa itu berasal dari stok opname, kapan, dan dalam sesi mana.
*   **Koreksi kesalahan setelah commit:** karena `stock_ledger` append-only (tidak bisa edit baris lama), jika hitungan ternyata salah, buat sesi opname baru dengan jumlah yang benar → variansi baru ditulis sebagai baris penyeimbang. Baris lama tetap ada sebagai riwayat audit.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
Tabel baru (additive, nol migrasi menghapus tabel lama):

```python
# stock_opname_session
id              UUID PRIMARY KEY
status          TEXT NOT NULL DEFAULT 'draft'        -- 'draft' | 'in_progress' | 'completed' | 'cancelled'
started_at      TIMESTAMPTZ NOT NULL DEFAULT now()
completed_at    TIMESTAMPTZ,                          -- nullable
note            TEXT,                                 -- catatan opname (opsional)
total_variance_value NUMERIC NOT NULL DEFAULT 0     -- total nilai variansi (Rp)
created_at      TIMESTAMPTZ NOT NULL DEFAULT now()

# stock_opname_item
id              UUID PRIMARY KEY
session_id      UUID NOT NULL REFERENCES stock_opname_session(id) ON DELETE CASCADE
product_size_id UUID NOT NULL REFERENCES product_size(id)
scanned_qty     NUMERIC NOT NULL DEFAULT 0           -- jumlah yang dihitung/fisik
system_stock_qty_snapshot NUMERIC NOT NULL DEFAULT 0 -- stok sistem saat item pertama kali dicatat (snapshot)
variance_qty    NUMERIC NOT NULL DEFAULT 0           -- scanned_qty - snapshot (ditentukan ulang pada complete)
note            TEXT                                  -- catatan per item (opsional)
created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
```

Indeks yang disarankan: `stock_opname_session(status, started_at)`, `stock_opname_item(session_id)`.

`last_counted_at` per produk **tidak perlu kolom baru di `product_size`** — derive dari `MAX(stock_opname_session.completed_at)` melalui `stock_opname_item` yang menyentuh produk itu. Untuk performa list produk, bisa dipertimbangkan kolom cache `last_counted_at` di `product_size` di versi lanjutan, tetapi v1 derived-only cukup.

Catatan produk baru/terlewat: saat pengguna menandai item sebagai "produk baru", buat `Product` + `ProductSize` segera melalui endpoint existing (`POST /products`, `POST /products/{sku}/sizes`) lalu buat `stock_opname_item` yang merujuk ke `product_size_id` baru. Tidak ada `product_size_id` nullable yang menunggu di belakang.

## 4. API Contract (FastAPI)
Base path `/api/v1`. Semua endpoint butuh `Authorization: Bearer <token>`.

| Method | Endpoint | Deskripsi |
|---|---|---|
| `POST` | `/stock-opname/sessions` | Buat sesi baru (draft). Body: `{ note? }`. Response: session object. |
| `GET` | `/stock-opname/sessions` | Daftar sesi dengan status, jumlah item, total variansi. Query: `status?`, `from?`, `to?`. |
| `GET` | `/stock-opname/sessions/{id}` | Detail sesi + daftar item (termasuk `product_size` enrichment: nama produk, ukuran, varian, stok sistem). |
| `POST` | `/stock-opname/sessions/{id}/items` | Tambah/tambah item scan. Body: `{ product_size_id, scanned_qty?, note? }`. Jika `product_size_id` sudah ada di sesi, tambah (`increment`) `scanned_qty`. Hanya sesi `draft`/`in_progress`. |
| `PATCH` | `/stock-opname/sessions/{id}/items/{item_id}` | Ubah jumlah hitungan / catatan item. Body: `{ scanned_qty?, note? }`. Hanya sesi `draft`/`in_progress`. |
| `DELETE` | `/stock-opname/sessions/{id}/items/{item_id}` | Hapus item dari sesi. Hanya sesi `draft`/`in_progress`. |
| `POST` | `/stock-opname/sessions/{id}/complete` | Kompak sesi: untuk setiap item hitung `variance_qty = scanned_qty − snapshot`; jika `!= 0` tulis `stock_ledger` baris baru `reason='adjustment'`, `change_qty=variance_qty`, `note` mereferensi sesi; tandai sesi `completed`, isi `completed_at` + `total_variance_value`. Hanya sesi `in_progress`. |
| `POST` | `/stock-opname/sessions/{id}/cancel` | Tandai sesi `cancelled`. Tidak menulis ledger. |
| `POST` | `/stock-opname/sessions/{id}/resume` | Kembalikan sesi `draft`/`cancelled` → `in_progress`. Opsional. |

Validasi & error:
- `409` jika mencoba menambah/edit item pada sesi `completed`/`cancelled`.
- `409` jika `complete` pada sesi bukan `in_progress`.
- `404` jika `product_size_id` tidak ditemukan atau sudah di-archived.
- `422` jika `scanned_qty` < 0.

## 5. Frontend Changes (SwiftUI)
File baru (saran): `Screens/StokOpname/`.
- `StokOpnameListView.swift` — daftar sesi (status badge, total variansi, tombol "+ Buat Opname Baru"), pull-to-refresh, empty state.
- `StokOpnameScannerView.swift` — kamera QR (reuse `QRScannerSheet` / scanner), daftar item yang sudah di-scan di bawah (cart inline), tombol "Tambah Produk Baru".
- `StokOpnameCartView.swift` — daftar item hitungan, edit `scanned_qty` (input numerik), hapus item, tandai item baru.
- `StokOpnameNewProductSheet.swift` — fast create: Nama, SKU (auto-suggest slug), Ukuran (size_label), Varian Kain (opsional) → panggil `POST /products` + `POST /products/{sku}/sizes`, lalu masukkan ke cart.
- `StokOpnameReconcileView.swift` — reviewed counted vs sistem vs variansi per item, edit jumlah sebelum kompak, ringkasan total variansi, peringatan variansi besar (warna), total dampak finansial (Rp), tombol "Simpan & Selesai" (`canSave`).
- `StokOpnameResultView.swift` — ringkasan hasil kompak, daftar penyesuaian ledger yang ditulis.

**Tambahan visibilitas di layar existing:**
- `ProdukListView` / `ProdukSizeDetailView`: tambah badge "Terakhir diperiksa: [tanggal]" atau indikator "Belum pernah dicek", diambil dari `stock_opname_session.completed_at` terbaru melalui `stock_opname_item`.
- `ProdukListView`: tambah filter "Belum pernah dicek" / "Dicek dalam 30 hari terakhir" dan opsi urutan "Terakhir diperiksa".
- `ProdukSizeDetailView`: tambah section "Riwayat Stok Opname" — daftar sesi yang pernah menghitung produk ini (tanggal, jumlah sistem vs fisik, variansi, status).

Codable/APIService: tambah model `StockOpnameSession`, `StockOpnameItem`, dan rute `StockOpnameAPIService` (getSessions, getSession, createSession, addItem, updateItem, deleteItem, complete, cancel).

State & `canSave`:
- Tombol "Simpan & Selesai" disabled jika sesi tidak ada item dengan variansi != 0 ATAU semua item belum direview.
- Konfirmasi discard (`"Buang perubahan?"`) saat menutup sheet/scan yang sudah ada input.

Navigasi: List → Scanner (push). Scanner → Cart (sheet/push). Cart → Reconcile (push). Reconcile → Result (push).

## 6. UI & User Flow Detail

### 6.1 Layar: Daftar Sesi Opname (`StokOpnameListView`)
**Entry point:** Tab `Lainnya` (atau entri dari tab `Produk`).

**Tata letak:**
- Header: judul "Stok Opname" + tombol `+` "Buat Opname Baru" di kanan atas.
- List sesi: setiap row menampilkan:
  - Badge status (`Draft` abu-abu, `Selesai` hijau, `Dibatalkan` merah).
  - Jumlah item yang dicatat.
  - Total variansi (Rp, hijau kalau positif, merah kalau negatif).
  - Tanggal mulai / selesai.
- Empty state: ilustrasi kosong + teks "Belum ada sesi stok opname" + tombol "Buat Opname Baru".
- Pull-to-refresh untuk memuat ulang daftar.

**Status layar:** empty / loading / filled / error (bawa pola existing app).

**Navigasi:** tap row sesi → push ke `StokOpnameScannerView` (untuk draft/in_progress) atau `StokOpnameResultView` (untuk completed).

---

### 6.2 Layar: Scanner + Cart Hitungan (`StokOpnameScannerView`)
**Entry point:** push dari daftar sesi setelah membuat sesi baru.

**Tata letak (layar penuh):**
- Bagian atas: kamera QR (`QRScannerSheet`-style overlay) yang tetap aktif.
- Indikator sesi: "Sesi #X — Draft" + jumlah item yang sudah dicatat.
- Bagian bawah (cart inline, bisa di-scroll): daftar item yang sudah di-scan/ditambah:
  - Setiap item: nama produk, ukuran, varian kain, `scanned_qty` (editable inline), tombol hapus (swipe atau ikon).
  - Jika produk baru/terlewat (tidak punya QR): tombol "+ Tambah Produk Manual" membuka `StokOpnameNewProductSheet`.

**Interaksi:**
- Scan QR produk dikenal → item otomatis masuk cart. Scan ulang produk sama → `scanned_qty` bertambah 1.
- Tap item di cart → edit `scanned_qty` (input numerik).
- Swipe kiri/item → hapus dari cart.

**State:** empty (belum ada item) / filled (ada item) / error (kamera tidak boleh, gagal fetch produk).

**Navigasi:** tombol "Lanjut ke Review" → push ke `StokOpnameReconcileView`. Tidak boleh lanjut jika cart kosong (`canSave` di tombol lanjut).

---

### 6.3 Layar: Tambah Produk Manual (`StokOpnameNewProductSheet`)
**Entry point:** sheet modal dari Scanner saat produk baru/terlewat.

**Form (progressive disclosure):**
1. Nama Produk (text).
2. SKU (auto-suggest slug dari nama, editable).
3. Ukuran (size_label, dropdown/search existing atau baru).
4. Varian Kain (opsional, dropdown existing atau baru).
5. Jumlah Fisik (input numerik, wajib > 0).

**Tombol:** "Simpan & Masukkan ke Cart" (`canSave` aktif jika semua valid). Saat disimpan:
- Panggil `POST /products` + `POST /products/{sku}/sizes` (jika baru).
- Buat `stock_opname_item` dengan `product_size_id` baru.
- Tutup sheet, item muncul di cart scanner.

---

### 6.4 Layar: Reconciliation / Review (`StokOpnameReconcileView`)
**Entry point:** push dari Scanner.

**Tata letak:**
- Header: "Review Hitungan Fisik" + ringkasan kecil (total item, total variansi pcs, total dampak Rp).
- List item per produk:
  - Nama produk, ukuran, varian.
  - **Stok Sistem (Snapshot):** abu-abu, tidak editable.
  - **Jumlah Fisik (scanned_qty):** editable numerik, bisa diubah.
  - **Variansi:** hitungan otomatis (`fisik − sistem`), warna hijau (+) / merah (−) / abu-abu (0).
  - Peringatan visual (border merah / ikon peringatan) jika variansi melebihi ambang (mis. > 10% atau > 5 pcs).
- Footer: total dampak finansial (Rp) + tombol "Simpan & Selesai".

**`canSave`:** tombol "Simpan & Selesai" disabled jika:
- Tidak ada item dengan variansi != 0, ATAU
- Ada item yang nilainya invalid (negatif).

**Interaksi:** user boleh ubah jumlah fisik di sini sebelum menyetujui. Variansi dan total Rp menghitung ulang secara live.

**Navigasi:** tap "Simpan & Selesai" → memicu `POST /sessions/{id}/complete`, lalu push ke `StokOpnameResultView`.

---

### 6.5 Layar: Hasil Kompak (`StokOpnameResultView`)
**Entry point:** push dari Reconcile setelah complete sukses.

**Tampilkan:**
- Status: "Selesai" + tanggal selesai.
- Daftar penyesuaian yang ditulis ke `stock_ledger`:
  - Produk, ukuran, variansi (+/− pcs), dampak Rp, catatan.
- Total variansi akhir (Rp).
- Tombol "Kembali ke Daftar Sesi" (pop ke root list).

**Jika dibatalkan sebelumnya:** layar ini tidak muncul; sesi hanya berstatus `cancelled` tanpa ledger.

## 7. Verification & Test Plan
*   **Smoke test:** App build, tab `Lainnya` (atau entri `Produk`) reachable, layar List/Scanner/Reconcile dapat dibuka tanpa crash, kamera QR izin menangani gracefully.
*   **Sanity test scenarios:**
    1. Scan QR produk yang dikenal → item masuk cart, `scanned_qty` bertambah saat scan duplikat.
    2. Produk baru/terlewat (tidak punya QR) → tambah manual via daftar produk existing atau buat produk baru, masukkan ke cart, hitung jumlah fisik.
    3. Selesaikan sesi dengan variansi positif → `stock_ledger` baru `reason='adjustment'`, `change_qty` = selisih, stok sistem bertambah.
    4. Selesaikan sesi dengan variansi negatif → ledger `change_qty` negatif (stok berkurang).
    5. Edit jumlah hitungan di Reconcile → variansi ulang, tombol Simpan refleksi total baru dan dampak finansial (Rp) berubah.
    6. Peringatan variansi besar muncul di Reconcile jika selisih melebihi ambang.
    7. Batal sesi → tidak ada baris ledger baru, sesi status `cancelled`.
    8. Visibilitas produk: badge "Terakhir diperiksa" muncul di ProdukListView/Detail setelah sesi completed; produk yang belum pernah dicek tampil indikator "Belum pernah dicek".
    9. Filter "Belum pernah dicek" di Produk List menyembunyikan produk yang sudah dicek.
    10. Koreksi setelah commit: buat sesi opname baru dengan jumlah benar → variansi penyeimbang ditulis ke ledger, baris lama tetap ada.

*   **Regression test:** `POST /stock/adjustments` existing dan stok di ProdukListView/Penjualan tetap benar setelah opname; QR jual (`ScanToSellSheet`) tidak rusak; `stock_ledger` tetap append-only (tidak ada baris yang diubah).
