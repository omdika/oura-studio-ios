# Version 3.77 - Fix Pull-to-Refresh + Search-Triggered Reload di ProdukListView

**Status:** IMPLEMENTED
**Date:** 2026-10-29
**Changed by:** Frontend
**Build:** `xcodebuild` BUILD SUCCEEDED
**Git:** commit `9ac3ce5`, pushed to `origin/main`

## 1. Problem / Opportunity

*   **Context:** Di `ProdukListView` (tab Produk), dua bug ditemukan:
    1.  **Pull-to-refresh tidak bekerja.** `.refreshable` awalnya ditempel pada `ZStack` (baris 186), bukan pada scroll container. `ZStack` bukan scrollable view, sehingga gesture tarik-ke-bawah tidak pernah terdeteksi. Perbaikan v3.76 coba menempatkannya pada `ScrollView` di dalam `productList`, tapi `ScrollView` bersarang di dalam `Group > VStack > ZStack` masih menangkap gesture dari layar atas, sehingga pull-to-refresh tetap tidak muncul.
    2.  **Pencarian nama/SKU hanya filter lokal.** `TextField` bind ke `searchText` (baris 267) digunakan hanya untuk `filtered` computed property (baris 46-69) yang memfilter `products` yang sudah di-cache (maksimal 20 produk halaman 1). Tidak ada pemanggilan jaringan saat `searchText` berubah.
*   **Objective:**
    1.  `.refreshable` ditempel pada `ScrollView` di body level (scroll container terluar yang langsung di dalam `ZStack`), sehingga gesture tarik-ke-bawah dari layar atas mencapai refresh control. `productList` tidak lagi punya `ScrollView` sendiri (hanya `VStack`).
    2.  Saat user mengetik di search field, `onChange(of: searchText)` memicu `requestReload(force: true)` → `loadFirstPage(force: true)` fetch semua halaman (`fetchAllProducts`) bila search aktif, lalu filter client-side. Produk di luar halaman 1 juga muncul dalam hasil pencarian.

## 2. User Flow & UX Specifications

*   **Entry Point:** Tab Produk (bottom nav) → `ProdukListView`.
*   **Pull-to-refresh:**
    1.  User menarik layar ke bawah dari atas → spinner native iOS muncul pada `ScrollView` root.
    2.  `loadFirstPage(force: true)` dipanggil → fetch data dari backend → `products` di-update → UI merefresh.
    3.  Saat cache sudah ada: tampilkan data lama + indikator kecil (`isRefreshing`), tidak full-screen spinner.
    4.  Saat gagal jaringan: data lama tetap tampil, tidak dikosongkan.
*   **Search-triggered reload:**
    1.  User mengetik nama atau SKU di search field → `searchText` berubah.
    2.  `onChange(of: searchText)` → `requestReload(force: true)` → `loadFirstPage(force: true)`.
    3.  Bila `searchText` tidak kosong dan `!isFilterActive`: fetch semua halaman via `fetchAllProducts()` + `fetchAllSizesBulk()`, lalu filter client-side oleh `filtered`.
    4.  Saat search dikosongkan: kembali ke pemuatan normal halaman 1 + pagination.
*   **UI Components:** reuse existing — `ScrollView`, `ProgressView`, `TextField`, `ProductGroupRow`, `emptyView`.
*   **Validation Rules (`canSave`):** N/A.
*   **State & Progressive Disclosure:** `isLoading` vs `isRefreshing` dipisah. `loadTask` single-flight + `lastLoadAt` debounce 1 detik sudah menangani burst.

## 5. Frontend Changes

*   **File:** `Screens/Produk/ProdukListView.swift`
    1.  `body`: `VStack(spacing: 0)` dibungkus dalam `ScrollView { ... }`. `.refreshable { await loadFirstPage(force: true) }` ditempel pada `ScrollView` ini (scroll container terluar di dalam `ZStack`).
    2.  `productList`: `ScrollView` wrapper dihilangkan, sekarang hanya mengembalikan `VStack(spacing: 12)`. `.refreshable`, `.scrollDismissesKeyboard`, `.background`, `.simultaneousGesture` dipindah ke `ScrollView` di body.
    3.  `onChange(of: searchText)` ditambahkan pada `VStack` body (baris ~160) → `requestReload(force: true)` saat search text berubah.
    4.  `loadFirstPage`: cabang baru untuk `!searchText.isEmpty && !isFilterActive` → `fetchAllProducts()` + `fetchAllSizesBulk()` sebelum filter client-side (mirip pola `isFilterActive` v3.57).
