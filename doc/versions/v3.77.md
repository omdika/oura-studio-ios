# Version 3.77 - Fix Pull-to-Refresh + Search-Triggered Reload di ProdukListView

## 1. Problem / Opportunity

*   **Context:** Di `ProdukListView` (tab Produk), dua bug ditemukan:
    1.  **Pull-to-refresh tidak bekerja.** `.refreshable` ditempel pada `ZStack` (baris 186) bukan pada `ScrollView` (baris 487, di dalam `productList`). `ZStack` bukan scrollable view, sehingga gesture tarik-ke-bawah tidak pernah dipicu. Padahal `loadFirstPage(force: true)` sudah benar fetch data baru dari `api.getProducts()` dan mengganti `products` (baris 673).
    2.  **Pencarian nama/SKU hanya filter lokal.** `TextField` bind ke `searchText` (baris 267) digunakan hanya untuk `filtered` computed property (baris 46-69) yang memfilter `products` yang sudah di-cache (maksimal 20 produk halaman 1). Tidak ada pemanggilan jaringan saat `searchText` berubah. `getProducts()` API tidak menerima parameter search. Produk di luar halaman 1 tidak pernah dicari atau di-fetch ulang.
*   **Objective:**
    1.  Pindahkan `.refreshable` ke `ScrollView` agar pull-to-refresh deteksi gesture dan memicu `loadFirstPage(force: true)`.
    2.  Saat user mengetik di search field, trigger reload data dari backend (fetch semua halaman bila search aktif, lalu filter client-side) sehingga produk di luar halaman 1 juga muncul dalam hasil pencarian.
*   **Bandingkan pola yang sudah bekerja:** `v3.72` (PenjualanListView) menempatkan `.refreshable` di dalam scroll-container dan memisah `isLoading` vs `isRefreshing`. `v3.57` (ProdukListView date filter) fetch semua halaman saat filter tanggal aktif — pola yang sama dapat diterapkan untuk search.

## 2. User Flow & UX Specifications

*   **Entry Point:** Tab Produk (bottom nav) → `ProdukListView`.
*   **Pull-to-refresh:**
    1.  User menarik layar ke bawah di area daftar produk → spinner native iOS muncul.
    2.  `loadFirstPage(force: true)` dipanggil → fetch `GET /products?page=1&limit=20` → `products` di-update → UI merefresh.
    3.  Saat cache sudah ada: tampilkan data lama + indikator kecil (`isRefreshing`), tidak full-screen spinner (pola v3.72 / v3.60).
    4.  Saat gagal jaringan: data lama tetap tampil, tidak dikosongkan (hindari `try? ?? []`).
*   **Search-triggered reload:**
    1.  User mengetik nama atau SKU di search field → `searchText` berubah.
    2.  Trigger `loadFirstPage(force: true)` yang fetch semua halaman (`fetchAllProducts`) bila `searchText` tidak kosong.
    3.  Setelah data lengkap diterima, filter client-side berdasarkan `searchText` (nama, SKU, ukuran, bahan).
    4.  Saat search dikosongkan (clear X button atau kembali kosong): kembali ke pemuatan normal halaman 1 + pagination.
*   **UI Components:** reuse existing — `ScrollView`, `ProgressView`, `TextField`, `ProductGroupRow`, `emptyView`. Tidak ada komponen baru.
*   **Validation Rules (`canSave`):** N/A (layar read-only + search + refresh).
*   **State & Progressive Disclosure:** `isLoading` (first-load) vs `isRefreshing` (pull/search) dipisah. `searchText: String` sudah ada. `loadTask` single-flight sudah ada (baris 43, 598-602).

## 3. Database Schema Changes (FastAPI / SQLAlchemy)

*   **New / Modified Columns:** Nihil — murni frontend.

## 4. API Contract (FastAPI)

*   **Endpoints (reuse, tanpa perubahan backend):**
    *   `GET /api/v1/products?page=1&limit=20` via `api.getProducts(page:limit:)` (sudah ada).
    *   Tidak ada parameter search baru di endpoint — filtering dilakukan client-side setelah fetch semua data bila search aktif.
*   **Catatan:** `MockAPIService.getProducts()` mengabaikan parameter — verifikasi sanity pakai backend real.

## 5. Frontend Changes (SwiftUI)

*   **Codable Models & APIService:** Nihil (reuse `Product`, `api.getProducts`, `fetchAllProducts`, `fetchAllSizesBulk`).
*   **Views & Controllers (tepat apa yang diubah):**
    *   `Screens/Produk/ProdukListView.swift`
        *   **Pindahkan `.refreshable`:** Dari `ZStack` (baris 186) ke `ScrollView` di dalam `productList` (baris 487), sehingga gesture pull-to-refresh terdeteksi. Atau bungkus isi `ScrollView` dengan `.refreshable` pada `ScrollView` itu sendiri.
        *   **Tambah `onChange(of: searchText)`:** Saat `searchText` berubah dan tidak kosong, panggil `requestReload(force: true)` yang akan `loadFirstPage(force: true)`. Di dalam `loadFirstPage`, bila `searchText` tidak kosong dan `!isFilterActive`, gunakan `fetchAllProducts()` + `fetchAllSizesBulk()` untuk mendapatkan semua data sebelum filter client-side (mirip pola `isFilterActive` di baris 630-655).
        *   **Jaga `products` / `allSizes` tidak ditimpa `[]` saat error:** `loadFirstPage` sudah pakai `try?` + `return` (baris 662, 670) — pertahankan.
        *   **Saas search dikosongkan:** `loadFirstPage` normal (halaman 1 + pagination), `additionsByVariant = [:]`.
        *   Hindari double-reload: `loadTask` single-flight + `lastLoadAt` debounce 1 detik (baris 43-44, 598-602) sudah menangani burst saat `searchText` berubah cepat.
*   **Alternatif yang ditolak:** Biarkan `.refreshable` di `ZStack` (gesture tidak terdeteksi); tambah parameter search ke backend `getProducts` (butuh perubahan backend, out of scope v3.77).

## 6. Verification & Test Plan

*   **Smoke Test:** `xcodebuild` BUILD SUCCEEDED; tab Produk terbuka tanpa crash; daftar produk tampil; search field fokus tanpa crash.
*   **Sanity Test Scenarios (device/simulator):**
    1.  **Pull-to-refresh pada daftar yang sudah ada data:** Tarik layar ke bawah → spinner native muncul → data segar dari backend tampil, produk yang baru ditambahkan muncul di daftar.
    2.  **Pull-to-refresh saat offline:** Spinner muncul → data lama tetap tampil → tidak jadi layar kosong.
    3.  **Search nama produk:** Ketik "polka" → data di-fetch dari backend (semua halaman) → "Scrunchie Satin Polkadot Coklat" muncul meskipun tidak ada di halaman 1.
    4.  **Search SKU:** Ketik SKU parsial → varian/produk yang sesuai muncul.
    5.  **Hapus search (X button):** `searchText = ""` → kembali ke tampilan normal halaman 1 + pagination, tidak ada data sisa dari search sebelumnya.
    6.  **Search lalu pull-to-refresh:** Pull tetap bekerja meski search aktif.
    7.  **Scroll ke bawah saat search aktif:** `loadMoreProducts` tetap jalan (guard `!isFilterActive` hanya skip saat date filter, bukan search).
*   **Regression:** `ProdukDetailView`, `ProdukSizeGroupView`, `TambahProdukBaruSheet`, `ResepStockPickerSheet` — tidak ada perubahan perilaku.
