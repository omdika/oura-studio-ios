## Latar Belakang

User memiliki puluhan material kain dengan nama per warna (Satin Pink, Satin Merah, Satin Hijau, Waffle Kuning, Waffle Biru, dst). Saat membuat resep, user harus mengisi dimensi potongan (panjang × lebar) untuk setiap material secara terpisah — meskipun semua varian warna dari jenis yang sama selalu punya dimensi yang identik per ukuran:

- Satin Pink XS: 90×6 cm
- Satin Merah XS: 90×6 cm ← sama persis
- Satin Hijau XS: 90×6 cm ← sama persis
- Waffle Merah XS: 88×6 cm
- Waffle Kuning XS: 88×6 cm ← sama persis

Dengan range 6 ukuran (XS–XXL) dan misalnya 10 material satin + 5 material waffle, user harus mengisi 6 × 15 = 90 input. Seharusnya cukup 6 × 2 = 12 (satu per jenis per ukuran).

**Root cause:** sistem saat ini tidak punya konsep "jenis kain" — setiap `Material` adalah entitas mandiri tanpa grouping.

---

## Solusi: `fabric_family` field pada Material

Tambahkan field `fabric_family` (nullable string) ke `Material`. Material yang diisi family-nya akan dikelompokkan di form resep. Input dimensi dilakukan sekali per family → sistem expand ke semua material dalam family saat save.

Individual override tetap bisa: jika satu warna satin memang punya dimensi berbeda, user bisa expand family dan override per-warna.

Material tanpa `fabric_family` tetap berfungsi seperti biasa — ditampilkan sebagai entitas individual.

---

## DB Change

```sql
-- Migration: tambah kolom fabric_family ke tabel material
ALTER TABLE material
    ADD COLUMN fabric_family VARCHAR(100) NULL;
```

Tidak ada tabel baru, tidak ada foreign key. Satu kolom nullable — backward compatible penuh. Material lama tetap bekerja dengan `fabric_family = NULL`.

## API Changes

### Existing endpoints yang berubah

| Endpoint | Perubahan |
|---|---|
| `GET /materials` | Tambah `fabric_family: string \| null` di setiap item response |
| `POST /materials` | Terima `fabric_family: string \| null` opsional di request body |
| `PATCH /materials/{id}` | Terima `fabric_family: string \| null` opsional di request body |

### Endpoint baru

```
GET /materials/families
Authorization: Bearer <jwt>
```

Response: `string[]` — array of distinct non-null fabric_family values untuk owner, sorted alphabetically.

Digunakan oleh iOS untuk autocomplete saat user mengedit atau membuat material.

Contoh response:
```json
["Nilon", "Satin", "Waffle"]
```

### Tidak ada perubahan pada PatternSpec endpoints

`POST /pattern-specs` tidak berubah — expansion dari family ke individual material terjadi di iOS client sebelum API call, sehingga request tetap berisi array `fabrics[]` dengan individual `material_id`.

## Frontend Changes

### 1. MaterialModels.swift

```swift
struct Material: Codable, Identifiable, Hashable {
    // ... existing fields ...
    var fabricFamily: String?          // NEW — nullable

    enum CodingKeys: String, CodingKey {
        // ... existing keys ...
        case fabricFamily = "fabric_family"  // NEW
    }

```

### 2. APIService.swift

- `getMaterials()`: sudah decode, tidak ada perubahan selain model
- `GET /materials/families`: endpoint baru — `func getFabricFamilies() async throws -> [String]`
- `createMaterial(...)` / `patchMaterial(...)`: tambah parameter `fabricFamily: String?` opsional, kirim di body

### 3. BahanDetailView / Material edit UI

Tampilkan `fabricFamily` di info card material. Field "Jenis Kain" editable — tapping membuka autocomplete sheet yang load `getFabricFamilies()` dan menampilkan existing families + opsi buat baru (free text).

### 4. TambahPembelianSheet (inline material creation)

Saat user buat material baru inline, tambah field "Jenis Kain" (opsional, dengan autocomplete). Hanya muncul jika `category = .fabric`.

### 5. TambahResepSheet + TambahProdukLengkapSheet (step 2)

**Fabric picker:** ganti `TokenizedMultiSelectField` individual material → grouped picker yang tampilkan families:
- `[Satin (8 warna)]`, `[Waffle (5 warna)]`, `[Nilon (3 warna)]`
- Material tanpa family tetap tampil individual di bawah separator

**Input dimensi per tab ukuran:** ganti `ForEach(selectedFabricIds)` → `ForEach(selectedFamilies)`:
- Header row per family: nama family + input panjang × lebar
- Chevron "Tampilkan per warna" → expand sub-rows per individual material
- Sub-row dengan override: jika warna tertentu punya dimensi berbeda dari family, tampil bold; jika pakai dimensi family, tampil dimmed dengan teks "pakai ukuran Satin"
- Sub-row memiliki input panjang × lebar sendiri (opsional override)

**State baru yang dibutuhkan:**
```swift
// Dimensions keyed by family name (untuk family grouping)
@State private var familyLengths: [String: [String: Double]] = [:] // [sizeLabel: [family: value]]
@State private var familyWidths:  [String: [String: Double]] = [:]

// Per-material overrides (optional, keyed by materialId)  
@State private var overrideLengths: [String: [UUID: Double]] = [:] // [sizeLabel: [materialId: value]]
@State private var overrideWidths:  [String: [UUID: Double]] = [:]
```

**Expand pada save:** sebelum kirim API, expand setiap family ke individual materials:
```swift
// Pseudocode — dijalankan di save()
for family in selectedFamilies {
    let materialsInFamily = fabrics.filter { $0.fabricFamily == family && selectedFabricIds.contains($0.id) }
    for mat in materialsInFamily {
        let length = overrideLengths[sizeLabel]?[mat.id] ?? familyLengths[sizeLabel]?[family] ?? 0
        let width  = overrideWidths[sizeLabel]?[mat.id]  ?? familyWidths[sizeLabel]?[family]  ?? 0
        // append FabricInput(materialId: mat.id, cutLengthCm: length, cutWidthCm: width, ...)
    }
}
```

### 6. ResepEditorView

Sama — pre-populate dari `spec.fabrics[]`, detect family dari material.fabricFamily, group dalam tampilan edit.

### 7. sizeIsComplete update

`sizeIsComplete(_ label: String)` perlu diupdate: cek bahwa setiap family yang dipilih punya length + width > 0 (di level family atau individual override).

## Edge Cases

| Kasus | Handling |
|---|---|
| Material tanpa `fabric_family` | Tampil individual di picker dan form (behavior sama seperti sekarang) |
| Dua material dalam satu family tapi beda dimensi | User expand family → override per material → kedua FabricInput dengan dimensi berbeda dikirim ke API |
| Family dipilih tapi semua materialnya di-deselect | Family hilang dari form |
| Satu material dipindah ke family berbeda setelah resep dibuat | PatternSpec existing tidak berubah (materialId tetap sama); hanya input UI yang berubah ke depannya |
| `fabric_family` dengan karakter aneh | Backend: `VARCHAR(100)`, strip whitespace. iOS: trim sebelum save |
