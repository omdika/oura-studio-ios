# v3.21 — Arsip Bahan (Material Archive)

**Status:** PLANNED
**Date:** 2026-08-21
**Changed by:** Design
**Backend changes required:** Minimal — schema sudah punya `is_archived` di tabel `material`,
tapi perlu dua extension kecil (lihat bagian Backend di bawah).

---

## Latar Belakang

User ingin bisa "menyembunyikan" bahan yang sudah tidak dipakai lagi (warna discontinued,
stok habis dan tidak akan dibeli lagi, bahan TEST) tanpa menghapus riwayat pembelian dan
produksinya. Saat ini tidak ada UI untuk mengarsipkan material — hanya bisa dari database
langsung.

Kerumitan utama: bahan yang diarsipkan mungkin **masih direferensikan oleh resep aktif
(PatternSpec)**. Arsip bahan tidak boleh merusak data resep yang sudah ada.

---

## Prinsip Desain

1. **Arsip bukan hapus.** `PATCH /materials/{id}` dengan `{is_archived: true}`. Data
   pembelian, riwayat pemakaian, dan HPP historis tetap utuh.
2. **Resep lama tetap hidup.** PatternSpec yang mereferensikan bahan diarsipkan TIDAK
   dihapus atau diinvalidasi — mereka tetap bisa dipakai untuk estimasi HPP menggunakan
   `current_avg_cost` terakhir yang tersimpan.
3. **Tidak bisa beli lagi.** Bahan diarsipkan tidak muncul di picker TambahPembelianSheet.
4. **Tidak bisa tambah ke resep baru.** Archived material tidak muncul di FabricPickerSheet
   dan TambahResepSheet.
5. **Bisa di-unarchive kapan saja.** `PATCH` dengan `{is_archived: false}` — tidak ada
   kondisi blocking.
6. **Tidak ada hard delete selama ada riwayat.** Blocked 409 jika sudah ada pembelian
   maupun referensi ke confirmed batch atau PatternSpec.

## Dampak ke Entitas Lain

### PatternSpec / Resep

| Kondisi | Perilaku |
|---|---|
| Resep yang sudah ada mereferensikan bahan diarsipkan | **Tetap valid.** Resep tidak dihapus atau diinvalidasi. |
| ResepListView — baris yang punya bahan diarsipkan | Tampilkan chip kecil `⚠ bahan diarsipkan` di bawah nama fabric (warning color, non-blocking) |
| ResepEditorView — edit resep dengan bahan diarsipkan | Bahan lama tetap tampil di list dengan badge `[Arsip]`. User bisa hapus bahan tersebut dari resep, atau biarkan (non-blocking). |
| TambahResepSheet — picker fabric | Bahan diarsipkan tidak muncul sama sekali (filtered out) |
| HPP estimasi dari resep dengan bahan diarsipkan | **Tetap berfungsi** menggunakan `current_avg_cost` terakhir yang tersimpan di DB |

**Alasan tidak invalidate resep:** `current_avg_cost` tidak berubah saat diarsipkan —
ini adalah snapshot harga terakhir yang valid. HPP estimasi tetap akurat secara historis.
User yang ingin meresepkan ulang dengan bahan baru cukup edit resep dan ganti fabric-nya.

### Optimasi (OptimasiView)

| Kondisi | Perilaku |
|---|---|
| Step 2 — Pilih Kain: roll picker per fabric | Pembelian dari bahan diarsipkan **tidak muncul** di picker (sudah tidak bisa dioptimasi) |
| Resep dengan bahan diarsipkan di Step 1 — Pilih Produk | Tetap muncul di list. Badge `⚠ bahan diarsipkan` di bawah nama fabric. |
| User pilih resep dengan bahan diarsipkan → Step 2 | Roll picker untuk fabric tersebut kosong (no options) → `canCalculate = false` → tombol "Hitung" disabled dengan message: "Tidak ada gulungan tersedia untuk [Nama Bahan]. Bahan diarsipkan." |

### Production Batch

Batch yang sudah confirmed: **tidak terpengaruh sama sekali.** HPP snapshot tersimpan di
`production_batch_item` dan tidak dihitung ulang dari material.

Draft batch yang belum confirmed: masih bisa di-confirm — cutting sudah selesai, kain
sudah terpotong. Bahan diarsipkan tidak block confirm.

### ScanToStockSheet / ScanToSellSheet

Tidak ada perubahan — QR scan bekerja berdasarkan `productSizeId`, bukan `materialId`.
Material archive tidak relevan untuk flow ini.

### TambahPembelianSheet

Picker material (via `InlineSearchDropdownField`) filtered: hanya tampilkan
`is_archived == false`. Bahan diarsipkan tidak bisa dibeli.

## Hard Delete vs Archive

| Kondisi | Action |
|---|---|
| Material belum punya pembelian apapun | Hard delete diizinkan (konfirmasi dialog). Misal: bahan TEST yang tidak jadi dibeli. |
| Material sudah punya pembelian tapi belum ada confirmed batch | Archive direkomendasikan. Hard delete bisa dengan konfirmasi kuat: "Ini akan menghapus semua data pembelian bahan ini secara permanen." |
| Material sudah ada di confirmed batch atau PatternSpec dengan batch history | **Hard delete diblokir.** Hanya archive. Tampilkan pesan: "Bahan ini memiliki riwayat produksi — hanya bisa diarsipkan, tidak bisa dihapus." |

Untuk simplicity di v3.21: **tampilkan tombol "Hapus" hanya jika tidak ada pembelian**.
Jika ada pembelian → hanya "Arsipkan" yang tersedia.

## API Changes

### Backend (minimal)

**Sudah ada:** `PATCH /materials/{id}` — hanya perlu tambah `is_archived` ke
`PatchMaterialRequest` schema jika belum ada:

```python
class PatchMaterialRequest(BaseModel):
    name:            Optional[str]   = None
    reorder_min_qty: Optional[float] = None
    fabric_family:   Optional[str]   = None
    is_archived:     Optional[bool]  = None  # ← ADD jika belum ada
```

**Perlu dicek:** apakah `GET /materials` sudah support `?archived=false` filter (default)
atau perlu ditambahkan. Frontend saat ini mungkin filter client-side. Untuk skala besar
lebih baik server-side.

**Endpoint baru (opsional, bisa defer):**
`GET /materials/{id}/active-specs-count` — jumlah PatternSpec aktif yang referensikan
material ini. Dipakai untuk warning pre-archive jika tidak mau load semua specs di client.

Alternatif (lebih simple): load PatternSpec list saat BahanDetailView dibuka dan filter
client-side (sudah di-load untuk bagian "Resep yang pakai bahan ini" jika ada).

### Frontend

**APIService:**
```swift
func archiveMaterial(_ materialId: UUID) async throws -> Material {
    // PATCH /materials/{id} { is_archived: true }
}

func unarchiveMaterial(_ materialId: UUID) async throws -> Material {
    // PATCH /materials/{id} { is_archived: false }
}
```

**Models:**
`Material` struct sudah punya `isArchived: Bool` atau perlu ditambahkan:
```swift
struct Material: Identifiable, Decodable {
    // ... existing ...
    var isArchived: Bool  // CodingKey: "is_archived"
}
```

## Open Questions

1. **Apakah perlu tampilkan bahan diarsipkan di ResepListView secara default?**
   Saran: tidak (hanya badge warning). Resep tetap valid — user tidak perlu tahu bahan
   diarsipkan kecuali mau edit atau run optimizer.

2. **Apakah `current_avg_cost` perlu di-freeze saat archive?**
   Saran: tidak perlu — nilai sudah tidak akan berubah karena tidak ada pembelian baru.
   Nilai di DB sudah otomatis "frozen".

3. **Apakah PatternSpec perlu otomatis diarsipkan jika semua fabric-nya diarsipkan?**
   Saran: tidak — terlalu agresif. Biarkan user yang decide apakah mau edit resep atau
   unarchive bahan. Badge warning di ResepListView sudah cukup sebagai nudge.
