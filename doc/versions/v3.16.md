# v3.16 — Varian Kain di TambahResepSheet

**Status:** IMPLEMENTED — siap QA
**Date planned:** 2026-08-19
**Date implemented:** 2026-08-19
**Changed by:** Frontend only
**Backend changes:** Tidak ada — semua endpoint sudah ada sejak v1.7. Diverifikasi live terhadap production (oura-backend-seoul + Supabase): GET & POST /products/{sku}/sizes sudah support fabric_variant_name.

---

## Latar Belakang & Root Cause

`TambahResepSheet` saat ini selalu menyimpan **semua kain yang dipilih ke dalam satu PatternSpec per ukuran**. Ini benar untuk produk kombo (pouch: membutuhkan beberapa kain sekaligus), tapi salah untuk produk varian kain (scrunchie: setiap unit hanya butuh SATU jenis kain).

**Bukti bug:**
- User pilih Waffle Hijau + Waffle Red di TambahResepSheet untuk Scrunchie S
- Kedua kain masuk ke satu PatternSpec: `fabrics: [waffle_hijau, waffle_red]`
- Backend + optimizer membaca ini sebagai "untuk buat 1 scrunchie S, butuh KEDUA kain sekaligus"
- Optimizer menampilkan dua roll pilihan seolah keduanya wajib ada — padahal scrunchie hanya butuh salah satu

**Bandingkan dengan `TambahProdukLengkapSheet`:**
Sheet ini sudah punya `isFabricVariant: Bool` yang handle ini dengan benar:
- `Varian Kain` (`isFabricVariant = true`): tiap fabric → ProductSize terpisah (sizeLabel + fabricVariantName) + PatternSpec dengan satu fabric
- `Kombo Kain` (`isFabricVariant = false`): semua fabric → satu PatternSpec per size

`TambahResepSheet` tidak punya konsep ini — selalu bertindak seperti Kombo Kain.

---

## Solusi

Tambahkan `isFabricVariant: Bool` ke `TambahResepSheet` dengan behavior identik dengan `TambahProdukLengkapSheet`.

---

## Dua Mode

### Mode Varian Kain (default, `isFabricVariant = true`)

**Use case:** Scrunchie dengan 8 warna Waffle. Setiap warna = varian produk terpisah.

**Save logic per sizeLabel × fabricId:**
1. Cari ProductSize existing yang cocok: `sizeLabel == label && fabricVariantName == fabric.name`
2. Jika ada → gunakan `productSizeId`-nya langsung (tidak buat baru)
3. Jika tidak ada → `createProductSize(sku, sizeLabel, fabricVariantName: fabric.name)` → append ke `allSizes` lokal (cegah double-create dalam satu session)
4. `createOrUpdatePatternSpec(productSizeId, fabrics: [satu fabric saja], ...)`

**Hasil:** N fabrics × M sizes → N×M PatternSpec individual. Masing-masing dengan satu fabric, masing-masing punya ProductSize sendiri (atau reuse yang sudah ada).

FabricGroup tetap berguna: user isi dimensi sekali per family → semua warna dalam family dapat dimensi sama → saat save, setiap warna jadi PatternSpec terpisah.

### Mode Kombo Kain (`isFabricVariant = false`)

**Use case:** Pouch dengan Outer + Lining + Batting. Semua kain diperlukan bersamaan untuk satu unit.

**Save logic:** Identik dengan behavior TambahResepSheet saat ini — semua fabrics dalam satu PatternSpec per size, linked ke base ProductSize (first match by sizeLabel).

## Perubahan Save Logic (pseudocode)

```swift
private func save() async {
    let completedLabels = uniqueSizeLabels.filter { sizeIsComplete($0) }
    let components = selectedComponentIds.map { ... }

    if isFabricVariant {
        // ── Varian Kain: satu spec per (size × fabric) ──
        for sizeLabel in completedLabels {
            for fabId in selectedFabricIds {
                guard let fabric = fabrics.first(where: { $0.id == fabId }) else { continue }

                // 1. Cari atau buat ProductSize untuk variant ini
                let existingVariant = allSizes.first {
                    $0.sizeLabel == sizeLabel && $0.fabricVariantName == fabric.name
                }
                let targetSizeId: UUID
                if let existing = existingVariant {
                    targetSizeId = existing.id
                } else {
                    let newSize = try await api.createProductSize(
                        sku: selectedProduct!.sku,
                        sizeLabel: sizeLabel,
                        fabricVariantName: fabric.name
                    )
                    allSizes.append(newSize)
                    targetSizeId = newSize.id
                }

                // 2. Buat spec dengan satu fabric
                let fabricInput = CreatePatternSpecRequest.FabricInput(
                    materialId: fabId,
                    cutLengthCm: fabricLengths[sizeLabel]?[fabId] ?? 0,
                    cutWidthCm: fabricWidths[sizeLabel]?[fabId] ?? 0,
                    rotationAllowed: fabricRotations[sizeLabel]?[fabId] ?? true
                )
                let req = CreatePatternSpecRequest(
                    productSizeId: targetSizeId,
                    fabrics: [fabricInput],
                    estLaborMinutes: laborMinutes ?? 0,
                    components: components
                )
                _ = try await api.createOrUpdatePatternSpec(req)
            }
        }
    } else {
        // ── Kombo Kain: behavior existing, tidak berubah ──
        for sizeLabel in completedLabels {
            guard let size = sizesForProduct.first(where: { $0.sizeLabel == sizeLabel }) else { continue }
            let fabricInputs = selectedFabricIds.map { fabId in
                CreatePatternSpecRequest.FabricInput(
                    materialId: fabId,
                    cutLengthCm: fabricLengths[sizeLabel]?[fabId] ?? 0,
                    cutWidthCm: fabricWidths[sizeLabel]?[fabId] ?? 0,
                    rotationAllowed: fabricRotations[sizeLabel]?[fabId] ?? true
                )
            }
            _ = try await api.createOrUpdatePatternSpec(CreatePatternSpecRequest(
                productSizeId: size.id,
                fabrics: fabricInputs,
                estLaborMinutes: laborMinutes ?? 0,
                components: components
            ))
        }
    }
    dismiss()
}
```

## Tidak Ada Backend Change

Semua endpoint yang dibutuhkan sudah ada:

| Endpoint | Dipakai oleh |
|---|---|
| `POST /products/{sku}/sizes` dengan optional `fabric_variant_name` | Create variant size baru jika belum ada (v1.7) |
| `POST /pattern-specs` dengan single fabric | Buat spec per variant (sudah dipakai TambahProdukLengkapSheet) |
| `GET /products/{sku}/sizes` (via getAllProductSizes) | Load existing variant sizes untuk cek duplikat |

---

## Edge Cases

| Kasus | Handling |
|---|---|
| Varian Kain, 1 fabric saja | Buat 1 variant size + spec. Identik dengan TambahProdukLengkapSheet. |
| Varian Kain, variant size sudah ada (nama fabric sama) | Gunakan existing `productSizeId` — tidak duplikat. `allSizes` di-append in-place jika baru buat. |
| Kombo Kain, 1 fabric saja | 1 spec dengan 1 fabric, linked ke base size. Sama seperti sekarang. |
| Mode `isFabricVariant` berubah setelah pilih kain | Hanya mempengaruhi save — pilihan kain + dimensi tidak di-reset. |
| Product dipilih ulang | `allSizes` re-load via `getAllProductSizes()`. Lookup existing variants menggunakan data terbaru. |
| N fabrics × M sizes (contoh: 8 warna × 6 ukuran = 48 API calls) | Sequential await — tidak ideal tapi tolerable untuk session sekali pakai. Bisa di-optimize dengan async let jika perlu. |
