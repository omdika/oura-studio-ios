# Version 3.44 - Filter Rentang Tanggal Update Stok (Updated Date)

## 1. Masalah / Peluang
* **Konteks:** Pemilik toko aksesoris seringkali menambahkan atau memproduksi sekelompok stok produk pada hari tertentu (misal: memproduksi 2 pcs scrunchie satin L pada tanggal 2/2/2026). Saat mencetak label QR, mereka ingin dapat mencetak label *hanya* untuk produk yang barusan ditambahkan hari itu, bukan seluruh stok berjalan (misal total stok saat ini 10 pcs).
* **Objektif:** Menambahkan filter rentang tanggal "Tanggal Update" (`updated date` menggunakan komponen `DateRangeField`) di halaman **Daftar Produk** (`ProdukListView`) dan **Generator QR** (`QRGeneratorView`). 
  * Di halaman **Daftar Produk**, filter ini akan membatasi tampilan hanya untuk produk yang memiliki penambahan stok dalam rentang tanggal tersebut, lengkap dengan rincian jumlah stok yang ditambahkan (misal: `+2 pcs masuk`).
  * Di halaman **Generator QR**, filter ini hanya menampilkan varian dengan penambahan stok dan secara otomatis mengisi jumlah cetak QR sesuai dengan jumlah stok baru yang masuk dalam rentang tanggal tersebut, bukan total stok saat ini.

## 2. Alur Pengguna & Spesifikasi UX

### A. Halaman Daftar Produk (`ProdukListView`)
1. **Titik Masuk (Entry Point):** Pengguna menekan tab "Produk". Di bawah kolom pencarian, ditambahkan komponen `DateRangeField` opsional (secara default bernilai non-aktif atau "Semua Waktu", atau pengguna dapat mengaktifkannya secara manual).
2. **Kondisi Aktif (Filter Menyala):**
   * Jika filter aktif (misal tanggal `1/2/2026` sampai `2/2/2026`), halaman akan memicu pemanggilan API `api.getStockLedger(from:to:)`.
   * Hanya produk-produk yang memiliki varian dengan penambahan stok (`changeQty > 0`) dalam periode tersebut yang ditampilkan di dalam daftar.
   * Di samping label ukuran (atau varian), selain menampilkan stok berjalan (misal `10 pcs`), ditampilkan indikator penambahan berwarna hijau yang sangat jelas: `+2 masuk`.
3. **Kondisi Non-Aktif (Filter Mati):**
   * Menampilkan semua produk dan stok berjalan seperti perilaku semula.

### B. Halaman Generator QR (`QRGeneratorView`)
1. **Titik Masuk (Entry Point):** Pengguna menekan ikon Generator QR di pojok kanan atas `ProdukListView`.
2. **Komponen UI Tambahan:** Ditambahkan `DateRangeField` di bawah kolom pencarian (di atas tombol "Pilih Semua").
3. **Perilaku Filter & Pra-Isi (Pre-fill Qty):**
   * Jika filter aktif:
     * Hanya menampilkan varian yang memiliki riwayat penambahan stok (`changeQty > 0`) pada periode tersebut.
     * Tombol "Pilih Semua" hanya memilih varian yang tersaring.
     * Saat ukuran dicentang/dipilih, nilai default jumlah label yang akan dicetak (`qtyPerSize[size.id]`) secara otomatis di-prefill menggunakan **jumlah stok yang baru masuk** dalam periode tersebut (misal `2` pcs), bukan total stok saat ini (`10` pcs).
     * Pengguna masih bisa menyesuaikan jumlah cetak tersebut menggunakan stepper plus/minus.
   * Jika filter mati:
     * Menampilkan semua varian aktif dan pra-isi jumlah cetak menggunakan total stok berjalan (atau default `max(1, currentStockQty)`) sesuai dengan perilaku saat ini.

## 3. Spesifikasi API & Perubahan Model

Untuk mengimplementasikan fitur ini dengan performa tinggi tanpa masalah N+1 queries, kita akan menerapkan **Opsi A** (penambahan endpoint `GET /stock-ledger`).

### A. Endpoint API Baru
* **Nama Endpoint:** `GET /stock-ledger`
* **Query Parameters:**
  * `from` (string, format `YYYY-MM-DD`): Tanggal mulai penyaringan.
  * `to` (string, format `YYYY-MM-DD`): Tanggal akhir penyaringan.
* **Tipe Respons:** `[StockAdjustmentLedgerEntry]`
* **Definisi Model di iOS (`ProductModels.swift`):**
  Menggunakan model `StockAdjustmentLedgerEntry` yang sudah ada:
  ```swift
  struct StockAdjustmentLedgerEntry: Codable {
      let id: UUID
      let productSizeId: UUID
      let changeQty: Int
      let reason: String
      let createdAt: Date

      enum CodingKeys: String, CodingKey {
          case id
          case productSizeId = "product_size_id"
          case changeQty = "change_qty"
          case reason
          case createdAt = "created_at"
      }
  }
  ```

### B. Penambahan di `APIService.swift`
Menambahkan fungsi pemanggilan HTTP GET untuk endpoint baru:
```swift
func getStockLedger(from: Date, to: Date) async throws -> [StockAdjustmentLedgerEntry] {
    if useMock { return try await MockAPIService.shared.getStockLedger(from: from, to: to) }
    let q = "?from=\(dateFmt.string(from: from))&to=\(dateFmt.string(from: to))"
    return try await get(path: "/stock-ledger\(q)")
}
```

### C. Penambahan di `MockAPIService.swift`
Untuk mendukung simulasi di frontend tanpa backend nyata, state dan data ledger disimulasikan:
* Menambahkan array list ledger mutable: `private var _ledgerEntries: [StockAdjustmentLedgerEntry] = []`
* Mengisi data benih (seed data) di `seedData()` dengan riwayat mutasi stok yang bervariasi (beberapa entri dibuat pada 1-2 hari yang lalu agar bisa difilter secara realistis).
* Mengimplementasikan fungsi `getStockLedger(from:to:)` di mock service:
  ```swift
  func getStockLedger(from: Date, to: Date) async throws -> [StockAdjustmentLedgerEntry] {
      await delay()
      let cal = Calendar.current
      let startOfDay = cal.startOfDay(for: from)
      let endOfDay = cal.startOfDay(for: cal.date(byAdding: .day, value: 1, to: to) ?? to)
      
      return _ledgerEntries.filter { entry in
          entry.createdAt >= startOfDay && entry.createdAt < endOfDay
      }
  }
  ```
* Memastikan setiap kali mutasi stok terjadi (seperti saat `adjustStock`, `addStockFromBahan`, `addStockManual`, dan konfirmasi batch produksi `confirmProductionBatch`), kita juga menambahkan entri ke `_ledgerEntries` secara realtime agar simulasi sinkronisasi data tetap 100% presisi.

## 4. Alur Integrasi & Logika Penyaringan Frontend

Saat filter tanggal aktif di `ProdukListView` atau `QRGeneratorView`:
1. Muat data produk dan ukuran dasar secara paralel: `api.getProducts()` dan `api.getAllProductSizes()`.
2. Jika filter aktif, panggil `api.getStockLedger(from:to:)`.
3. Filter dan kumpulkan entri ledger yang memiliki nilai `changeQty > 0` (hanya penambahan stok).
4. Buat kamus pemetaan (Map/Dictionary) dari `productSizeId` ke total kuantitas yang ditambahkan:
   ```swift
   // [UUID: Int] -> productSizeId ke total penambahan dalam rentang tanggal
   let additionsMap = Dictionary(grouping: ledgerEntries.filter { $0.changeQty > 0 }, by: { $0.productSizeId })
       .mapValues { entries in entries.reduce(0) { $0 + $1.changeQty } }
   ```
5. **Penyaringan Produk & Ukuran:**
   * Di `ProdukListView`: 
     * Hanya tampilkan varian ukuran (`ProductSizeDetail`) yang memiliki entri penambahan di `additionsMap` (atau tampilkan rincian di sampingnya). Jika tidak ada varian yang ditambahkan, seluruh baris grup produk induk disembunyikan.
     * Simpan status `additionsMap` ini di state view untuk merender label `+N masuk` pada sel ukuran.
   * Di `QRGeneratorView`:
     * Gunakan `additionsMap` untuk menyaring daftar varian ukuran yang tampil di bawah tiap produk.
     * Jika varian terpilih memiliki data penambahan, isi `qtyPerSize[size.id] = additionsMap[size.id] ?? 1`.

### 2. `ProdukListView.swift`
* Tambahkan `@State private var filterFrom: Date = Date()`
* Tambahkan `@State private var filterTo: Date = Date()`
* Tambahkan `@State private var isFilterActive: Bool = false`
* Tambahkan `@State private var additionsByVariant: [UUID: Int] = [:]`
* Tambahkan komponen `DateRangeField` tepat di bawah judul/summary statistik atau di atas list produk dengan toggle checkbox/switch bertuliskan "Filter berdasarkan Tanggal Masuk Stok".
* Perbarui fungsi `load()` agar jika `isFilterActive` bernilai true, sistem memanggil `getStockLedger(from: filterFrom, to: filterTo)` lalu mengisi `additionsByVariant`.
* Sesuaikan logic `filteredProducts` agar mematuhi aturan penyaringan tanggal jika `isFilterActive` bernilai true.

### 3. `QRGeneratorView.swift`
* Tambahkan state penyaringan yang sama dengan `ProdukListView`.
* Tambahkan komponen `DateRangeField` di bagian atas section.
* Sesuaikan `filteredSizes(for:)` untuk membatasi varian yang tampil hanya yang memiliki entri di `additionsMap` ketika filter menyala.
* Sesuaikan `onTapGesture` di mana saat ukuran dicentang, ia mengambil nilai kuantitas dari `additionsMap[size.id]` terlebih dahulu sebelum fallback ke total stok berjalan.
