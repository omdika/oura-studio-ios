# v2.5 — Hardware Purchase: Tambah Field Panjang (cm) Opsional
**Date:** 2026-08-07  
**Changed by:** Frontend (spec update)

---

## Summary

Spec change: hardware materials kini bisa memiliki BOTH `qty` (unit count) AND `length_cm` (panjang per unit). Sebelumnya hardware hanya bisa ditrack by piece count. Dengan penambahan ini, hardware yang dijual/diukur berdasarkan panjang — seperti karet elastis, pita, atau zipper tape — bisa di-track sisa panjangnya persis seperti kain.

**Tidak ada migrasi kolom yang diperlukan** — kolom `length_cm` dan `remaining_length_cm` sudah ada di tabel `material_purchase`. Yang berubah hanya constraint "fabric only" yang dicabut untuk hardware.

---

## 1. Motivasi

Contoh hardware yang perlu field Panjang:
- **Karet elastis 3mm** — dibeli per gulung 100cm, dikonsumsi per satuan panjang di setiap produk
- **Pita/ribbon** — dibeli per meter, dikonsumsi sedikit per produk
- **Zipper tape** — dibeli per meter, dipotong sesuai kebutuhan per produk

Hardware seperti ring D, klip, snap button tetap cukup dengan qty (unit count) saja.

---

## 2. Perubahan UI — TambahPembelianSheet: If Kategori = Hardware

### Sebelum (v2.4 dan sebelumnya)
```
Jumlah (pcs): [  ]
```

### Sesudah (v2.5)
```
Jumlah (pcs): [  ]
Panjang (cm): [  ]    ← opsional
```

**Behavior baru:**
- `Panjang (cm)` adalah opsional — hardware tanpa panjang (ring, klip) tetap valid
- Jika `Panjang` diisi: `canSave` tetap `qty > 0` saja (panjang boleh diisi meski qty masih kosong, tapi save tetap butuh qty)
- Jika kedua diisi: total length = `qty × length_cm`, backend inisialisasi `remaining_length_cm = qty × length_cm`
- Cost calculation saat `length_cm` hadir: `cost_per_cm = total_cost / (qty × length_cm)` — sama seperti kain

**Display di BahanDetailView (Riwayat Pembelian):**
- Hardware dengan `length_cm`: tampilkan seperti kain — "X gulung × 100 cm = 500 cm total, sisa: 380 cm"
- Hardware tanpa `length_cm`: tampilkan seperti sebelumnya — "3 pcs, sisa: 2 pcs"

**Display di Pergerakan Stok:**
- Hardware dengan `length_cm`: deduction entry menampilkan berapa cm yang dikonsumsi (bukan pcs)
- Hardware tanpa `length_cm`: deduction entry menampilkan pcs (behavior lama)

---

## 3. Perubahan DB Schema

Tabel `material_purchase` — perubahan komentar kolom (tidak ada migrasi DDL):

| Kolom | Sebelum | Sesudah |
|---|---|---|
| `length_cm` | fabric only ("Panjang (cm)") | fabric: panjang roll. **hardware (opsional):** panjang per unit untuk hardware yang dikonsumsi berdasarkan panjang |
| `qty` | thread/hardware only: jumlah gulung / pcs | thread/hardware: jumlah gulung / pcs. **hardware dengan `length_cm`:** qty × length_cm = total panjang |
| `remaining_length_cm` | decremented by CuttingLayouts (fabric only) | fabric: dikurangi oleh CuttingLayouts. **hardware dengan `length_cm`:** diinisialisasi = qty × length_cm, dikurangi saat dikonsumsi. null untuk hardware count-only dan thread/packaging |

---

## 4. Perubahan API Contract

### POST /materials/{id}/purchases

**Sebelum:**
```
-- hardware materials: qty required, width_cm/length_cm/package_label omitted
```

**Sesudah:**
```
-- hardware materials: qty required; length_cm optional (for length-tracked hardware like elastic bands)
--   if length_cm present: remaining_length_cm = qty × length_cm; cost_per_cm = total_cost / remaining_length_cm
--   if length_cm absent:  count-only; remaining_length_cm stays null
```

### PATCH /materials/{id}/purchases/{purchase_id}

Tambahan: hardware dengan `length_cm` yang sudah dikonsumsi (`remaining_length_cm < qty × length_cm`) juga masuk kategori "touched" — field `qty` dan `length_cm` harus ditolak (400) jika purchase sudah punya consumption, sama seperti kain.

---

## 5. Tidak Ada Perubahan Pada

- PatternSpec components (`qty_per_unit`) — tetap hitungan unit, bukan panjang
- Cutting optimizer — tetap fabric only, tidak relevan untuk hardware
- Frontend Swift models (`MaterialPurchase`, `CreatePurchaseRequest`, `PatchPurchaseRequest`) — sudah punya field `lengthCm: Double?` dan `widthCm: Double?` sebagai optional, tidak perlu perubahan
- Konsumsi hardware dalam produksi — sudah ada `remaining_length_cm` path di backend; hanya perlu di-enable untuk hardware
