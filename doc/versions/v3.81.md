# Version 3.81 - Pisah API Statistik + Pagination List Produk + Server-Side Search

## 1. Problem / Opportunity
*   **Context:** `ProdukListView` saat ini menghitung Total Produk, Total Varian, Total Stok, Nilai Modal, dan Potensi Omset secara **client-side** dari data yang sudah di-load (halaman 1 + subset pencarian). Saat user mencari produk, frontend memuat **semua halaman** backend (`fetchAllProducts()`, max 50 halaman) baru lalu filter client-side — user harus menunggu lama sebelum list dan statistik muncul. Statistik juga hanya akurat untuk subset yang sudah dimuat, bukan total sebenarnya di backend.
*   **Objective:** Statistik ringkasan (total produk, stok, nilai modal, potensi omset) dipisah ke endpoint statistik sendiri yang di-load segera bersama halaman pertama; list produk tetap dipaginasi (scroll-load) agar tidak load semua sekaligus; pencarian dilakukan server-side via parameter `?search=` agar cepat tanpa load semua data.

## 2. User Flow & UX Specifications
*   **Entry Point:** Tab Produk → `ProdukListView`.
*   **UI Components:** Stat cards (Total Produk, Total Varian, Total Stok, Stok Kosong) + banner Nilai Modal / Potensi Omset (sudah ada, v3.60); daftar grup produk dengan pagination trigger pada 5 baris terakhir (sudah ada, v3.67); search field di header.
*   **Validation Rules:**
    *   Statistik selalu mencerminkan **semua** produk non-archived di backend, tidak hanya subset yang sudah di-load.
    *   List produk ditampilkan halaman per halaman (default limit 20), `loadMoreProducts()` saat mendekati akhir.
    *   User tidak perlu menunggu semua produk selesai load untuk melihat statistik atau baris pertama.
*   **State & Progressive Disclosure:** Statistik dan halaman 1 dimuat secara parallel saat view muncul; tampilan statistik tidak diblokir oleh pemuatan list. Error transient pada salah satu tidak menghapus cache yang sudah tampil.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada tabel baru. Endpoint statistik adalah read-only aggregation dari tabel existing (`products`, `product_sizes`).
*   **New / Modified Columns:** Tidak ada. Nol migrasi.

## 4. API Contract (FastAPI)
*   **Endpoints:**
    *   `GET /products/stats`
        *   **Response Body:**
            ```json
            {
              "total_produk": 88,
              "total_varian": 473,
              "total_stok": 412,
              "stok_kosong": 259,
              "nilai_modal": 6455822.0,
              "potensi_omset": 6512192.0
            }
            ```
        *   **Aggregasi server-side:** count produk non-archived, count varian non-archived, sum `current_stock_qty`, count varian stok==0, sum `stok × HPP efektif` (fallback harga jual), sum `stok × harga jual`.
    *   `GET /products?page=&limit=&search=`
        *   **Perubahan:** tambahkan query parameter `search` (opsional). Backend melakukan pencarian nama/SKU server-side; frontend **tidak perlu** load-all-then-filter lagi.
        *   **Response:** `PaginatedResponse<Product>` (sudah ada).
*   **Validation & Errors:** `stats` gagal → error 500, frontend menampilkan cache lama / placeholder dan tidak crash.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService (`Networking/Models/ProductModels.swift`, `Networking/APIService.swift`):**
    *   Tambah struct `ProductStats: Codable` dengan field `totalProduk`, `totalVarian`, `totalStok`, `stokKosong`, `nilaiModal`, `potensiOmset` (snake_case coding keys).
    *   Tambah `func getProductStats() async throws -> ProductStats` → `GET /products/stats`.
    *   Ubah `getProducts(page:limit:)` → `getProducts(page:limit:search:)` tambah parameter `search: String? = nil`, sirkan ke query URL `?search=`.
*   **Views & Controllers (`Screens/Produk/ProdukListView.swift`):**
    *   Ganti perhitungan `totalProductsCount`, `totalVarianCount`, `totalStockQty`, `outOfStockCount`, `stockValuation` dari client-side → diambil dari `ProductStats` API.
    *   Saat view muncul: panggil `getProductStats()` dan `getProducts(page: 1, limit: 20, search: searchText)` secara **parallel** (`async let` / `TaskGroup`).
    *   Statistik tampil segera saat `getProductStats()` selesai (tidak menunggu list).
    *   List produk tampil halaman per halaman; `loadMoreProducts()` saat 5 baris terakhir tampil (pertahankan pola v3.67).
    *   Saat search aktif: gunakan parameter `?search=` ke backend, **hapus** jalur `fetchAllProducts()` load-all-then-filter client-side.
    *   Filter tanggal (`isFilterActive`) tetap menggunakan jalur load-all saat ini (kecuali diumumkan lain), karena agregasi stok berdasarkan rentang tanggal lebih kompleks.
    *   `MockAPIService`: tambah mock `getProductStats()` dan update `getProducts(page:limit:search:)`.
*   **Files to create or edit:**
    *   Edit: `Networking/Models/ProductModels.swift` (tambah `ProductStats`)
    *   Edit: `Networking/APIService.swift` (tambah `getProductStats()`, ubah signature `getProducts`)
    *   Edit: `Networking/MockAPIService.swift` (mock stats + search)
    *   Edit: `Screens/Produk/ProdukListView.swift` (load parallel, stats dari API, search via backend)

## 6. Verification & Test Plan
*   **Smoke Test:** `xcodebuild` sukses; buka tab Produk → statistik (Total Produk, Nilai Modal, Potensi Omset) muncul instan bersama baris pertama list; scroll ke bawah → `loadMoreProducts` memuat halaman berikutnya tanpa duplikasi.
*   **Sanity Test Scenarios:**
    1. Statistik angka sama dengan data backend (total 88 produk, 412 pcs, nilai Rp6.455.822, omset Rp6.512.192) dan tidak berubah meski baru halaman 1 dimuat.
    2. Ketik kata kunci search → backend menerima `?search=`, list menyaring tanpa memuat semua halaman (tidak ada jeda lama).
    3. Pull-to-refresh → statistik dan halaman 1 dimuat ulang parallel; data lama tidak dihapus saat error transient.
    4. Tambah produk/varian baru di detail → kembali ke list, statistik ter-update melalui `requestReload()` + `getProductStats()`.
*   **Regression:** Pastikan filter tanggal masuk stok masih jalan (jalur load-all untuk filter tetap utuh); pastikan cover list dan fallback gallery tetap 0 request (v3.66).
