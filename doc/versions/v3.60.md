# Version 3.60 - Total Nilai Stok di Halaman Produk

## 1. Problem / Opportunity
*   **Context:** Halaman Produk (`ProdukListView`) saat ini hanya menampilkan 3 card ringkasan: Total Produk, Total Stok (pcs), Stok Kosong (varian). Pemilik tidak bisa melihat **nilai modal yang terikat di stok** maupun **potensi omset** tanpa menghitung manual per varian (lihat screenshot: 257 pcs tanpa valuasi rupiah).
*   **Objective:** Menambahkan banner ringkasan **Total Nilai Stok** (Nilai Modal berbasis HPP + Potensi Omset berbasis harga jual) yang menghormati search & filter tanggal yang aktif, murni frontend-only tanpa perubahan backend.

## 2. User Flow & UX Specifications
*   **Entry Point:** Buka tab Produk (`ProdukListView`) — tidak ada navigasi baru. Banner muncul otomatis di dalam `ScrollView` (`productList`), tepat di bawah `summaryHeaderView` (3 card existing) dan di atas `dateFilterSection`.
*   **UI Components:**
    *   Container: `.ouraCard()` full-width, `padding(OuraTheme.Spacing.cardPad)`, reuse pola `SalesSummaryHeader`/`SummaryTile` (v3.54) tapi 2 kolom.
    *   Kolom kiri — "Nilai Modal" (icon `banknote.fill`, `OuraTheme.Colors.accent`): `totalModal.rupiahFormatted`.
    *   Kolom kanan — "Potensi Omset" (icon `tag.fill`, `OuraTheme.Colors.blueAccent`): `totalOmset.rupiahFormatted`.
    *   Footnote (conditional, font 10, `textTertiary`, max 2 baris): `"*N varian pakai harga jual sbg modal"` bila `fallbackModalCount > 0`; `"M varian tanpa harga tak terhitung"` bila `unpricedCount > 0`. Sembunyikan footnote bila keduanya 0.
    *   `lineLimit(1)` + `.minimumScaleFactor(0.7)` pada kedua angka (nilai bisa > Rp100jt, cegah truncate seperti `statCard` existing).
*   **Validation Rules (`canSave`):** N/A (read-only summary, tidak ada aksi simpan).
*   **State & Progressive Disclosure:**
    *   Loading: banner ikut `isLoading && products.isEmpty` → tidak render (tertutup spinner existing).
    *   Empty: bila `filteredProductsToDisplay.isEmpty`, banner disembunyikan (ikut blok empty/search-not-found).
    *   Scope perhitungan: dari **varian yang tampil** — yaitu `allSizes` yang lolos `isArchived == false` + filter tanggal (`additionsByVariant[s.id] != nil` bila `isFilterActive`) + filter search (hanya size milik produk dalam `filtered`). Sama seperti `totalStockQty`/`outOfStockCount` hari ini (cache ter-load, bukan agregat server global — konsisten dengan batasan pagination v3.56).

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak ada perubahan. Gunakan properti existing di `ProductModels.swift`:
    *   `ProductSizeDetail.currentStockQty: Int`
    *   `ProductSizeDetail.effectiveHppBreakdown: HPPBreakdown?` (= `latestHppBreakdown ?? manualHppBreakdown`)
    *   `ProductSizeDetail.sellingPrice: Double?`
*   **Views & Controllers:** Satu file — `oura studio frontend/Screens/Produk/ProdukListView.swift`:
    1.  Tambah computed properties (sejajar `totalStockQty`, baris ~76-82):
        ```swift
        private var visibleSizesForValuation: [ProductSizeDetail] {
            let ids = Set(filteredProductsToDisplay.map(\.id))
            return allSizes.filter { s in
                !s.isArchived && ids.contains(s.productId)
                && (!isFilterActive || additionsByVariant[s.id] != nil)
            }
        }
        private var stockValuation: (modal: Double, omset: Double, fallbackModal: Int, unpriced: Int) {
            visibleSizesForValuation.reduce((0, 0, 0, 0)) { acc, s in
                let qty = Double(s.currentStockQty)
                guard qty > 0 else { return acc }
                let hpp = s.effectiveHppBreakdown?.total
                let price = s.sellingPrice
                let unitModal = hpp ?? price ?? 0
                let unitOmset = price ?? 0
                return (acc.0 + qty * unitModal,
                        acc.1 + qty * unitOmset,
                        acc.2 + ((hpp == nil && price != nil) ? 1 : 0),
                        acc.3 + ((hpp == nil && price == nil) ? 1 : 0))
            }
        }
        ```
        *Catatan: `unitModal = effectiveHPP ?? sellingPrice ?? 0` sesuai keputusan user ("tampilin sesuai harga jual" bila tanpa HPP). `unitOmset = sellingPrice ?? 0`.*
    2.  Tambah `private var stockValueBanner: some View` (banner 2 kolom + footnote conditional, `.ouraCard()`).
    3.  Sisipkan `stockValueBanner` di `productList` antara `summaryHeaderView` dan `dateFilterSection` (baris ~363-366).
    4.  Tidak menyentuh `statCard`, `ProductGroupRow`, pagination, atau `MockAPIService` (mock sudah punya `latestHppBreakdown` + stok; banner otomatis terisi di mock).

## 6. Verification & Test Plan
*   **Smoke Test:** Build sukses; tab Produk tampil tanpa crash; banner muncul di bawah 3 card; pull-to-refresh tidak menghilangkan banner.
*   **Sanity Test Scenarios:**
    1.  **Hitungan manual:** seed 2 varian — A: stok 5 × HPP Rp10.000 + harga Rp15.000; B: stok 3 × tanpa HPP + harga Rp20.000. Harapan: Nilai Modal = 5×10rb + 3×20rb = Rp110.000; Potensi Omset = 5×15rb + 3×20rb = Rp135.000; footnote `"*1 varian pakai harga jual sbg modal"`.
    2.  **Varian tanpa harga & HPP:** stok 2, HPP nil, harga nil → kontribusi Rp0 ke keduanya, `unpriced = 1`, footnote `"1 varian tanpa harga tak terhitung"`.
    3.  **Search scope:** ketik nama produk A → banner hanya hitung varian A (angka mengecil).
    4.  **Filter tanggal:** aktifkan "Filter berdasarkan Tanggal Masuk Stok" dengan range tanpa mutasi → `visibleSizesForValuation` kosong → banner Rp0/Rp0 (tidak crash).
    5.  **Stok 0:** varian stok 0 tidak berkontribusi walau punya HPP/harga.
