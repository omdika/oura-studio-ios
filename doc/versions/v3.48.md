# Version 3.48 - Otomatisasi Security Test BOLA (API1:2023)

## 1. Masalah / Peluang
* **Konteks:** Broken Object Level Authorization (BOLA) adalah salah satu kerentanan keamanan tertinggi dalam OWASP API Security Top 10 (2023). Pada Oura Studio, penyerang dapat memanipulasi UUID objek di path parameter request (seperti `material_id`, `purchase_id`, `sizeId`, `batch_id`, atau `sales_order_id`) untuk memodifikasi atau membaca data milik owner sah.
* **Objektif:** Mengimplementasikan rangkaian pengujian keamanan otomatis (*automated security test suite*) berbasis `XCTest` pada lapisan integrasi iOS client untuk memproteksi 4 modul kritis (Materials, Products/Sizes, Production, Sales) dari potensi kebocoran otorisasi BOLA.
* **Constraint:** Rangkaian pengujian harus tangguh, mendeteksi kegagalan secara akurat (*strict validation*), dan dilarang keras meloloskan pengujian secara diam-diam (*silent-pass/bypass*) menggunakan fallback mock jika kredensial/variabel lingkungan tidak lengkap.

## 2. Strategi Pengujian & Prinsip "Fail Loudly"

Untuk memastikan keandalan suite pengujian, kami menerapkan prinsip rekayasa pengujian ketat berikut:
1. **Prinsip Fail Loudly (Gagal Nyaring):** Jika variabel lingkungan (`JWT_OWNER` dan `JWT_ATTACKER`) tidak disetel atau disabotase di skema Xcode, pengujian akan langsung digagalkan secara eksplisit menggunakan `XCTFail()` di fase setup (`setUpWithError`), alih-alih melewatinya secara diam-diam.
2. **Koneksi Keychain Simulator:** Untuk memudahkan eksekusi tes lokal di simulator Xcode tanpa harus menyetel env vars secara manual, tes secara cerdas akan jatuh (*fallback*) membaca token login aktif langsung dari `KeychainManager.loadToken()`.
3. **Pencarian ID Dinamis (Dynamic ID Discovery):** Untuk mencegah kegagalan tes berupa error `404 Not Found` akibat UUID dummy yang tidak ada di database live, pengujian akan secara dinamis memanggil endpoint list (seperti `GET /materials`) untuk mendeteksi ID material asli pertama yang ada di database Supabase untuk dipakai sebagai target uji.

## 3. Rincian Implementasi Kode Pengujian

Rangkaian pengujian ditulis di dalam target unit test `oura studio frontendTests` di bawah grup baru bernama `Security` (`oura studio frontendTests/Security/`):

### A. Modul A — Bahan & Pembelian (`TC_BOLA_A1_Materials.swift`)
* **Kasus Uji A.1.1 (GET - Owner Sah):** Menguji akses sah owner ke detail material, ekspektasi `200 OK`.
* **Kasus Uji A.1.2 (GET - Attacker BOLA):** Menguji manipulasi attacker ke detail material, ekspektasi `403 Forbidden` atau `404 Not Found`.
* **Kasus Uji A.1.3 (GET - Unauthenticated):** Menguji request tanpa token, ekspektasi `401 Unauthorized`.
* **Kasus Uji A.2.1 (PATCH - Owner Sah):** Menguji perubahan nama material oleh owner, ekspektasi `200 OK` atau `204 No Content`.
* **Kasus Uji A.2.2 (PATCH - Attacker BOLA):** Menguji perubahan nama material oleh attacker, ekspektasi `403 Forbidden`.
* **Kasus Uji A.3.1 (PATCH Purchase - Owner Sah):** Menguji perubahan biaya pembelian material oleh owner, ekspektasi `200 OK`.
* **Kasus Uji A.3.2 (PATCH Purchase - Attacker BOLA):** Menguji perubahan biaya pembelian material oleh attacker, ekspektasi `403 Forbidden`.

### B. Modul B — Produk & Ukuran (`TC_BOLA_B1_Products.swift`)
* **Kasus Uji B.1.1 (GET Size - Owner Sah):** Menguji akses detail ukuran produk oleh owner, ekspektasi `200 OK`.
* **Kasus Uji B.1.2 (GET Size - Attacker BOLA):** Menguji akses detail ukuran produk oleh attacker, ekspektasi `403 Forbidden`.
* **Kasus Uji B.2.1 (PATCH Size - Owner Sah):** Menguji pembaruan harga jual oleh owner, ekspektasi `200/204`.
* **Kasus Uji B.2.2 (PATCH Size - Attacker BOLA):** Menguji pembaruan harga jual oleh attacker, ekspektasi `403 Forbidden`.

### C. Modul C — Konfirmasi Produksi (`TC_BOLA_C1_Production.swift`)
* **Kasus Uji C.1.1 (POST Confirm - Owner Sah):** Menguji konfirmasi batch produksi draf oleh owner, ekspektasi `200 OK`.
* **Kasus Uji C.1.2 (POST Confirm - Attacker BOLA):** Menguji konfirmasi batch produksi draf oleh attacker, ekspektasi `403 Forbidden`.

### D. Modul D — Pembatalan Penjualan (`TC_BOLA_D1_Sales.swift`)
* **Kasus Uji D.1.1 (POST Cancel - Owner Sah):** Menguji pembatalan nota penjualan paid oleh owner, ekspektasi `200 OK`.
* **Kasus Uji D.1.2 (POST Cancel - Attacker BOLA):** Menguji pembatalan nota penjualan paid oleh attacker, ekspektasi `403 Forbidden`.
