# v3.2 — Tambah Item ke Batch Produksi Manual (2026-08-10)

**Changed by:** Frontend (plan only — tidak ada perubahan kode)  
**Sections affected:** Section 2 (Tab Produksi → Produksi), Section 4 (Production API)

---

## Latar Belakang

`createManualBatch()` membuat `production_batch` kosong (tanpa `cutting_layout_id`). Card tampil sebagai
"Batch Kosong · 0 pola" karena `batch.items` selalu kosong. Tidak ada endpoint maupun UI untuk menambah
item ke batch yang sudah dibuat. User tidak bisa menggunakan manual batch untuk apapun yang berarti —
batch hanya bisa dikonfirmasi (dengan item kosong, menghasilkan HPP yang salah) atau dihapus.

Fitur ini menutup gap tersebut dengan menambahkan:
1. Tombol **"+ Tambah Item"** di `BatchCard` untuk batch manual yang masih draft.
2. Sheet **`TambahItemBatchSheet`** — memilih product_size + qty, bisa multi-item sebelum simpan.
3. Swipe-to-delete item dari batch yang masih draft.

## UX Flow

### Entry point

`BatchCard` menampilkan tombol **"+ Tambah Item"** di bagian bawah card jika dan hanya jika:
- `batch.isDraft == true`
- `batch.cuttingLayoutId == nil` (batch manual, bukan dari optimizer)

Tombol ini muncul **di bawah** daftar item yang sudah ada (jika ada), sehingga user bisa menambah item
bertahap dalam beberapa sesi berbeda.

### TambahItemBatchSheet

**Presentasi:** bottom sheet standar. Header: "Tambah Item ke Batch" + tombol "×" (dismiss tanpa simpan).

**Konten:**

Sheet menampilkan satu atau lebih **item row**. Setiap row terdiri dari:

| Field | Komponen | Keterangan |
|---|---|---|
| Produk & Ukuran | `InlineSearchDropdownField` | Menampilkan `{productName} · {displayLabel}` + badge stok. Hanya tampilkan `ProductSize` yang tidak diarsipkan. Ukuran yang sudah ada di batch (items sebelumnya) boleh dipilih lagi (produksi tambahan). |
| Jumlah | `NumericInputField` | Integer ≥ 1. Label: "Jumlah (pcs)". |
| Hapus baris | Ikon trash kecil (×) | Hanya muncul jika ada lebih dari 1 baris. Menghapus baris tersebut dari state sheet — bukan API call. |

**Tombol "Tambah Baris":** menambah item row baru (kosong) di bawah baris yang sudah ada. Maksimum tidak
dibatasi, tapi validasi per-baris tetap berlaku.

**Tombol "Simpan" (primary, pinned di bottom):**
- Disabled jika ada baris yang belum lengkap (product_size belum dipilih atau qty = 0).
- Tap → loading state → kirim `POST /production-batches/{id}/items` untuk **setiap baris** secara
  berurutan (bukan paralel — respons tiap item dikembalikan satu per satu).
- Jika semua berhasil: dismiss sheet, `BatchCard` reload (tampilkan item baru).
- Jika ada yang gagal: sheet tetap terbuka, baris yang gagal ditandai dengan inline error (merah),
  baris yang berhasil ditandai confirmed. User bisa retry baris yang gagal saja.

### Hapus item dari BatchCard

- Gesture swipe-left pada setiap item row di `BatchCard`, hanya jika `batch.isDraft`.
- Muncul tombol "Hapus" (merah). Tap → konfirmasi singkat ("Hapus item ini dari batch?") → kirim
  `DELETE /production-batches/{id}/items/{item_id}`.
- Setelah berhasil: item hilang dari card in-place (tidak perlu reload seluruh list batch).
- Swipe-delete **tidak muncul** jika `batch.isConfirmed` — item di batch yang sudah dikonfirmasi
  adalah history yang tidak boleh diedit.

## Keputusan Desain

**Multi-item dalam satu sheet, bukan satu per satu dialog.** Penggunaan nyata: owner selesai potong
manual 3 produk sekaligus. Membuka sheet 3× lebih lambat dari menambah 3 baris sekaligus dalam 1 sheet.

**Sequential POST, bukan batch endpoint.** Menghindari kebutuhan API baru yang lebih kompleks. Jika
salah satu gagal, user tahu persis baris mana yang bermasalah.

**Hanya batch manual (no cutting_layout_id) yang bisa tambah item via sheet ini.** Batch dari optimizer
sudah punya items dari `cutting_layout_item` — menambah item di luar itu akan membuat fabric cost per
piece tidak konsisten (item manual tidak punya `cutting_layout_item.cost_per_piece`). Untuk batch
optimizer, user cukup edit `qty_actual` yang sudah ada.

**`pattern_spec_id` di item manual = active spec untuk product_size itu, atau null jika belum ada.**
Diperlukan untuk HPP labor dan hardware saat confirm. Backend mencari spec terbaru yang aktif; jika
tidak ada, item tidak bisa dikonfirmasi sampai resep dibuat terlebih dahulu.
