# Version 3.67 - Fix List Produk Macet di 40 (Pagination Stall) + Cover List Mati

## 1. Problem / Opportunity
*   **Context:** Tab Produk berhenti di 40 produk (tepat 2 halaman × limit 20) — halaman 3+ tidak pernah ke-load. Terakhir normal di commit `2184526`; regresi masuk lewat v3.66 (`fdb3f5e`).
*   **DB aktual:** 77 produk aktif / 434 varian (zwakili via API live) — header "Total Produk 40" adalah count yang ke-load, bukan total DB.
*   **Objective:** Kembalikan infinite scroll sampai semua 77 produk ke-load, tanpa menghidupkan lagi burst paralel yang dibunuh v3.66.

## 2. Root Cause (hasil investigasi, terverifikasi)
1.  **Pagination stall (utama):** `loadMoreProducts` v3.66 me-`append` produk BARU ke `products` **sebelum** `await fetchAllSizesBulk()` (~2–4 dtk, 249 KB). Append langsung menggeser `filtered.last` ke baris baru; user yang scroll cepat sampai bawah selama window itu menghanguskan `onAppear` satu-kali baris terakhir karena guard `!isLoadingMore`. Setelah bulk selesai tidak ada yang me-refire trigger → macet permanen di 40. Di `2184526` sizes di-fetch DULU baru append atomik, jadi baris terakhir selalu fresh. Backend, payload, dan decoding halaman 3/4 verified sehat (200 OK, `next_page` chain benar, decode OK via `swiftc` test harness).
2.  **Cover list mati total:** `Product.coverImageURL` dideklarasikan `let ... : String? = nil`. Swift **me-skip `let`-with-default** di synthesized `Decodable` — terbukti via `swiftc` test: payload berisi URL pun decode jadi `nil` (live: 2 cover → 0). Akibatnya SEMUA kartu jatuh ke fallback fetch galeri per-kartu (burst yang mau dibunuh v3.66), hanya diredam limiter 3-konkuren. Fix: `var` (test: present→value, null→nil, missing→nil, semua OK).
3.  **Laten:** `isLoadingMore` tidak di-reset pada dua early-return `Task.isCancelled` (leak flag → guard `loadMore` macet).

## 3. User Flow & UX Specifications
*   Tidak ada perubahan visual. Scroll bawah → halaman berikut ke-load dengan kartu langsung terisi varian (tidak ada flash kartu kosong), sampai 77 produk.
*   Cover kartu yang punya foto langsung tampil dari list (0 request); produk tanpa foto → 1 fetch galeri bounded (limiter 3, seperti 2184526) lalu placeholder.

## 4. Database Schema Changes
*   NONE (frontend-only).

## 5. API Contract
*   Tidak ada endpoint baru/berubah. Pola panggil tetap v3.66 (1 products + 1 bulk sizes sequential per halaman, fallback galeri bounded), hanya urutan publish diperbaiki.

## 6. Frontend Changes
*   `Networking/Models/ProductModels.swift` — `Product.coverImageURL`: `let` → `var` (+ komentar kenapa `let` dilarang di sini).
*   `Screens/Produk/ProdukListView.swift`:
    *   `loadMoreProducts`: fetch bulk DULU untuk produk baru, lalu `append` produk + varian + state halaman secara atomik (kembalikan semantik 2184526). `defer { isLoadingMore = false }`. Lewati replace `allSizes` saat bulk gagal (`[]`) agar error transient tidak mengosongkan semua kartu.
    *   `loadFirstPage` (non-filter): assign `products` + `allSizes` bersamaan SETELAH bulk; guard yang sama anti-wipe.
    *   Trigger infinite scroll: prefetch saat 5 baris terakhir tampil (threshold), bukan hanya baris terakhir persis — trigger satu-kali yang terkonsumsi tidak lagi bisa memacetkan list.
*   Layar lain tidak disentuh.
