# Version 3.73 - Default Harga Jual Varian Scrunchie Saat Edit (Hardcoded Placeholder)

## 1. Problem / Opportunity
*   **Context:** Produk bertipe **scrunchie** dibuat dengan size XS–XXL, dan tiap variannya awalnya tanpa harga (`selling_price = nil` / Rp 0). Mengedit tiap varian satu per satu lalu mengetik nominal harga yang sama berulang kali itu melelahkan dan rawan lupa.
*   **Objective:** Saat masuk mode **Edit** di layar detail varian (`ProdukSizeDetailView`), apabila harga jual varian masih kosong/0 **dan** kategori produk adalah `scrunchie`, field "Harga Jual" otomatis terisi harga default per size sehingga **siap langsung disimpan** tanpa mengetik ulang. Frontend-only, nilai default di-hardcode dulu.

## 2. User Flow & UX Specifications
*   **Entry Point:** Level 3 `ProdukSizeDetailView` (dari `ProdukDetailView` saat tap varian, juga dari `ProdukListView`/`BerandaView`/`ReportsView`/`QRScannerSheet`) → tombol **"Edit"**.
*   **Flow yang disepakati:**
    1. User membuka detail varian scrunchie (harga masih Rp 0).
    2. Tap **Edit** → `startEdit()` dijalankan.
    3. Jika `selling_price` varian **nil atau 0**, kategori produk = `"scrunchie"`, dan `size_label` ada di map default → field **Harga Jual** langsung terisi nilai default (contoh: `L` → **Rp 18.000**).
    4. User dapat langsung tap **Simpan** (nilai default ikut tersimpan lewat PATCH existing) atau mengubahnya lebih dulu.
    5. Jika harga sudah > 0 → **tidak ditimpa**.
    6. Jika kategori bukan scrunchie, atau `size_label` di luar map (mis. ukuran kustom) → perilaku tetap seperti sekarang (field apa adanya).
*   **Default map (hardcoded):**

    | Size | Harga Default |
    |---|---|
    | XS | 10.000 |
    | S | 12.000 |
    | M | 15.000 |
    | L | 18.000 |
    | XL | 23.000 |
    | XXL | 30.000 |

    Pencocokan `size_label` **case-insensitive** + trim spasi.
*   **UI Components:** `CurrencyInputField` (existing, `Components/CurrencyInputField.swift`). Tidak ada komponen baru.
*   **Validation Rules (`canSave`):** Tidak berubah — toolbar "Simpan" tetap aktif saat mode Edit; nilai default sudah valid untuk disimpan.
*   **State & Progressive Disclosure:** Nilai `editSellingPrice` ditentukan di `startEdit()`. `CurrencyInputField` mengisi tampilan dari binding saat field muncul (`onAppear`), sehingga nilai default langsung terlihat tanpa interaksi tambahan.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Nihil — murni frontend.
*   **New / Modified Columns:** Nihil. Kolom `product_size.selling_price` dan endpoint PATCH sudah ada.

## 4. API Contract (FastAPI)
*   **Endpoints (reuse, tanpa perubahan backend):**
    *   `PATCH /api/v1/products/{sku}/sizes/{sizeId}`
        *   **Body:** `{ selling_price?, reorder_min_qty?, manual_hpp_*?, adjust_stock_by?, adjust_stock_reason? }` (kontrak existing `PatchProductSizeRequest`).
        *   **Peran:** menyimpan nilai default hasil prefill.
        *   **Validation & Errors:** kontrak existing (401 auth, 4xx validasi) — tidak berubah.
    *   `GET /api/v1/products` (via `APIService.getProducts()`)
        *   **Peran:** fallback resolve kategori produk by SKU saat caller tidak mengoper kategori.
*   **Catatan penting:** kontrak `GET /products/{sku}/sizes` **tidak** mengembalikan `product_category`. Karena itu kategori diperoleh dari pass-through (`Product.category`) atau lookup produk — bukan dari payload size. Tanpa backend baru.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:**
    *   Handler hardcoded baru `ScrunchieDefaultPrice` (taruh di `Networking/Models/ProductModels.swift`, atau file kecil baru `Networking/Models/ScrunchieDefaultPrice.swift`):
        *   `static let bySize: [String: Double]` = map pada Bagian 2.
        *   `static func defaultPrice(forSizeLabel label: String) -> Double?` → trim + uppercased + lookup (return `nil` bila tak ada).
    *   `Networking/APIService.swift`: tambah `func resolveProductCategory(sku: String) async -> String?` — samakan pola `resolveProductName(sku:)` (reuse `getProducts()`, cari `sku`, return `category`).
*   **Views & Controllers (tepat apa yang diubah):**
    *   `Screens/Produk/ProdukDetailView.swift` → `ProdukSizeDetailView`
        *   Tambah property `let productCategory: String?`; ubah `init(productSize:productCategory:)` (default `nil`).
        *   Tambah state untuk kategori ter-resolve (mis. `@State private var resolvedCategory: String?`, di-seed dari param init).
        *   `.task` (baris ~1611): jalankan resolve kategori (mis. `async let c = ...`) bila param `nil`, set `resolvedCategory`.
        *   `startEdit()` (baris ~2229): ganti baris pertama menjadi:
            ```swift
            let current = size.sellingPrice ?? 0
            if current == 0,
               resolvedCategory?.lowercased() == "scrunchie",
               let def = ScrunchieDefaultPrice.defaultPrice(forSizeLabel: size.sizeLabel) {
                editSellingPrice = def
            } else {
                editSellingPrice = size.sellingPrice
            }
            ```
        *   Tidak ada perubahan pada `saveEdits()` — `editSellingPrice` sudah dikirim lewat `PatchProductSizeRequest(sellingPrice:)`.
    *   **Call sites** (pass kategori bila tersedia; sisanya biarkan `nil` agar auto-resolve):
        *   `ProdukDetailView.swift:1030` (`ProdukSizeGroupView`) → `ProdukSizeDetailView(productSize: variant, productCategory: product.category)`.
        *   `ProdukListView.swift:235`, `BerandaView.swift:104`, `ReportsView.swift:784`, `QRScannerSheet.swift:464` → tidak diubah (auto-resolve).
*   **Alternatif yang ditolak:**
    *   Menambah `product_category` ke payload size → butuh perubahan backend (di luar scope).
    *   Menerapkan default hanya berdasarkan `size_label` tanpa cek kategori → salah untuk produk non-scrunchie yang juga memakai size XS–XXL.

## 6. Verification & Test Plan
*   **Smoke Test:** Build sukses (`xcodebuild`); buka detail varian scrunchie & non-scrunchie tanpa crash; toolbar Edit/Simpan tetap berfungsi.
*   **Sanity Test Scenarios:**
    1. Scrunchie, varian dengan `selling_price` nil/0 (mis. size L) → tap Edit → field Harga Jual terisi **Rp 18.000** → Simpan → GET detail `selling_price == 18000`.
    2. Scrunchie, varian dengan harga existing (mis. 25.000) → Edit → field **tetap 25.000** (tidak ditimpa).
    3. Produk non-scrunchie (mis. Pouch), size L harga kosong → Edit → field **tetap Rp 0** (tidak ada default).
    4. Scrunchie ukuran kustom di luar map (mis. "XL-Long") → Edit → field tetap kosong.
    5. Masuk dari pintu selain `ProdukDetailView` (QR/Beranda/Laporan) pada scrunchie → default tetap muncul (membuktikan fallback resolve kategori bekerja).
    6. Isi manual lalu ganti size lain → default hanya muncul saat harga benar-benar kosong/0.
*   **Mock note:** `MockAPIService` sudah punya produk `SCRUNCHIE` kategori `"scrunchie"`. Untuk menguji default, gunakan/ciptakan varian dengan `selling_price = nil`.
