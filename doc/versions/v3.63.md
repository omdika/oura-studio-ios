# Version 3.63 - Opsi Diskon × Qty di Catat Penjualan (Default Flat)

## 1. Problem / Opportunity
*   **Context:** Saat ini field `Diskon` di `TambahPenjualanSheet` selalu dihitung per-pcs: `lineTotal = (unitPrice - discount) * qty`. Contoh screenshot: Qty 2 × Rp25.000 − Diskon Rp2.000 menghasilkan Rp46.000. Owner menghendaki opsi: diskon kadang flat per baris (tidak dikali qty) → hasil yang diharapkan Rp48.000 (`25.000*2 - 2.000`).
*   **Objective:** Tambahkan opsi per-item `× Qty` (default OFF = flat/tidak dikali qty) di semua alur jual, frontend-only tanpa perubahan backend/API.

## 2. User Flow & UX Specifications
*   **Entry Point:** `TambahPenjualanSheet` → kartu tiap item di Section "Produk Dijual" (di bawah field `Diskon`); juga `ScanToSellSheet` → Section "Detail Penjualan" (di bawah field `Diskon`). `QRScannerSheet` tidak berubah (qty selalu 1 saat auto-add, kedua rumus identik).
*   **UI Components (reuse standard):**
    *   `CurrencyInputField(label: "Diskon")` tetap (input = nilai nominal Rupiah seperti yang diketik user).
    *   Tambah kontrol kecil di bawah/kanan field Diskon per item: `Toggle("× Qty")` compact (font 12) + hint subtotal live. Default `isPerQty = false`.
    *   Teks subtotal live per baris (font 12, secondary): flat → `"Subtotal: Rp48.000 (25.000×2 − 2.000)"`; per-pcs → `"Subtotal: Rp46.000 ((25.000−2.000)×2)"`. Ini klarifikasi anti-bingung.
    *   `ScanToSellSheet`: toggle yang sama; saat `qty == 1` toggle di-disable dengan opacity 0.5 (kedua rumus sama, hindari noise) tapi tetap terlihat untuk konsistensi.
*   **Validation Rules (`canSave`):**
    *   Flat (OFF): `discountFlat >= 0` dan `discountFlat <= unitPrice * qty` (lineTotal >= 0).
    *   Per-pcs (ON): `discountPerPcs >= 0` dan `discountPerPcs <= unitPrice`.
    *   `canSave` existing + syarat di atas per semua item. Jika diskon melebihi batas → border merah di field Diskon + pesan inline `"Diskon melebihi subtotal"` dan tombol Simpan disabled.
    *   Diskon `nil`/0 = tanpa diskon (perilaku lama, toggle diabaikan).
*   **State & Progressive Disclosure:**
    *   State baru hanya in-memory per item: `isPerQty: Bool = false`. Tidak dipersist ke AppStorage/backend (keputusan per transaksi).
    *   Item baru dari `ProductPickerSheet` / `handleScannedProduct` selalu `discount = nil, isPerQty = false`.
    *   Mengubah `qty` tidak mengubah `discountInput` maupun `isPerQty`; hanya subtotal live yang recompute.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada. Zero migration.
*   **Invariants:** Kontrak backend tetap `discount = per-pcs`. Tidak ada kolom baru.

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada endpoint baru/berubah. `POST /api/v1/sales` / `CreateSalesOrderRequest.ItemInput(product_size_id, qty, unit_price, discount)` tetap sama.
*   **Frontend Conversion Rule (di `save()`):**
    ```swift
    // per item:
    let disc = item.discount ?? 0
    let q = Double(Int(item.qty ?? 1))
    let discountToSend: Double? = disc > 0
        ? (item.isPerQty ? disc : disc / q)
        : nil
    ```
    *   Flat Rp2.000 qty 2 → kirim `1000.0`; backend hitung `(25.000−1.000)*2 = 48.000` ✓.
    *   Per-pcs Rp2.000 qty 2 → kirim `2000.0`; backend hitung `46.000` ✓ (perilaku lama).
    *   Rounding: `Double` division; backend NUMERIC(14,4) menampung desimal. Selisih rounding max Rp1 per baris — diterima.
*   **Validation & Errors:** Tidak ada error baru dari backend. Validasi negatif/over-discount sepenuhnya client-side sebelum kirim.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak berubah (`SalesModels.swift`, `MockAPIService`, `ReceiptGenerator`, `ReportsView` tetap pakai `(unitPrice - discount) * qty` — tetap benar karena nilai yang dikirim sudah dikonversi ke per-pcs).
*   **Views & Controllers:**
    *   `Screens/Penjualan/TambahPenjualanSheet.swift`:
        *   `SaleItem`: tambah `var isPerQty: Bool = false`.
        *   `totalRevenue`: `items.reduce { $0 + (item.isPerQty ? ((price-disc)*qty) : (price*qty - disc)) }`.
        *   `itemCard`: tambah `Toggle("× Qty", isOn: $item.isPerQty)` compact di bawah `CurrencyInputField Diskon` + teks subtotal live per baris.
        *   `canSave`: tambah cek batas diskon per mode di atas.
        *   `save()`: terapkan Conversion Rule sebelum bangun `ItemInput`.
    *   `Screens/QR/ScanToSellSheet.swift`:
        *   Tambah `@State isPerQty = false` + Toggle + `totalAmount` gunakan rumus yang sama; `save()` konversi flat → `discount/qty`.
*   **Known Limitation (documented, accepted):** Di riwayat/detail/struk, diskon flat akan tampil terpecah per-pcs (mis. input flat 2.000/qty2 tampil sebagai Rp1.000). Subtotal & total tetap benar. Tidak ada perbaikan display riwayat di scope ini.

## 6. Verification & Test Plan
*   **Smoke Test:** Build lolos; buka Catat Penjualan, tambah 1 produk, toggle × Qty muncul default OFF; ScanToSellSheet toggle muncul (disabled saat qty 1).
*   **Sanity Test Scenarios:**
    1.  Qty 2 × 25.000, Diskon 2.000, toggle OFF → Total Pendapatan `Rp48.000`; simpan → order tersimpan, revenue backend 48.000.
    2.  Item sama, toggle ON → total `Rp46.000`; simpan → revenue 46.000 (perilaku lama).
    3.  Diskon 60.000 flat atas subtotal 50.000 (2×25.000) → inline error + Simpan disabled.
    4.  Diskon per-pcs 30.000 > harga 25.000 → inline error + Simpan disabled.
    5.  Qty 1, diskon 5.000, ON vs OFF → hasil identik (20.000 jika harga 25.000).
    6.  Multi-item campuran: item A flat 2.000/qty2 + item B per-pcs 1.000/qty3 → total = (Pᴀ×Qᴀ−2.000) + ((Pʙ−1.000)×Qʙ).
    7.  ScanToSell qty 3, harga 10.000, diskon flat 3.000 → total 27.000; payload kirim discount 1.000.
