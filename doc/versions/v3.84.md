# Version 3.84 - Perbaikan Format Struk Penjualan: Harga Aktual per Pcs + Diskon per Item di Bawah List + Total Diskon di Bawah

## 1. Problem / Opportunity
*   **Context:** Struk penjualan (ESC/POS thermal + PDF) yang dihasilkan `ReceiptGenerator.swift` / `ReceiptPDFGenerator.swift` saat ini menampilkan harga per pcs yang sudah dikurangi diskon (`effectivePrice = unitPrice - discount`) pada baris item, serta subtotal baris yang sudah pasca-diskon (`lineRevenue`). Contoh kasus dari struk nyata (foto struk): item `Scrunchie katun bordir pink (M)` qty 1 menampilkan `1x @ 18.000` subtotal `18.000`, padahal `Total Belanja: 21.000`, `Diskon: -3.000`, `Total Bayar: 18.000`. Ini menimbulkan kebingungan pelanggan karena harga yang dicetak per pcs bukan harga aktual.
*   **Objective:** 
    1. Baris item harus menampilkan harga aktual per pcs (`unitPrice`) dan subtotal sebelum diskon (`unitPrice × qty`).
    2. Diskon per item ditampilkan di bawah setiap baris harga di list, satu per satu.
    3. Di paling bawah struk, tambahkan caption `Total Diskon:` sebagai jumlah semua diskon item, antara `Total Belanja` dan `Total Bayar`.

## 2. User Flow & UX Specifications
*   **Entry Point:** Cetak struk otomatis setelah simpan penjualan dan tombol cetak/simpan PDF di halaman detail penjualan (fitur existing v3.59).
*   **UI Components:** `ReceiptGenerator.generateESCPOS(order:)` untuk thermal ESC/POS, `ReceiptPDFGenerator.generatePDF(order:)` untuk PDF 57mm.
*   **Validation Rules:** Diskon per item ≥ 0; total diskon tidak boleh melebihi total belanja.
*   **State & Progressive Disclosure:** Baris "Diskon per item" hanya dicetak bila item tersebut memiliki `discount > 0`. Baris "Total Diskon:" hanya dicetak bila `totalDiscount > 0`.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada (frontend-only).
*   **New / Modified Columns:** Tidak ada.

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada perubahan backend. Model `SalesOrderItem` (`unitPrice`, `discount`, `effectivePrice`, `lineRevenue`) dan `SalesOrder` (`displayRevenue`) tidak diubah; hanya representasi tampilan struk yang disesuaikan.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak ada perubahan model.
*   **Views & Controllers:**
    *   `Services/ReceiptGenerator.swift` (ESC/POS thermal):
        *   Baris item: ganti `item.effectivePrice` menjadi `item.unitPrice` pada bagian `"@ ..."` (harga per pcs aktual).
        *   Subtotal kolom baris item: ganti `item.lineRevenue` menjadi `item.unitPrice * Double(item.qty)` (jumlah sebelum diskon).
        *   Tambahkan baris di bawah setiap item bila `item.discount > 0`: `"  Diskon: -{item.discount × item.qty}"` (diskon per item satu per satu), ditambah indikator `(×qty)` bila qty > 1.
        *   Bagian totals (sudah benar, disesuaikan label):
            *   `Total Belanja:` = `sum(unitPrice × qty)`
            *   `Total Diskon:` = `-sum(discount × qty)` (hanya bila > 0, posisi di antara Total Belanja dan Total Bayar)
            *   `Total Bayar:` = `displayRevenue`
    *   `Services/ReceiptPDFGenerator.swift` (PDF 57mm): Sama perubahan di atas pada render PDF (baris item, diskon per item di bawah, dan Total Diskon di bawah).

## 6. Verification & Test Plan
*   **Smoke Test:** App build & launch; struk tercetak tanpa crash (thermal + PDF).
*   **Sanity Test Scenarios:**
    1.  Kasus diskon qty 1: item qty 1, unitPrice 21.000, discount 3.000 → struk cetak:
        ```
        Scrunchie katun bordir pink (M)
        - 1x @ 21.000            21.000
          Diskon: -3.000
        ---------------------------------
        Total Belanja:           21.000
        Total Diskon:                 -3.000
        Total Bayar:               18.000
        ```
    2.  Kasus diskon qty 2 (diskon × qty ON): item qty 2, unitPrice 21.000, discount 3.000 → struk cetak:
        ```
        Scrunchie katun bordir pink (M)
        - 2x @ 21.000            42.000
          Diskon: -6.000 (×2)
        ---------------------------------
        Total Belanja:           42.000
        Total Diskon:                 -6.000
        Total Bayar:               36.000
        ```
    2.  Kasus tanpa diskon: item qty 2, unitPrice 15.000, discount 0 → struk cetak `2x @ 15.000` subtotal `30.000`; tidak ada baris Diskon per item dan tidak ada baris Total Diskon; `Total Belanja: 30.000`, `Total Bayar: 30.000`.
    3.  Kasus multi-item dengan diskon bervariasi → verifikasi jumlah subtotal baris = Total Belanja, jumlah diskon per item = Total Diskon, dan Total Belanja − Total Diskon = Total Bayar.
