## Bug #1 — HPP Formula 100× Terlalu Kecil (Critical)

**Symptom:** Profit di Laporan Penjualan selalu minus. Estimasi HPP di ProdukDetailView
jauh lebih kecil dari kenyataan. Bahan di BahanDetailView tampil Rp74/m padahal harusnya
Rp7.400/m.

**Root cause:** `current_avg_cost` disimpan backend sebagai **Rp per cm** (hasil
`total_cost / length_cm`). Frontend secara keliru mengasumsikan unit Rp/m dan membagi
`cutLengthCm / 100.0` sebelum mengalikan — ini menghasilkan 100× underestimate untuk
biaya kain.

**Files changed:**

| File | Perubahan |
|---|---|
| `Screens/QR/ScanToStockSheet.swift` | Hapus `/ 100.0` dari formula fabric cost di `prefillHppFromSpec()` |
| `Screens/Produk/ProdukDetailView.swift` | Hapus `/ 100.0` dari formula fabric cost di `loadSpec()` |
| `Screens/Produksi/Bahan/BahanDetailView.swift` | `avgCostLabel` perlu kalikan `× 100` untuk display Rp/m (karena stored as Rp/cm) |

**Formula yang benar:**
```swift
// currentAvgCost adalah Rp/cm. CutLengthCm sudah dalam cm. Kalikan langsung.
let fabricCost = fabric.cutLengthCm * currentAvgCost
```

**Dampak downstream:** Produk yang HPP-nya sudah diset via ScanToStockSheet (dengan
formula salah) perlu di-scan ulang agar manual_hpp dioverwrite dengan nilai yang benar.
`ProdukDetailView.loadSpec()` juga skip jika `manualHppBreakdown != nil` — artinya
produk yang sudah punya manual HPP tidak otomatis dikoreksi dari ProdukDetailView.

## Bug #2 — QR Generator Menampilkan Parent Size Tanpa Varian Kain

**Symptom:** Di QR Generator, produk yang punya varian kain (mis. "S · Waffle Blue",
"S · Satin Pink") juga menampilkan entry "S" tanpa kain — entry ini tidak valid untuk
dibuat QR karena tidak ada stok khusus.

**Root cause:** `filteredSizes(for:)` mengembalikan semua `ProductSizeDetail` termasuk
parent/base entry (yang `fabricVariantName == nil`) meskipun size label tersebut sudah
punya varian.

**File changed:** `Screens/QR/QRGeneratorView.swift`

**Fix:** Kumpulkan set `sizeLabel` yang memiliki varian, lalu filter-out parent entry
untuk label tersebut:
```swift
let labelsWithVariants = Set(all.compactMap { $0.fabricVariantName != nil ? $0.sizeLabel : nil })
all = all.filter { size in
    guard size.fabricVariantName == nil else { return true }
    return !labelsWithVariants.contains(size.sizeLabel)
}
```

## Bug #3 — Edit Resep Buka Kosong, Baru Terisi Setelah Tutup + Buka Lagi

**Symptom:** Saat user tap "Edit" di section produk di ResepListView, sheet EditResepSheet
terbuka tapi kosong (tidak ada data resep). Jika sheet ditutup lalu dibuka lagi, data
muncul.

**Root cause:** Race condition di SwiftUI `.sheet(isPresented:)`. Dua state mutation
terpisah (`editSpecGroups = group.groups` dan `showEditSheet = true`) mengakibatkan sheet
closure dapat menangkap nilai lama `editSpecGroups` sebelum update terjadi.

**File changed:** `Screens/Produksi/Resep/ResepListView.swift`

**Fix:** Ganti `.sheet(isPresented:)` + dua `@State` terpisah dengan `.sheet(item:)` +
satu `Identifiable` wrapper. SwiftUI menjamin item yang diteruskan ke closure adalah
nilai yang di-set saat sheet dipicu:
```swift
private struct EditSheetItem: Identifiable {
    let id = UUID()
    let specGroups: [SpecGroup]
}

@State private var editSheetItem: EditSheetItem? = nil

// Trigger:
editSheetItem = EditSheetItem(specGroups: group.groups)

// Sheet:
.sheet(item: $editSheetItem, onDismiss: { Task { await load() } }) { item in
    EditResepSheet(specGroups: item.specGroups, onUpdate: {})
}
```

## Bug #4 — Dashboard Menampilkan "0% margin"

**Symptom:** Metric margin di Beranda selalu tampil "0% margin" meskipun backend sudah
mengembalikan nilai yang benar setelah backend fix.

**Root cause:** Backend mengembalikan `avgMarginPct` sebagai fraksi 0–1 (mis. `0.391`).
Frontend format string menggunakan `%.0f` tanpa `× 100`, sehingga `0.391` diformat
menjadi `"0%"`.

**File changed:** `Screens/Beranda/BerandaView.swift`

**Fix:**
```swift
// Sebelum:
label: String(format: "%.0f%% margin", dashboard?.avgMarginPct ?? 0)

// Sesudah:
label: String(format: "%.0f%% margin", (dashboard?.avgMarginPct ?? 0) * 100)
```

## Bug #5 — Ranking Margin & Analisa Waste Kain Tampil Kosong Tanpa Feedback

**Symptom:** Layar "Ranking Margin" dan "Analisa Waste Kain" di tab Laporan selalu kosong
— tidak ada data, tidak ada pesan error, tidak ada indikator loading.

**Root cause (1) — `try?` membuang error diam-diam:** Kedua view menggunakan `try?`
pada panggilan API. Jika request gagal karena network error atau API error, error dibuang
tanpa ditampilkan ke user.

**Root cause (2) — Ranking Margin memang kosong untuk produk manual HPP:** Endpoint
`GET /reports/margin-ranking` hanya mempertimbangkan produk dengan batch produksi
terkonfirmasi. Produk yang HPP-nya diset via `manual_hpp_*` tidak masuk. Ini adalah
bug backend yang terpisah (lihat Bug Backend #1 di bawah).

**File changed:** `Screens/Lainnya/ReportsView.swift`

**Fix:** Tambahkan `@State private var errorMsg: String?`, ganti `try?` dengan
`do/catch`, dan tambahkan view untuk state kosong (empty state) dan error state:
```swift
private func load() async {
    isLoading = true
    errorMsg = nil
    do {
        ranking = try await api.getMarginRanking()
    } catch {
        errorMsg = error.localizedDescription
        ranking = []
    }
    isLoading = false
}
```
