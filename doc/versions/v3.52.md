# Version 3.52 - Thermal Label Printing for Sales QR Codes

## 1. Problem / Opportunity
*   **Context:** The Oura Studio app generates QR codes for sales items. There is a need to print these QR codes onto physical labels using a Bluetooth thermal printer, specifically with dimensions 33x15mm and a 2mm gap, utilizing direct TSPL command mode for generic Bluetooth printers.
*   **Objective:** Implement functionality to directly print QR code labels for sales from the application to a generic TSPL-compatible Bluetooth thermal printer, using existing QR code generation logic and in-app Bluetooth communication.

## 2. User Flow & UX Specifications
*   **Entry Point:** A new "Print Label" action will be available within the existing UI where QR codes for sales are displayed or generated (e.g., from a product detail view, or a list item context menu).
*   **UI Components:**
    *   A prominent "Print Label" button or contextual menu item.
    *   A simple UI for entering the desired quantity of labels to print (defaulting to 1).
    *   **New:** A "Select Printer" button to scan and connect to available Bluetooth thermal printers.
    *   User feedback for printer status (searching, connecting, connected, printing, error).
*   **Printer Connection:** The system will leverage iOS CoreBluetooth for device discovery, connection, and data transmission to BLE thermal printers. The app will list available printers, allow the user to select one, and manage the connection.
*   **Validation Rules (`canPrint`):**
    *   Bluetooth must be enabled on the iOS device.
    *   A compatible Bluetooth printer must be connected.
    *   The QR code data to be printed must be valid and non-empty.
*   **State & Progressive Disclosure:** The "Print Label" action will be disabled if no printer is connected or if Bluetooth is off. The "Select Printer" button will indicate if no printers are found.

## 3. Direct TSPL Command Generation & Bluetooth Communication

*   **Core Logic:** A new module (`TSPLPrinterService` or similar) will be responsible for:
    1.  Managing Bluetooth Low Energy (BLE) peripheral scanning and connection (`CoreBluetooth`).
    2.  Constructing raw TSPL command strings based on printing requirements.
    3.  Sending these raw TSPL commands directly to the connected printer's characteristic.

*   **Label Dimensions & Setup Commands:**
    *   The service will dynamically generate TSPL commands based on configurable label settings.
    *   `SIZE <width_mm> mm,<height_mm> mm` (e.g., `SIZE 33 mm,15 mm`)
    *   `GAP <gap_mm> mm,0 mm` (e.g., `GAP 2 mm,0 mm`)
    *   `CLS` (Clear buffer)
    *   `DIRECTION 1` (Print direction, configurable if needed)
    *   `REFERENCE 0,0` (Origin point, configurable if needed)

*   **QR Code Command:**
    *   The TSPL `QRCODE` command will be used to print the QR code.
    *   Parameters (X, Y position, error correction level, cell width) will be calculated to fit and center the QR code appropriately within the label dimensions.
    *   Example (simplified):
        ```tspl
        QRCODE X_COORD,Y_COORD,ECC_LEVEL,CELL_WIDTH,ROTATION,QR_VERSION,MODE,FACTOR,"<QR_CODE_DATA>"
        ```
        (Where `ECC_LEVEL` is typically 'L', 'M', 'Q', 'H'; `CELL_WIDTH` is integer 1-10; `ROTATION` 0/90/180/270; `MODE` 'M' or 'A')

*   **Text & Data Commands (if any):**
    *   TSPL `TEXT` commands will be used for any human-readable information (e.g., SKU, product name, size/variant).
    *   Font type, size, rotation, and positioning (X, Y coordinates) will be determined to fit within the label layout.
    *   Example (simplified):
        ```tspl
        TEXT X_COORD,Y_COORD,"FONT",ROTATION,X_MULTIPLICATION,Y_MULTIPLICATION,"<TEXT_DATA>"
        ```

*   **Print Execution:**
    *   Finally, the `PRINT <quantity>,1` command will be sent to initiate printing.

## 4. Frontend Changes (SwiftUI)
*   **New Service (`TSPLPrinterService`):**
    *   Implement `TSPLPrinterService` (or similar) to encapsulate `CoreBluetooth` functionalities (scanning, connecting, writing data to a peripheral's characteristic).
    *   This service will expose methods like `startScanning()`, `connect(to: CBPeripheral)`, `printLabel(qrData: String, quantity: Int, width: Double, height: Double, gap: Double)`.
*   **Settings View (`SettingsView.swift`):**
    *   Add a new section for "Thermal Printer Settings".
    *   Fields for `Label Width (mm)`, `Label Height (mm)`, `Gap (mm)`.
    *   A "Select Bluetooth Printer" button which, when tapped, initiates scanning and presents a list of available BLE devices for connection.
    *   Allow the user to select a printer from the list and store its UUID.
    *   Display the currently connected printer's name or status.
    *   `@AppStorage` will be used to persist selected printer details (e.g., UUID, name) and label dimensions.
*   **QR Generator/Product Detail View:**
    *   Modify the relevant SwiftUI `View` (e.g., `ProdukDetailView` or a `ProdukListItem`'s context menu) where sales QR codes are generated/displayed.
    *   Integrate a "Print Label" button that calls `TSPLPrinterService.printLabel` with the current QR code data and configured dimensions/gap.
    *   Display connection status and provide feedback to the user regarding printing success or failure.

## 5. Verification & Test Plan
*   **Smoke Test:**
    1.  Enable Bluetooth on iOS device.
    2.  Navigate to "Thermal Printer Settings" and tap "Select Bluetooth Printer".
    3.  Connect to a generic TSPL-compatible Bluetooth thermal printer.
    4.  Navigate to a product/sales item with a generated QR code.
    5.  Tap the "Print Label" action.
    6.  Verify that one label is printed successfully by the connected printer.
    7.  Scan the printed QR code to confirm it contains correct product data.
*   **Sanity Test Scenarios:**
    *   **Label Dimensions Accuracy:** Physically measure printed labels to confirm dimensions match the configured values (e.g., 33x15mm with 2mm gap).
    *   **QR Code Readability:** Verify QR codes are scannable by a standard QR reader application across various data lengths.
    *   **Multiple Copies:** Test printing 5 copies of a label and verify 5 identical labels are produced.
    *   **No Printer Connected:** Verify appropriate error message is displayed when attempting to print without a connected printer.
    *   **Bluetooth Disabled:** Verify appropriate error message is displayed and printer selection/printing is disabled when Bluetooth is off.
    *   **Printer Disconnection:** Test behavior when the printer disconnects during a printing job.
    *   **Different Label Sizes:** Configure different label sizes in settings and verify the printer adapts correctly.

## 6. Incremental Implementation Steps for `dev-fullstack`

To facilitate incremental development by the `dev-fullstack` skill, here's a breakdown of the feature into distinct, testable stages:

### Step 1: CoreBluetooth Scanner & Connection Service
*   **Objective:** Implement basic Bluetooth device scanning and connection functionality.
*   **Tasks:**
    *   Create `TSPLPrinterService` class (or similar) that conforms to `CBCentralManagerDelegate` and `CBPeripheralDelegate`.
    *   Implement `startScanningForPeripherals()` to discover BLE devices.
    *   Implement `connect(to: CBPeripheral)` to establish a connection.
    *   Implement `disconnect()` and handle connection state changes.
    *   Expose a way to observe discovered peripherals and connection status (e.g., `@Published` properties).
*   **Verification (Smoke Test):**
    *   Run app on a physical device.
    *   Verify the app can detect nearby BLE devices (e.g., a thermal printer).
    *   Verify the app can connect and disconnect from a selected device.

### Step 2: Settings UI for Printer Selection & Configuration
*   **Objective:** Integrate printer selection and label dimension configuration into `SettingsView.swift`.
*   **Tasks:**
    *   Add a new section "Thermal Printer Settings" in `SettingsView.swift`.
    *   Add controls for `Label Width (mm)`, `Label Height (mm)`, `Gap (mm)` using `@AppStorage` for persistence.
    *   Implement a "Select Bluetooth Printer" button that triggers `TSPLPrinterService` scanning and displays discovered devices.
    *   Allow the user to select a printer from the list and store its UUID.
    *   Display the currently connected printer's name or status.
*   **Verification (Smoke Test):
    *   Navigate to Settings, verify the new section and fields appear.
    *   Test scanning for printers and selecting one. Verify the selected printer's name is shown.
    *   Verify label dimensions persist after app restart.

### Step 3: TSPL Command Generator & Data Transmission
*   **Objective:** Implement TSPL command construction and sending to the connected printer.
*   **Tasks:**
    *   Within `TSPLPrinterService`, implement methods to generate TSPL command strings for `SIZE`, `GAP`, `CLS`, `QRCODE`, and `PRINT` based on input `qrData`, `width`, `height`, `gap`, and `quantity`.
    *   Add logic to write the generated TSPL command bytes to the connected `CBPeripheral`'s write characteristic.
    *   Handle potential data chunking if the TSPL command is too long for a single BLE write operation.
*   **Verification (Sanity Test):**
    *   Use the implemented UI from Step 2 to connect to a printer.
    *   Call `printLabel` (from a debug button or temporary UI) with sample QR data.
    *   Verify a label prints with the QR code and correct dimensions.

### Step 4: QR Generator/Product Detail View Integration & Error Handling
*   **Objective:** Integrate the printing functionality into the main app flow and refine error handling.
*   **Tasks:**
    *   Add the "Print Label" button to the relevant view (e.g., `ProdukDetailView`).
    *   Pass the necessary QR code data from existing logic to `TSPLPrinterService.printLabel`.
    *   Implement user-friendly alerts or toast messages for all error conditions (e.g., Bluetooth off, no printer connected, printing failed).
    *   Ensure the "Print Label" button state (enabled/disabled) correctly reflects printer connectivity.
*   **Verification (Full Test Suite):**
    *   Execute all test scenarios from Section 5 to ensure full functionality and robustness.
