# Version 3.75 - Optimasi Pemuatan Katalog di Generator QR (Cache-First + Slim + Filter Ringan)

**Status:** PLANNED
**Date:** 2026-10-20
**Changed by:** Fullstack
**Konteks backend:** `../../backend/doc/versions/v3.75.md` (kontrak endpoint yang sama)
**Backend changes required:** Ya (additive): `product_id` di `ProductSizeScanOut`, `with_total` di `/product-sizes/slim`, `Cache-Control`, GZip middleware. Nol migrasi DB.

---

## 1. Problem / Opportunity

*   **Context:** Membuka sheet **Generator QR** (Produk → ikon QR) masih menampilkan spinner lama. Penyebab terukur:
    1.  `QRGeneratorView.loadData()` (`Screens/QR/QRGeneratorView.swift:590`) memanggil `getProducts()` lalu `getAllProductSizes()` **berurutan** (2 RTT jaringan serial).
    2.  `getAllProductSizes()` memakai `GET /product-sizes?limit=500` versi **full** (`ProductSizeWithProductOut`), yang di backend menjalankan ±7 query (count, sizes+images, stock aggregate, latest HPP, fabric items, hardware items) dan mengembalikan HPP breakdown + margin + 5 field manual HPP + images untuk ±434 varian. QR Generator hanya butuh 8 field.
    3.  `onChange(of: isFilterActive)` (`:138`) dan `DateRangeField` (`:164`) memanggil `loadData()` **penuh** hanya untuk mengubah filter; `isLoading = true` menyembunyikan seluruh daftar dan memunculkan spinner lagi.
    4.  Data yang sama sudah ada di memori `ProdukListView` (products + allSizes) dan di `QRProductCache`, tetapi tidak dipakai ulang.
    5.  Backend tidak mengirim `Cache-Control`/ETag untuk endpoint katalog dan tidak memasang GZip; Cloud Run `minScale: 0` menambah cold start pada open pertama.
    6.  `makeQRImage()` (`:429`) membuat `CIContext()` baru **per baris per evaluasi body** → jank setelah data muncul (bukan penyebab spinner, tapi membuat layar terasa lambat).
*   **Objective:** Buka Generator QR **instan** bila snapshot sudah ada (<100 ms), dan open pertama turun menjadi **1 request ringan** (slim) dengan 2–3 query backend, tanpa regresi fitur cetak/cari/filter.

## 2. User Flow & UX Specifications

*   **Entry Point:** Ikon QR di toolbar/shortcut `ProdukListView` → sheet `QRGeneratorView` (tidak berubah).
*   **Perilaku pemuatan (cache-first):**
    1.  Saat sheet dibuka, jika ada **snapshot katalog** (dari `QRCatalogStore`, di-warm oleh `ProdukListView` atau open sebelumnya) → daftar **langsung tampil** tanpa spinner.
    2.  Selanjutnya jalankan refresh **silent** di background (`GET /product-sizes/slim`). Jika data berubah, daftar di-swap tanpa reset pilihan (`selectedSizeIds`, `qtyPerSize` dipertahankan untuk id yang masih ada).
    3.  Spinner penuh **hanya** bila snapshot kosong (open pertama di device) — layout header (search, toggle tanggal, toggle harga) tetap terlihat.
    4.  Gagal refresh dengan snapshot ada → pertahankan data lama + banner error non-blocking + tombol "Coba lagi" (pola v3.72). Gagal tanpa snapshot → error state dengan retry.
*   **Filter Tanggal:**
    *   Toggle/ubah rentang **hanya** memanggil `getStockLedger(from:to:)`; katalog tidak di-fetch ulang.
    *   Indikator loading kecil (mis. `ProgressView` inline di row filter) alih-alih spinner penuh; daftar tetap terlihat.
    *   Default qty cetak saat filter aktif tetap `additionsByVariant[id] ?? 1` (perilaku v3.44 tidak berubah).
*   **Search:** perilaku tidak berubah (`product.name`, `sku`, `displayLabel`). Hanya sumber data yang berubah.
*   **UI Components:** reuse existing — `DateRangeField`, `LabelPriceRadioGroup`, `List(.insetGrouped)`, bottom bar `Preview & Print`, `QRPrintPreviewSheet`. Tidak ada komponen baru yang user-facing.
*   **Validation Rules (`canSave`):** tidak ada form; bottom bar tetap disabled saat `selectedSizeIds` kosong atau `isGenerating`.
*   **State & Progressive Disclosure:** pilihan user tidak boleh hilang saat background refresh; id yang hilang dari server dibuang dari `selectedSizeIds`/`qtyPerSize`.

## 4. API Contract (FastAPI)

### 4.1 `GET /product-sizes/slim` (modifikasi additive, sudah ada sejak v3.69)

*   **Schema `ProductSizeScanOut`** (`app/schemas/product.py:193`) ditambah:
    ```python
    product_id: uuid.UUID
    ```
    Diisi dari `s.product_id` pada `_scan_out()` (`app/routers/products.py:1320`). Field ini juga otomatis muncul di `GET /product-sizes/scan-resolve` (additive; klien lama mengabaikan key tak dikenal).
*   **Query param baru:**
    ```
    with_total: bool = Query(True, description="False = skip COUNT(*) untuk preload katalog")
    ```
    *   `with_total=false` → lewati `q.count()` (hemat 1 RTT ±100–150 ms). Implementasi: fetch `limit + 1` baris; jika lebih dari `limit`, `next_page = page + 1`, `total_items = 0`, `total_pages = 1` (klien preload hanya membaca `data` + `next_page`).
    *   `with_total=true` → perilaku saat ini, tidak berubah.
*   **Header response:** `Cache-Control: private, max-age=30`.
*   **Query plan dengan `with_total=false`:** 2 statement (sizes+product, `_stock_all_map`) + 0 count.
*   **Contoh response (satu baris):**
    ```json
    {
      "data": [{
        "id": "uuid", "product_id": "uuid",
        "product_sku": "SCR", "product_name": "Scrunchie",
        "size_label": "M", "fabric_variant_name": "Waffle Blue",
        "current_stock_qty": 12, "production_stock_qty": 10, "manual_stock_qty": 2,
        "selling_price": 18000.0, "is_archived": false
      }],
      "total_items": 0, "total_pages": 1, "current_page": 1,
      "next_page": null, "prev_page": null
    }
    ```
*   **Kompatibilitas:** field baru additive → backend lama (tanpa `product_id`) tetap bisa dilayani klien via fallback grouping by SKU (lihat §5).

### 4.2 Header cache untuk endpoint katalog

*   `GET /product-sizes` (full) dan `GET /products`: `Cache-Control: private, max-age=15`. Tidak mengubah body.
*   `GET /product-sizes/slim`: `private, max-age=30` (di atas).
*   **GZip:** pasang `GZipMiddleware(minimum_size=1024)` di `app/main.py`. Payload katalog ±434 baris turun drastis di koneksi mobile.

### 4.3 Non-goal kontrak

*   Tidak ada endpoint baru, tidak ada perubahan bentuk response lama (selain field tambahan additive).

## 5. Frontend Changes (SwiftUI)

### 5.1 Models (`Networking/Models/ProductModels.swift`)

*   `ProductSizeSlim`: tambah `let productId: UUID?` (`CodingKeys: "product_id"`). **Optional** agar app tidak gagal decode bila backend belum di-deploy.
*   `ProductSizeDetail`: tambah initializer konversi ringan:
    ```swift
    init(slim s: ProductSizeSlim, productId: UUID)
    ```
    Mapping: `productionStockQty`/`manualStockQty` dari slim; `latestHppBreakdown`, `marginPct`, `manualHpp*`, `images`, `reorderMinQty` = `nil`; `sellingPrice`, `isArchived`, `productSku`, `productName`, `sizeLabel`, `fabricVariantName` dari slim.
    Ini menjaga `generatePDF`, `QRPrintPreviewSheet`, dan `makeQRImage` tetap memakai `ProductSizeDetail` tanpa refactor besar.

### 5.2 `Networking/APIService.swift`

*   `getSlimProductSizes()`:
    *   Loop halaman (`page=1...`, `limit=500`, `with_total=false`) sampai `nextPage == nil` (safety guard 10 halaman), seperti `fetchAllSizesBulk()` di `ProdukListView`.
    *   Fallback kompatibilitas: jika `404`/`422` (backend lama) → `getAllProductSizes()` lalu konversi.
*   `session`: ganti `URLSession.shared` dengan `URLSession(configuration:)` ber-`URLCache(memoryCapacity: 8MB, diskCapacity: 50MB)` agar `Cache-Control` benar-benar dipakai saat sheet dibuka ulang.

### 5.3 `Screens/QR/QRCatalogStore.swift` (baru, kecil)

*   `final class QRCatalogStore` (`@MainActor`, singleton) menyimpan snapshot:
    ```swift
    struct Snapshot {
        let products: [Product]
        let sizesByProduct: [UUID: [ProductSizeDetail]]
        let fetchedAt: Date
    }
    ```
*   API: `snapshot`, `store(products:sizes:)`, `invalidate()`, `ttl: TimeInterval = 60`.
*   Dipakai bersama `ProdukListView` (warm) dan `QRGeneratorView` (baca/tulis) — **satu sumber cache**, tidak menduplikasi dictionary per-sheet (sejalan v3.68).
*   `QRProductCache` tidak diubah; fokusnya scan/cart, bukan katalog QR.

### 5.4 `Screens/QR/QRGeneratorView.swift`

*   `loadData()` dipecah:
    *   `loadCatalog(force:)`: baca snapshot → render instan; lalu `api.getSlimProductSizes()` → konversi + grouping (by `productId`; fallback by `productSku` bila `productId == nil`) → swap state + simpan snapshot. `isLoading` hanya `true` bila snapshot kosong.
    *   `loadLedger()`: hanya `getStockLedger` (dipanggil saat filter aktif/berubah). Katalog tidak disentuh.
    *   Initial: `async let` katalog + ledger (bila filter aktif) berjalan paralel.
*   `.onChange(of: isFilterActive)` dan closure `DateRangeField` → `loadLedger()` saja.
*   Task management: simpan `Task` aktif di `@State`, cancel sebelum memulai load baru (mencegah race `.task` + `onChange`).
*   Gagal refresh: pertahankan snapshot + `errorBanner` (state baru) + retry; hapus pola `try? ?? []` yang diam-diam mengosongkan data.
*   Saat swap data: pruned `selectedSizeIds`/`qtyPerSize` untuk id yang tidak ada lagi.
*   `makeQRImage()`: pakai satu `CIContext` statis/shared + cache `[String: UIImage]` per payload (key = string QR, termasuk `includePrice`). Hapus pembuatan `CIContext()` per baris.
*   `sizesByProduct` tetap `[UUID: [ProductSizeDetail]]` agar seluruh jalur cetak tidak berubah.

### 5.5 `Screens/Produk/ProdukListView.swift`

*   Setelah `loadFirstPage`/`loadMoreProducts`/filter berhasil: panggil `QRCatalogStore.shared.store(products:..., sizes:...)` (murah, hanya assignment) agar open QR pertama **instan**.
*   Sheet `QRGeneratorView(initialIsFilterActive:...)` tidak berubah signature-nya.

### 5.6 Rollout compatibility

*   App baru + backend lama: `getSlimProductSizes` fallback ke full; grouping by SKU; tetap benar (hanya tidak secepat target).
*   App lama + backend baru: field `product_id`/`with_total` additive, aman.
*   Urutan deploy disarankan: backend dulu → app.

## 6. Verification & Test Plan

### Smoke
*   `xcodebuild ... CODE_SIGNING_ALLOWED=NO build` → BUILD SUCCEEDED.
*   Buka Produk → Generator QR → tidak crash, daftar muncul.

### Sanity (device/simulator)
1.  **Cold open (cache kosong):** spinner hanya sampai request slim selesai; daftar ±434 varian tampil; tidak ada request `GET /products` atau `/product-sizes` full (cek log network).
2.  **Warm open:** tutup lalu buka lagi dalam <60 s → daftar tampil <100 ms tanpa spinner; refresh silent terjadi di background.
3.  **Filter toggle ON:** daftar tidak hilang; hanya `GET /stock-ledger` yang terpanggil; qty default = net penambahan; OFF mengembalikan perilaku semula.
4.  **Ubah rentang tanggal:** sama seperti #3, indikator inline, bukan spinner penuh.
5.  **Search:** cari nama produk, SKU, dan label ukuran → hasil sama seperti versi lama.
6.  **Cetak:** pilih beberapa varian → Preview & Print → PDF A4 dan Label Thermal tetap benar; toggle "Sertakan Harga" masih meng-encode `oura2:<id>:<priceCents>:<shortName>`.
7.  **Backend lama (simulasi 404 slim):** fallback full tetap menampilkan katalog.
8.  **Error jaringan saat refresh:** data lama tetap tampil + banner retry; pilihan tidak hilang.

### Backend
*   `python -m py_compile app/routers/products.py app/schemas/product.py app/main.py`.
*   `GET /product-sizes/slim?limit=500&with_total=false` → 2 statement (log SQL), `product_id` ada di setiap baris, `next_page` benar saat data > limit, `Cache-Control: private, max-age=30`.
*   `GET /product-sizes/slim` tanpa `with_total` → response identik dengan v3.69 (regresi).
*   `Accept-Encoding: gzip` → `Content-Encoding: gzip` untuk payload >1 KB.
*   `GET /product-sizes/scan-resolve` tetap berfungsi (field tambahan tidak mengubah `items`/`missing_ids`).

### Regression
*   `ProdukListView` (paging, search, filter tanggal) — tidak ada perubahan perilaku.
*   `QRScannerSheet` / `ScanToSellSheet` / `TambahPenjualanSheet` yang memakai `QRProductCache` — tetap jalan (slim sekarang punya `product_id`, opsional).
*   `ProdukDetailView` dan `PatternSpec` yang memakai `getAllProductSizes()` full — tidak berubah.
