# v2.8 — Stock Validation in TambahPenjualanSheet + Quick Stok Adjustment (2026-08-09)

**Changed by:** Frontend  
**Sections affected:** Section 2 (Penjualan), Section 4 (Products/Stock)

---

## Summary

Dua perubahan di `TambahPenjualanSheet`:

1. **Tombol stepper up/down qty** diperbaiki — semua tombol di dalam List rows kini menggunakan `.buttonStyle(.borderless)` agar tap tidak diintercept oleh gesture selection row.

2. **Validasi stok real-time dengan quick adjustment** — up stepper tidak lagi diam-diam berhenti di `maxQty`. Jika qty yang diinput melebihi stok tersedia, muncul inline warning dengan tombol "Tambah Stok". Tombol tersebut membuka `QuickAdjustStokSheet` yang memanggil endpoint stock-adjustments yang sudah ada.

---

## Change 1 — Stepper button fix (`.buttonStyle(.borderless)`)

### Masalah
Tombol up/down qty di dalam `Form`/`List` row menggunakan `.buttonStyle(.plain)`. Pada beberapa konteks SwiftUI List/Form, row's selection gesture dapat mengintercept tap sehingga button tidak merespons.

### Fix
Ganti `.buttonStyle(.plain)` → `.buttonStyle(.borderless)` pada semua tombol di dalam `itemCard` (down stepper, up stepper, ×-close button).

---

## Change 2 — Inline over-stock warning

### Sebelum
Up stepper di-cap diam-diam di `maxQty` — user tidak mendapat feedback ketika mencoba menjual lebih dari stok tersedia. Text field juga mencap input di `min(v, maxQty)`.

### Sesudah
- Up stepper **tidak ada hard cap** — user dapat memasukkan qty berapapun
- Text field juga tidak lagi membatasi ke `maxQty`
- Ketika `qty > maxQty`: muncul inline warning row di bawah input:
  - Icon segitiga kuning + teks "Stok tidak cukup (tersedia N pcs)"
  - Tombol "Tambah Stok" di kanan → membuka `QuickAdjustStokSheet`
- Tombol "Simpan" di toolbar tetap disabled selama ada item dengan `qty > maxQty`

---

## Change 3 — QuickAdjustStokSheet (new)

Sheet baru `private struct QuickAdjustStokSheet` di dalam file yang sama.

| Field | Value |
|---|---|
| Trigger | Tombol "Tambah Stok" di warning row |
| Detent | `.medium` |
| Info section | Nama produk + stok saat ini |
| Input | `NumericInputField` — jumlah yang ditambah (pcs) |
| Footer | Preview "Stok baru: N pcs" (muncul setelah qty diisi) |
| API call | `POST /products/{sku}/sizes/{sizeId}/stock-adjustments` dengan `reason: "sales_adjustment"` |
| On success | Update `items[i].maxQty` = `updated.currentStockQty` dari response; warning hilang otomatis jika qty ≤ maxQty baru |
| On error | Inline error text di dalam sheet, sheet tidak dismiss |

### API endpoint (sudah ada sejak v2.0)

```
POST /products/{sku}/sizes/{sizeId}/stock-adjustments
Body: { "qty": Int, "reason": String, "note": String? }
Returns: ProductSizeBasic (sama seperti PATCH size response)
```

Tidak ada endpoint baru — endpoint ini sudah dispec dan diimplementasikan untuk use case "Stok Awal" di AddSizeSheet.
