# Version 3.47 - Otomatisasi API Integration & Network Contract Test

## 1. Masalah / Peluang
* **Konteks:** Perubahan skema API pada backend atau model data di frontend berpotensi merusak sinkronisasi data (*contract drift*). Saat ini, verifikasi fungsionalitas APIService sebagian besar dilakukan secara manual atau melalui mockup, sehingga sulit mendeteksi perubahan model secara dini di lingkungan CI (GitHub Actions).
* **Objektif:** Mengimplementasikan skrip pengujian integrasi live yang komprehensif (`APIIntegrationTests.swift`) sesuai dengan spesifikasi dokumen strategi pengujian **TC-003-api-integration-test-strategy.md**.
* **Constraint:** 
  1. Pengujian harus dapat berjalan secara live terhadap staging/sandbox backend (`https://ourastudiobackendseoul-763614853578.asia-northeast3.run.app/api/v1`).
  2. Menggunakan JWT bearer token otentikasi dari environment variable `DEV_BEARER_TOKEN`.
  3. Memiliki mekanisme graceful bypass (skip notice) jika dijalankan secara lokal tanpa token, agar tidak merusak build harian developer.
  4. Menerapkan self-cleaning hook (archive block) yang membersihkan/mengarsipkan data uji setelah pengujian selesai untuk menjaga kerapihan database tanpa merusak integritas relasional (Backend tidak mendukung HARD DELETE untuk Material untuk menjaga relasi historis transaksi).

## 2. Alur Pengujian & Langkah Verifikasi

### A. Setup Fase
1. Membaca nilai dari variable environment `DEV_BEARER_TOKEN`. Jika token kosong atau tidak ditemukan, tes akan dilewati (*gracefully skipped*) dengan pencatatan log.
2. Menginisialisasi singleton `APIService.shared`, menonaktifkan mode mock (`useMock = false`), dan mengatur header otentikasi menggunakan token tersebut.

### B. Alur CRUD Bahan (Material)
1. **Pencarian (GET /materials):** Melakukan kueri untuk mengambil seluruh bahan guna memastikan model `Material` didekode dengan benar dari response database.
2. **Pembuatan (POST /materials):** Membuat satu entitas bahan uji baru menggunakan nama acak (misal: `TEST_FABRIC_UUID`) dengan properti lengkap (nama, tipe, jenis unit, harga, deskripsi).
3. **Validasi Kontrak:** Memastikan decoding response sukses tanpa melempar kegagalan decode (`keyNotFound` dll).
4. **Pembersihan Otomatis (PATCH /materials/{id} is_archived = true):** Karena backend melarang penghapusan keras (hard delete) pada bahan untuk menjaga integritas transaksi historis, pembersihan diri dilakukan dengan melakukan soft-archiving melalui metode `archiveMaterial` bawaan APIService.

### C. Alur Produk & Ukuran (Product & Size Lookup)
1. **Pencarian Produk (GET /products):** Mengambil daftar produk utuh.
2. **Validasi Deserialisasi:** Memastikan seluruh item produk berserta array ukuran (`sizes`), kategori, dan rincian breakdown HPP ter-decode secara sempurna sesuai skema `ProductModels`.
