# v3.74 — Pisah Alur "Tambah Produk Baru" vs "Tambah Stok dari Resep"

**Status:** PLANNED
**Date:** 2026-10-18
**Changed by:** Frontend
**Backend changes required:** Tidak ada (frontend-only)

---

## 1. Problem / Opportunity

*   **Context:** `TambahProdukLengkapSheet` menggabungkan dua intent berbeda dalam satu sheet:
    form **"Buat Produk Baru"** (murni lokal, instan) dan seksi **"DARI RESEP"** (network-bound).
    Saat sheet dibuka, `.task { await loadMaterials(); await loadResepProducts() }`
    (`TambahProdukLengkapSheet.swift:142`) menjalankan keduanya bersamaan.
    `loadResepProducts()` (baris 762) melakukan **N+1 call**: 1× `GET /pattern-specs`
    + 1× `GET /products/{sku}/sizes` **per SKU unik**.
*   **Efek flaky:**
    1.  Spinner muncul dulu, baris resep menyusul → divider `BUAT PRODUK BARU`
        (yang hanya dirender jika `!resepProducts.isEmpty`, baris 211) baru muncul
        setelah load → seluruh form **bergeser**.
    2.  Error jaringan disembunyikan (`try? ... ?? []`) → gagal-load tampak seperti
        "tidak ada produk", bukan error.
*   **Objective:** Pisahkan dua intent ke dua jalur/entry yang jelas:
    **(A)** Buat Produk Baru — instan, nol network saat dibuka.
    **(B)** Tambah Stok dari Resep — layar sendiri dengan loading/empty/error state
    terisolasi. FAB di tab Produk berubah jadi **Menu 2 aksi**.
    Perilaku "dari resep" **tidak berubah** (hanya `adjustStock`/tambah stok barang
    jadi — tanpa konsumsi bahan).

## 2. User Flow & UX Specifications

### Entry Point
*   FAB `+` di `ProdukListView` **tidak lagi** langsung membuka sheet; jadi `Menu` native:
    *   **"Buat Produk Baru"** (icon `plus`) → `TambahProdukBaruSheet`
    *   **"Tambah Stok dari Resep"** (icon `shippingbox`) → `ResepStockPickerSheet`
*   Visual FAB tidak berubah (plus 52×52, `accentGradient`). Menu muncul menempel ke FAB.

### Screen A — `TambahProdukBaruSheet` (form sekarang, tanpa seksi "DARI RESEP")
*   Isi = step 1 (Nama, SKU, Kategori, Ukuran, Tipe Produk) + step 2 (Resep) yang **sudah ada**.
*   **Dihapus:** seksi `dariResepSection` beserta divider `BUAT PRODUK BARU`.
*   **Tidak ada network call saat sheet dibuka.** `loadMaterials()` hanya dijalankan
    saat user masuk ke step resep (mis. `.task(id: isOnRecipeStep)` + guard
    `hasLoadedMaterials` agar tidak reload tiap toggle).
*   Tombol tetap: **"Lanjutkan ke Resep →"** (primary) dan **"Simpan Tanpa Resep"** (secondary).
*   Judul sheet tetap "Tambah Produk".

### Screen B — `ResepStockPickerSheet` (layar baru)
*   Header: "Batal" + judul **"Tambah Stok dari Resep"**.
*   Search field `Cari produk dari resep...` (case-insensitive, filter by nama).
*   **State eksplisit:**
    *   **Loading:** spinner terpusat + teks "Memuat resep…".
    *   **Error:** pesan + tombol **"Coba Lagi"** (memanggil ulang load). Bukan empty palsu.
    *   **Empty:** "Belum ada produk dengan resep." + arahan membuat resep dulu di tab Produksi.
    *   **Loaded:** daftar row — nama produk, size labels unik, tag stok
        ("Belum ada stok" / "Stok: N pcs"), chevron. Urut: **stok 0 dulu, lalu alphabetical**.
*   Tap row → present **`TambahStokDariResepSheet`** (existing, dipindah) →
    isi qty per ukuran → simpan (`adjustStock`) → reload daftar lalu dismiss.

### Validation Rules (`canSave`)
*   Step 1 & Step 2: **tidak berubah** dari implementasi sekarang
    (`step1Valid`: nama + SKU + ukuran non-kosong; `recipeCanSave`: kain + labor + qty komponen + minimal 1 ukuran lengkap).
*   `ResepStockPickerSheet` tidak punya `canSave` (layar pemilihan); tombol Simpan ada di
    `TambahStokDariResepSheet` (`hasAnyQty`).

### State & Progressive Disclosure
*   Step 2 tetap mengikuti aturan sekarang (materials baru dimuat saat masuk step resep).

## 6. Verification & Test Plan

*   **Smoke Test:**
    *   `xcodebuild` sukses.

    *   Kedua sheet (`TambahProdukBaruSheet`, `ResepStockPickerSheet`) terbuka tanpa crash.
*   **Sanity Test Scenarios:**
    *   **Buat Produk Baru tanpa resep:** sheet terbuka **instan tanpa spinner jaringan**;
        produk + ukuran terbuat; auto-navigasi ke `ProdukDetailView`.
    *   **Buat Produk Baru + resep:** materials baru ter-load saat masuk step resep
        (bukan saat sheet dibuka); spec terbuat benar.
    *   **Tambah Stok dari Resep:** pilih produk → isi qty → stok bertambah;
        daftar reload setelah sukses.
    *   **Error state:** matikan backend → picker tampil pesan error + "Coba Lagi"
        (bukan "Tidak ada produk").
    *   **Empty state:** tanpa produk beresep → tampil empty state yang informatif.

## Catatan / Di luar scope
*   **N+1 load** (`GET /pattern-specs` + per-SKU `getProductSizes`) sengaja **tidak** diperbaiki
    sekarang (frontend-only). Kalau nanti mau hilangkan total, tambah endpoint agregat
    (mis. `GET /pattern-specs/products`) — di luar v3.74.
*   **Memindah selector "Tipe Produk"** (Varian Kain/Kombo Kain) dari step 1 ke step 2: **opsional**,
    tidak termasuk perubahan v3.74. Biarkan di step 1 agar scope minimal.
