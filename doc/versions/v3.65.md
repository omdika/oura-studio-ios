# Version 3.65 - Search by SKU di Picker Catat Penjualan + Tampil SKU

## 1. Problem / Opportunity
*   **Context:** Sheet `Pilih Produk` di `Catat Penjualan` (`TambahPenjualanSheet` → `ProductPickerSheet`) saat ini hanya memfilter by `productName`, `sizeLabel`, `fabricVariantName` (lihat `TambahPenjualanSheet.swift:649-657`). Ketik SKU (mis. `SCR-001`) → hasil kosong. Header grup list juga hanya menampilkan nama produk tanpa SKU, jadi kasir tidak bisa bedakan varian dengan nama mirip.
*   **Objective:** Search di picker support **SKU + nama produk** (seperti `ProdukListView` yang sudah bisa `name || sku || size || variant`), dan **SKU selalu terlihat di list**. Scope hanya `TambahPenjualanSheet.ProductPickerSheet`. Frontend-only, tanpa perubahan backend.

## 2. User Flow & UX Specifications
*   **Entry Point:** `Penjualan` → `Catat Penjualan` → `Tambah Produk` → sheet `Pilih Produk`.
*   **Search behavior:**
    *   Placeholder diubah: `"Cari produk..."` → `"Cari produk / SKU..."`.
    *   Query di-trim (`trimmingCharacters(in: .whitespacesAndNewlines)`) lalu `lowercased()`; kosong → tampilkan semua pickable seperti sekarang.
    *   Match jika SALAH SATU terpenuhi (partial, case-insensitive, samakan pola `ProdukListView.swift:58-67`):
        *   `productName.localizedCaseInsensitiveContains(q)` (existing, dipertahankan)
        *   `productSku.localizedCaseInsensitiveContains(q)` (**baru**)
        *   `sizeLabel.localizedCaseInsensitiveContains(q)` (existing)
        *   `fabricVariantName?.localizedCaseInsensitiveContains(q)` (existing)
    *   Tidak ada highlight khusus; baris yang match tetap tampil penuh satu grup.
*   **Grouping (anti-merge nama kembar):**
    *   Key grup diubah dari `productName` → `productSku` (satu SKU = satu produk = satu grup). Sort grup tetap by `productName` asc agar urutan tidak berubah.
    *   Struktur: `[(sku: String, productName: String, sizes: [ProductSizeDetail])]`, `id: \.sku`.
*   **Tampilan SKU di list:**
    *   **Header grup (selalu tampil):** `Text("\(productName) • \(sku)".uppercased())` — style existing dipertahankan (size 11, semibold, `textTertiary`, kerning 0.8). Contoh: `SCRUNCHIE 2 TONE PINK KUNING • SCR-2T-PK`.
    *   **Baris item (tidak berubah):** `displayLabel` (size · varian) + harga + badge stok tetap. Tidak perlu ulang SKU per baris karena header grup sudah memuat SKU yang sama untuk semua baris dalam grup.
    *   **Item terpilih (`SaleItem.displayName`):** tidak berubah (`"\(productName) · \(displayLabel)"`) — struk/nota tidak ikut berubah di versi ini.
*   **UI Components:** reuse existing (`TextField` search box, `List` + `Section`, stock `Capsule` badge). Tidak ada komponen baru.
*   **Validation Rules (`canSave`):** tidak berubah (picker hanya memilih `size`, tidak mengubah validasi simpan penjualan).
*   **State & Progressive Disclosure:** tidak ada state baru; `searchText` tetap `@State` lokal sheet. `alreadySelected` filter tetap jalan sebelum search filter.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Tidak ada. Zero migration.
*   **Alasan backend tidak perlu diubah:** picker memanggil `GET /product-sizes?page=1&limit=500` (`APIService.getAllProductSizes()`) yang response-nya **sudah mengandung** `product_sku` + `product_name` per size (`ProductSizeDetail`, `ProductModels.swift:233-234`). Filtering terjadi murni client-side di computed `filtered`. Tidak ada query param `?search=` yang perlu ditambah.

## 4. API Contract (FastAPI)
*   **Endpoints:** Tidak ada endpoint baru / berubah.
*   **Request/Response Body:** Tidak berubah.
*   **Validation & Errors:** Tidak ada.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Tidak berubah (`ProductSizeDetail.productSku` sudah ada dan terisi dari `sizeDetailFromBasic`).
*   **Views & Controllers — satu file saja:**
    *   `oura studio frontend/Screens/Penjualan/TambahPenjualanSheet.swift` → `private struct ProductPickerSheet`:
        1. `filtered`: tambah kondisi `$0.productSku.localizedCaseInsensitiveContains(q)`; tambahkan `.trimmingCharacters` pada query.
        2. `groups`: ganti key `productName: String` → `(sku, productName)`; `ForEach(groups, id: \.sku)`.
        3. Header `Section`: `Text("\(group.productName) • \(group.sku)".uppercased())`.
        4. Placeholder `TextField`: `"Cari produk / SKU..."`.
    *   Referensi pola yang disamakan: `ProdukListView.filtered` (`ProdukListView.swift:45-68`).
    *   **Tidak menyentuh:** `ScanToSellSheet`, `QRGeneratorView`, `ProdukListView`, `MockAPIService` (mock sudah mengembalikan `productSku`, filter ikut otomatis).

## 6. Verification & Test Plan
*   **Smoke Test:** Build sukses; buka Catat Penjualan → Tambah Produk → sheet muncul tanpa crash; header tiap grup menampilkan `NAMA • SKU`.
*   **Sanity Test Scenarios:**
    1. Ketik SKU partial (mis. `scr-2t`) → grup produk dengan SKU tersebut muncul (walau nama tidak mengandung query).
    2. Ketik nama produk partial (mis. `bludru`) → tetap muncul seperti sebelum perubahan (regresi nama).
    3. Ketik size (`M`) / varian kain → tetap muncul seperti sebelum perubahan.
    4. Query uppercase / dengan spasi depan-belakang (`"  SCR-001 "`) → tetap match (trim + case-insensitive).
    5. Dua produk beda SKU tapi nama mirip → muncul sebagai 2 grup terpisah, masing-masing header menampilkan SKU-nya.
    6. Pilih salah satu size → item masuk ke `items` dengan `productSku` benar; simpan penjualan sukses (HPP/validasi tidak terpengaruh).
