# Version 3.72 - Fix Pull & Reload Penjualan (False-Empty + Spinner Mati + Judul Menimpa Filter)

## 1. Problem / Opportunity
*   **Context:** Di tab Penjualan (`PenjualanListView`), pull-to-refresh tidak memunculkan spinner sama sekali. Lebih parah: data yang tadinya ada, setelah di-pull malah menjadi layar kosong "Belum ada penjualan" padahal backend real seharusnya ada transaksi pada periode tersebut. Screenshot juga menunjukkan judul besar "Penjualan" menimpa pill periode (`DateRangeField`).
*   **Objective:** Pull-to-refresh selalu jalan (ada/tanpa data), gagal network tidak menghapus data lama dan menampilkan error + retry, judul tidak menimpa filter. Samakan pola dengan Beranda/ProduksiBatch.

## 2. User Flow & UX Specifications
*   **Entry Point:** Tab Penjualan (bottom nav index 3) → `PenjualanListView` di `MainTabView.swift:22-23`.
*   **Flow yang disepakati:**
    1. First-load: tampilkan `ProgressView` fullscreen hanya bila `orders.isEmpty && errorMsg == nil`.
    2. Pull-to-refresh: spinner native iOS selalu muncul (kosong maupun isi) karena `.refreshable` ditempel di satu `ScrollView` container, bukan di `VStack` kondisional.
    3. Gagal network saat pull: data lama tetap tampil + banner/view error merah + tombol "Coba Lagi". Tidak pernah tampil false-empty "Belum ada penjualan".
    4. Kosong beneran (200 OK, array kosong): tampilkan empty-state existing + teks periode aktif agar jelas bukan error.
    5. Ganti periode via `DateRangeField` → reload silent (spinner kecil di bawah filter, bukan fullscreen).
    6. Judul tidak menimpa filter: pakai `.navigationBarTitleDisplayMode(.inline)` (seperti `EditPenjualanSheet`) ATAU pertahankan large-title tapi filter masuk ke dalam scroll-container sehingga collapse sinkron — pilih satu, jangan `VStack` pinned + inner `List`.
*   **UI Components:**
    *   `ScrollView` tunggal sebagai root konten (ganti `VStack` + kondisional `List`); daftar grup tanggal dirender sebagai `VStack`/`LazyVStack` section di dalam ScrollView (pertahankan `OrderRow`, `SalesSummaryHeader`, swipe-to-delete boleh diganti long-press/menu bila `List` dihapus — pilih yang minim diff: opsi termurah adalah pertahankan `List` tapi bungkus empty/error state dalam `List` juga sehingga `.refreshable` tetap punya scroll-container).
    *   Error view: teks `errorMsg` + `Button("Coba Lagi")`, style `OuraTheme.Colors.dangerText/dangerBg` seperti pola `EditResepSheet`.
    *   Refreshing indicator kecil (`isRefreshing && !isLoading`) di bawah `DateRangeField`, pola `ResepListView.swift:91` / `ProduksiBatchView.swift:33`.
*   **Validation Rules (`canSave`):** N/A (layar read-only + filter).
*   **State & Progressive Disclosure:** `isLoading` (first-load saja) vs `isRefreshing` (pull/silent) dipisah; `errorMsg: String?` baru; `orders` tidak ditimpa saat error.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** Nihil.
*   **New / Modified Columns:** Nihil — murni frontend.

## 4. API Contract (FastAPI)
*   **Endpoints (reuse, tanpa perubahan backend):**
    *   `GET /api/v1/sales-orders?from=YYYY-MM-DD&to=YYYY-MM-DD`
        *   **Request:** `from`/`to` wajib berpasangan (kontrak existing `APIService.getSalesOrders(from:to:)`).
        *   **Validation & Errors:** 401 → flow auth existing; network/timeout/500 → tangkap sebagai `errorMsg`, JANGAN `try? ?? []`.
*   **Catatan:** `MockAPIService.getSalesOrders()` mengabaikan `from/to` — verifikasi sanity pakai backend real (user konfirmasi data real ada).

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:** Nihil (reuse `SalesOrder`, `api.getSalesOrders(from:to:)`).
*   **Views & Controllers (tepat apa yang diubah):**
    *   `Screens/Penjualan/PenjualanListView.swift`
        *   Tambah `@State private var errorMsg: String?` + `@State private var isRefreshing = false`.
        *   Ganti `private func load()` menjadi `load(silent: Bool = false)`:
            ```swift
            if silent { isRefreshing = true } else if orders.isEmpty { isLoading = true }
            errorMsg = nil (hanya saat first-load/silent sukses-reset; saat pull-gagal JANGAN clear orders)
            do { orders = try await api.getSalesOrders(from: fromDate, to: toDate) }
            catch { if orders.isEmpty { errorMsg = ... } else { errorMsg = ... } /* orders TIDAK ditimpa [] */ }
            isLoading = false; isRefreshing = false
            ```
            Hapus `orders = (try? ...) ?? []`.
        *   `.task { await load() }` tetap; `.refreshable { await load(silent: true) }` pindah ke scroll-container (`ScrollView`/`List` yang selalu ada, termasuk saat empty/error).
        *   Empty-state + error-state harus berada DI DALAM scroll-container (bukan `VStack` non-scroll) agar gesture pull selalu tersedia.
        *   `DateRangeField(from:to:)` `onApply` → `Task { await load(silent: true) }` (saat ini `load()` fullscreen — ganti).
        *   Judul: `.navigationBarTitleDisplayMode(.inline)` (fix overlap deterministik) ATAU masukkan filter ke scroll-content; dokumentasikan pilihan di PR.
        *   `deleteOrder`: setelah hapus, jangan full-reload fullscreen — cukup `orders.removeAll` existing + `load(silent:true)` opsional; pertahankan `appState.dashboardNeedsRefresh = true`.
*   **Alternatif yang ditolak:** Tetap `VStack` + `List` kondisional + `.refreshable` di root (inilah bug saat ini); `try? ?? []` (menelan error, penyebab false-empty).

## 6. Verification & Test Plan
*   **Smoke Test:** Build sukses (`xcodebuild`); tab Penjualan terbuka tanpa crash; judul tidak menimpa pill periode; FAB + dan ikon QR tetap tampil.
*   **Sanity Test Scenarios:**
    1. Periode berisi data (real) → list tampil; pull-to-refresh → spinner native muncul → data tetap/terbaru, tidak jadi kosong.
    2. Airplane-mode lalu pull → spinner muncul → data lama tetap tampil + error "Coba Lagi" tampil, TIDAK jadi "Belum ada penjualan".
    3. "Coba Lagi" saat online kembali → data tampil tanpa perlu ganti tab.
    4. Periode memang kosong (200 OK []) → empty-state tampil + label periode jelas (bukan error).
    5. Ganti periode via `DateRangeField` → reload silent (tanpa fullscreen flash), summary cards (omset/pcs/trx) terhitung ulang benar, `cancelled` tetap diabaikan di summary tapi tampil di list (kontrak v3.54).
    6. Scroll naik-turun → judul tidak menimpa filter pada posisi scroll mana pun (cek seperti screenshot).
